# Util Protocol

## Learning Objectives
- Create reusable Util scripts
- Share functions and types across Node scripts
- Use `require()` to import utilities
- Avoid common Util script pitfalls

---

## AE/JS Syntax Comparison

| Concept | After Effects / JavaScript | Luau (Rive Scripts) |
|---------|---------------------------|---------------------|
| Module file | `.js` file with `export` | Util script asset |
| Export functions | `export function fn()` or `module.exports` | `return ModuleTable` |
| Import module | `import { fn } from './utils'` or `require()` | `require("UtilName")` |
| Namespace | Module object | Returned table (`MyUtil.fn()`) |
| Shared types | `export type` (TypeScript) | `export type` |
| Module caching | Node.js caches `require()` | Rive caches `require()` |

:::danger Critical Difference: No Lifecycle in Util Scripts
**JavaScript Modules**: Can have initialization code that runs when imported, side effects, and even maintain state.

**Rive Util Scripts**: Are PURE modules. They:
- ❌ Have no `init`, `draw`, `advance`, or `update`
- ❌ Cannot attach to nodes
- ❌ Should not have global mutable state
- ✅ Export functions and types only
- ✅ Are shared across ALL scripts that import them

```lua
-- Util script structure
local MyUtil = {}
function MyUtil.helper() end
return MyUtil  -- Just return a table!
```

```javascript
// JavaScript module equivalent
const MyUtil = {
    helper: () => {}
};
export default MyUtil;
```
:::

---

## Rive Context: Where Reusable Logic Lives

Util scripts are Rive's way to share code across Node scripts. They have **no lifecycle** and simply return a table of functions and types.

Use Util scripts for:
- Math helpers and easing functions
- Geometry builders
- Reusable data structures (springs, timers, palettes)
- Constants and configuration

:::note Key Difference
Unlike Node scripts, Util scripts have no `init`, `draw`, or `advance` functions. They are pure modules that export functions and types.
:::

---

## Util Script Template

```lua
--!strict

local MyUtil = {}

export type Range = {
    min: number,
    max: number,
}

function MyUtil.clamp(value: number, range: Range): number
    return math.max(range.min, math.min(range.max, value))
end

return MyUtil
```

```typescript
// JavaScript/TypeScript equivalent:

interface Range {
    min: number;
    max: number;
}

const MyUtil = {
    clamp: (value: number, range: Range): number => {
        return Math.max(range.min, Math.min(range.max, value));
    }
};

export default MyUtil;
export type { Range };
```

**Usage in a Node script:**
```lua
local MyUtil = require("MyUtil")
local value = MyUtil.clamp(120, { min = 0, max = 100 })
```

## Creating a Util Script

1. Assets panel → **+** → Script → **Util**
2. Name your script (e.g., "MathUtils")
3. Define your module table and functions
4. Return the module table

## Practice Exercises

### Exercise 1: MathUtils Module

:::info Goal
Create a utility module with common math functions.
:::

:::tip Why This Matters
**After Effects comparison**: In AE, you'd copy-paste math functions between expressions or use global function libraries. Rive's Util scripts let you define functions ONCE and import them anywhere—proper code reuse.

**Real-World Use**: Every project needs math utilities: lerp for animations, clamp for constraints, smoothstep for easing. Writing them once in a Util script saves time and reduces bugs.
:::

<details>
<summary>Step-by-Step Setup</summary>

1. Assets panel → **+** → Script → **Util**
2. Name it "MathUtils"
3. Copy the Util code below
4. Create a Node script with the usage code
5. The Node script uses functions from MathUtils

</details>

**File: `MathUtils` (Util Script)**

```lua
--!strict

local MathUtils = {}

function MathUtils.clamp(value: number, min: number, max: number): number
    return math.max(min, math.min(max, value))
end

function MathUtils.lerp(a: number, b: number, t: number): number
    return a + (b - a) * t
end

function MathUtils.smoothstep(a: number, b: number, t: number): number
    t = MathUtils.clamp(t, 0, 1)
    t = t * t * (3 - 2 * t)
    return MathUtils.lerp(a, b, t)
end

function MathUtils.remap(value: number, inMin: number, inMax: number, outMin: number, outMax: number): number
    local t = (value - inMin) / (inMax - inMin)
    return outMin + (outMax - outMin) * t
end

return MathUtils
```

```typescript
// JavaScript/TypeScript equivalent:

const MathUtils = {
    clamp: (value: number, min: number, max: number): number => {
        return Math.max(min, Math.min(max, value));
    },

    lerp: (a: number, b: number, t: number): number => {
        return a + (b - a) * t;
    },

    smoothstep: (a: number, b: number, t: number): number => {
        t = MathUtils.clamp(t, 0, 1);
        t = t * t * (3 - 2 * t);
        return MathUtils.lerp(a, b, t);
    },

    remap: (value: number, inMin: number, inMax: number, outMin: number, outMax: number): number => {
        const t = (value - inMin) / (inMax - inMin);
        return outMin + (outMax - outMin) * t;
    }
};

export default MathUtils;
```

**Node Script using MathUtils:**

```lua
--!strict

local MathUtils = require("MathUtils")

export type EaseDemo = {
    time: number,
    x: number,
    path: Path,
    paint: Paint,
}

function init(self: EaseDemo): boolean
    self.time = 0
    self.x = 0
    self.path = Path.new()
    self.paint = Paint.with({ style = "fill", color = Color.rgb(255, 160, 80) })
    return true
end

function advance(self: EaseDemo, seconds: number): boolean
    self.time += seconds
    local t = (math.sin(self.time) + 1) / 2  -- 0 to 1
    self.x = MathUtils.smoothstep(-120, 120, t)

    self.path:reset()
    self.path:moveTo(Vector.xy(self.x - 10, -10))
    self.path:lineTo(Vector.xy(self.x + 10, -10))
    self.path:lineTo(Vector.xy(self.x + 10, 10))
    self.path:lineTo(Vector.xy(self.x - 10, 10))
    self.path:close()
    return true
end

function draw(self: EaseDemo, renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

return function(): Node<EaseDemo>
    return {
        init = init,
        advance = advance,
        draw = draw,
        time = 0,
        x = 0,
        path = late(),
        paint = late(),
    }
end
```

**Key points:**
- `require("MathUtils")` loads the Util script by name
- The Util script is loaded once and cached
- Functions are called with dot notation: `MathUtils.smoothstep(...)`

### Exercise 2: Exported Types from Util Scripts

:::info Goal
Share type definitions across multiple Node scripts.
:::

:::tip Why This Matters
**After Effects comparison**: AE expressions have no type system. In Rive, you can define types in a Util script and use them across your entire project—ensuring consistent data structures everywhere.

**Real-World Use**: Color palettes, game entity structures, animation configs—any data shape used in multiple places should be defined once in a Util script. This prevents bugs from mismatched structures.
:::

<details>
<summary>Step-by-Step Setup</summary>

1. Create a Util script named "Palette"
2. Define the `Swatch` type and factory functions
3. Create a Node script that imports and uses the palette
4. Multiple Node scripts can share the same palette definitions

</details>

**File: `Palette` (Util Script)**

```lua
--!strict

local Palette = {}

export type Swatch = {
    primary: Color,
    accent: Color,
    neutral: Color,
}

function Palette.warm(): Swatch
    return {
        primary = Color.rgb(255, 120, 80),
        accent = Color.rgb(255, 210, 120),
        neutral = Color.rgb(60, 60, 60),
    }
end

function Palette.cool(): Swatch
    return {
        primary = Color.rgb(80, 160, 255),
        accent = Color.rgb(120, 220, 200),
        neutral = Color.rgb(50, 50, 60),
    }
end

function Palette.dark(): Swatch
    return {
        primary = Color.rgb(40, 40, 50),
        accent = Color.rgb(200, 80, 120),
        neutral = Color.rgb(30, 30, 35),
    }
end

return Palette
```

```typescript
// JavaScript/TypeScript equivalent:

export interface Swatch {
    primary: Color;
    accent: Color;
    neutral: Color;
}

const Palette = {
    warm: (): Swatch => ({
        primary: { r: 255, g: 120, b: 80 },
        accent: { r: 255, g: 210, b: 120 },
        neutral: { r: 60, g: 60, b: 60 },
    }),

    cool: (): Swatch => ({
        primary: { r: 80, g: 160, b: 255 },
        accent: { r: 120, g: 220, b: 200 },
        neutral: { r: 50, g: 50, b: 60 },
    }),

    dark: (): Swatch => ({
        primary: { r: 40, g: 40, b: 50 },
        accent: { r: 200, g: 80, b: 120 },
        neutral: { r: 30, g: 30, b: 35 },
    }),
};

export default Palette;
```

**Node Script using Palette:**

```lua
--!strict

local Palette = require("Palette")

export type PaletteDemo = {
    swatch: Palette.Swatch,  -- Use the exported type!
    path: Path,
    paint: Paint,
}

function init(self: PaletteDemo): boolean
    self.swatch = Palette.warm()

    self.path = Path.new()
    self.path:moveTo(Vector.xy(-60, -30))
    self.path:lineTo(Vector.xy(60, -30))
    self.path:lineTo(Vector.xy(60, 30))
    self.path:lineTo(Vector.xy(-60, 30))
    self.path:close()

    self.paint = Paint.with({ style = "fill", color = self.swatch.primary })

    print("Using warm palette")
    return true
end

function draw(self: PaletteDemo, renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

return function(): Node<PaletteDemo>
    return {
        init = init,
        draw = draw,
        swatch = late(),
        path = late(),
        paint = late(),
    }
end
```

**Key points:**
- `export type` makes types available to other scripts
- Access exported types with `ModuleName.TypeName` (e.g., `Palette.Swatch`)
- Factory functions like `Palette.warm()` return configured objects
- Multiple Node scripts can share the same palette definitions

### Exercise 3: Spring Animation Util

:::info Goal
Create a reusable spring physics utility.
:::

:::tip Why This Matters
**After Effects comparison**: In AE, you'd use the springy slider or custom expressions for spring physics. Rive's Util scripts let you encapsulate complex physics in a reusable module that any script can use.

**Real-World Use**: Springs create natural-feeling animations: buttons bouncing back, elements settling into position, menus sliding with momentum. A Spring util is reusable across your entire project.
:::

<details>
<summary>Step-by-Step Setup</summary>

1. Create a Util script named "Spring"
2. Copy the Spring code below
3. Create a Node script that uses the spring
4. Adjust the input to see spring animation

</details>

**File: `Spring` (Util Script)**

```lua
--!strict

local Spring = {}

export type SpringState = {
    position: number,
    velocity: number,
    target: number,
    stiffness: number,
    damping: number,
}

function Spring.new(initial: number, stiffness: number?, damping: number?): SpringState
    return {
        position = initial,
        velocity = 0,
        target = initial,
        stiffness = stiffness or 150,
        damping = damping or 10,
    }
end

function Spring.setTarget(spring: SpringState, target: number)
    spring.target = target
end

function Spring.update(spring: SpringState, dt: number): number
    local displacement = spring.target - spring.position
    local springForce = displacement * spring.stiffness
    local dampingForce = spring.velocity * spring.damping
    local acceleration = springForce - dampingForce

    spring.velocity += acceleration * dt
    spring.position += spring.velocity * dt

    return spring.position
end

function Spring.isSettled(spring: SpringState, threshold: number?): boolean
    local thresh = threshold or 0.01
    local atTarget = math.abs(spring.target - spring.position) < thresh
    local stopped = math.abs(spring.velocity) < thresh
    return atTarget and stopped
end

return Spring
```

```typescript
// JavaScript/TypeScript equivalent:

export interface SpringState {
    position: number;
    velocity: number;
    target: number;
    stiffness: number;
    damping: number;
}

const Spring = {
    new: (initial: number, stiffness = 150, damping = 10): SpringState => ({
        position: initial,
        velocity: 0,
        target: initial,
        stiffness,
        damping,
    }),

    setTarget: (spring: SpringState, target: number) => {
        spring.target = target;
    },

    update: (spring: SpringState, dt: number): number => {
        const displacement = spring.target - spring.position;
        const springForce = displacement * spring.stiffness;
        const dampingForce = spring.velocity * spring.damping;
        const acceleration = springForce - dampingForce;

        spring.velocity += acceleration * dt;
        spring.position += spring.velocity * dt;

        return spring.position;
    },

    isSettled: (spring: SpringState, threshold = 0.01): boolean => {
        const atTarget = Math.abs(spring.target - spring.position) < threshold;
        const stopped = Math.abs(spring.velocity) < threshold;
        return atTarget && stopped;
    },
};

export default Spring;
```

**Node Script using Spring:**

```lua
--!strict

local Spring = require("Spring")

export type SpringDemo = {
    targetX: Input<number>,
    spring: Spring.SpringState,
    path: Path,
    paint: Paint,
}

function init(self: SpringDemo): boolean
    self.spring = Spring.new(0, 200, 15)
    self.path = Path.new()
    self.paint = Paint.with({ style = "fill", color = Color.rgb(120, 200, 255) })
    print("Spring demo initialized")
    return true
end

function update(self: SpringDemo)
    Spring.setTarget(self.spring, self.targetX.value)
    print(`Target set to {self.targetX.value}`)
end

function advance(self: SpringDemo, seconds: number): boolean
    local x = Spring.update(self.spring, seconds)

    self.path:reset()
    self.path:moveTo(Vector.xy(x - 20, -20))
    self.path:lineTo(Vector.xy(x + 20, -20))
    self.path:lineTo(Vector.xy(x + 20, 20))
    self.path:lineTo(Vector.xy(x - 20, 20))
    self.path:close()

    return true
end

function draw(self: SpringDemo, renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

return function(): Node<SpringDemo>
    return {
        init = init,
        update = update,
        advance = advance,
        draw = draw,
        targetX = 0,
        spring = late(),
        path = late(),
        paint = late(),
    }
end
```

**Try:** Change `targetX` in the inspector and watch the shape spring smoothly to the new position.

## Best Practices

### Keep Util Scripts Focused

Each Util script should do one thing well:
- `MathUtils` - math helpers
- `Palette` - color schemes
- `Spring` - spring physics
- `EasingFunctions` - easing curves

### Avoid Global State

```lua
-- BAD: Global state is shared across ALL script instances
local counter = 0
function MyUtil.increment()
    counter += 1
    return counter
end

-- GOOD: State is passed in and returned
function MyUtil.increment(counter: number): number
    return counter + 1
end
```

```typescript
// JavaScript equivalent of the problem:

// BAD: Module-level state shared everywhere
let counter = 0;
export const increment = () => ++counter;

// GOOD: Pure function
export const increment = (counter: number) => counter + 1;
```

### Export Types for Type Safety

```lua
-- Types are available to importing scripts
export type Vec2 = { x: number, y: number }

function MyUtil.add(a: Vec2, b: Vec2): Vec2
    return { x = a.x + b.x, y = a.y + b.y }
end
```

## Common Mistakes

### 1. Adding Lifecycle Functions to Util Scripts

```lua
-- WRONG: Util scripts don't have lifecycle functions
local MyUtil = {}
function init(self) end  -- This does nothing!
function MyUtil.helper() end
return MyUtil

-- CORRECT: Just return a table of functions
local MyUtil = {}
function MyUtil.helper() end
return MyUtil
```

### 2. Not Returning the Module Table

```lua
-- WRONG: Forgot to return
local MyUtil = {}
function MyUtil.helper() end
-- Missing return!

-- CORRECT: Always return the module table
local MyUtil = {}
function MyUtil.helper() end
return MyUtil
```

### 3. Mutable Global State

```lua
-- WRONG: Shared mutable state
local cache = {}
function MyUtil.getOrCreate(key)
    -- This cache is shared by ALL scripts!
end

-- CORRECT: Let each script manage its own cache
function MyUtil.createCache()
    return {}
end

function MyUtil.getOrCreate(cache, key)
    -- Cache is owned by the calling script
end
```

## Summary

- Util scripts are modules that export functions and types
- They have no lifecycle - just `return` a table
- Use `require()` to import them in Node scripts
- Keep them focused and avoid global state
- Export types for better type safety across scripts
