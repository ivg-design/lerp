# Lesson 2.1: Type Annotations & Inference

## Learning Objectives
- Enable and understand `--!strict` mode
- Add type annotations to variables and functions
- Understand type inference and when to rely on it
- Use type refinement with control flow

---

## AE/JS Syntax Comparison

If you're coming from After Effects expressions or JavaScript, here's how Luau's type system compares:

| Concept | JavaScript/AE | Luau (Rive) | Notes |
|---------|--------------|-------------|-------|
| Variable with type | `let x = 5` (inferred) | `local x: number = 5` | Luau uses `:` for type annotations |
| Function parameters | `function foo(x) {}` | `function foo(x: number)` | Parameters need explicit types |
| Return type | Implicit | `function foo(): number` | Return types come after `)` |
| Type checking mode | None (runtime only) | `--!strict` | Luau catches errors at compile time |
| Optional type | `x?: number` (TypeScript) | `x: number?` | `?` comes AFTER the type name |
| Union type | `x: number \| string` (TS) | `x: number \| string` | Same syntax! |
| Type alias | `type X = number` (TS) | `type X = number` | Same syntax! |
| Interface/Object type | `{ name: string }` (TS) | `{ name: string }` | Same syntax! |
| Any type | `any` (TS) | `any` | Avoid when possible |

:::danger Critical Difference
**JavaScript has NO compile-time type checking.** Errors happen at runtime when your code runs.

**Luau with `--!strict` catches type errors BEFORE your code runs.** This is why Rive requires strict mode—bugs are caught during development, not when users see your animation.
:::

---

## Rive Context

Rive scripts run in `--!strict` mode by default. That means your script must define types for persistent state and inputs, and the engine enforces them.

**Why does this matter?** When your animation runs on a user's device, there's no debugger. Strict mode catches bugs during development so your animation works reliably everywhere.

Key rules in Rive:
- Use `export type` to describe your script instance (`self`)
- Use `Input<T>` for values exposed to the editor
- Use `late()` when a value is provided by the engine after creation

---

## Why Types Matter

In Module 1, you wrote code that worked—but how do you know it won't break when you change something? Types act as guardrails:

1. **Catch errors early**: Before your animation even runs
2. **Better autocomplete**: The editor knows what methods are available
3. **Self-documenting code**: Types explain what data flows where
4. **Rive integration**: Rive generates types for its entire API

---

## Mode Directives

```lua
--!strict    -- Full type checking (recommended for Rive)
--!nonstrict -- Partial checking, allows 'any' inference
--!nocheck   -- No type checking (default if no directive)
```

:::tip Always Use Strict Mode
Add `--!strict` as the first line of every Rive script. It catches bugs before they become runtime errors.
:::

## Basic Type Annotations

```lua
local age: number = 25
local name: string = "Hero"
local active: boolean = true

local function greet(name: string): string
    return `Hello, {name}!`
end
```

**JavaScript Equivalent:**
```javascript
// JavaScript (no type checking)
let age = 25;
let name = "Hero";
let active = true;

function greet(name) {
    return `Hello, ${name}!`;
}

// TypeScript (similar to Luau)
let age: number = 25;
let name: string = "Hero";
let active: boolean = true;

function greet(name: string): string {
    return `Hello, ${name}!`;
}
```

## Type Inference

Luau can often infer types automatically:

```lua
local score = 100        -- Luau infers: number
local items = {"a", "b"} -- Luau infers: {string}
```

**Why This Matters:** You don't need to annotate every single variable. Luau is smart enough to figure out obvious types. But for function parameters and complex structures, explicit types prevent errors.

## Practice Exercises

### Exercise 1: Enable Strict Mode

**Goal:** Understand how `--!strict` catches bugs that would otherwise slip through.

**Why This Matters:** In JavaScript and AE expressions, type bugs crash at runtime—sometimes only in specific conditions. Strict mode catches them during development, saving hours of debugging.

**Real-World Use:** Every professional Rive animation uses strict mode. It's the difference between "works on my machine" and "works everywhere."

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Start WITHOUT the strict directive to see what happens
3. Then add `--!strict` to see the errors

**Rive setup:** Attach the script to any node and open both the Console and Problems panels.

**Expected result:** Without `--!strict`, the script runs and may produce a wrong value. With `--!strict`, the editor flags the type error before you run.

**Part A - WITHOUT strict mode (DON'T DO THIS IN PRODUCTION):**

```lua
export type BuggyScript = {}

function init(self: BuggyScript): boolean
    local damage = "50"  -- Oops, string instead of number!
    local health = 100

    local result = health - damage  -- This should error...
    print(`Result: {result}`)

    return true
end

function draw(self: BuggyScript, renderer: Renderer)
end

return function(): Node<BuggyScript>
    return { init = init, draw = draw }
end
```

**Question 1**: What happens when you run this? Does it catch the bug?

**JavaScript Equivalent:**
```javascript
// This would also fail silently in JavaScript!
let damage = "50";  // String, not number
let health = 100;
let result = health - damage;  // JavaScript converts "50" to 50 (coercion)
console.log(result);  // Prints 50, but this hides a bug!
```

**Part B - WITH strict mode (DO THIS):**

```lua
--!strict

export type BuggyScript = {}
-- ... rest of code
```

**Question 2**: What error do you see in the Problems tab?

**Part C**: Fix the bug by changing `"50"` to `50`.

### Exercise 2: Variable Type Annotations

**Goal:** Learn the syntax for annotating variables with their types.

**Why This Matters:** When you see `local level: number = 15`, you immediately know what kind of data `level` holds. This makes code readable and prevents accidental misuse.

**Real-World Use:** In a game character script, you'd annotate health, position, and inventory to ensure you never accidentally assign a string to a number field.

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add the `--!strict` directive
3. Copy the code below
4. Run to see the output

**Rive setup:** Attach the script to any node and open the Console panel.

**Expected result:** The Console prints typed values for the player stats and inventory.

**Task**: Add type annotations to ALL variables:

```lua
--!strict

export type CharacterStats = {}

function init(self: CharacterStats): boolean
    -- Add type annotations to each variable
    local playerName: string = "Warrior"
    local level: number = 15
    local experience: number = 2500.75
    local isAlive: boolean = true
    local inventory: {string} = {"sword", "shield", "potion"}
    local position: {x: number, y: number} = {x = 100, y = 200}

    print(`Player: {playerName}`)
    print(`Level {level} with {experience} XP`)
    print(`Alive: {isAlive}`)
    print(`Items: {#inventory}`)
    print(`Position: ({position.x}, {position.y})`)

    return true
end

function draw(self: CharacterStats, renderer: Renderer)
end

return function(): Node<CharacterStats>
    return { init = init, draw = draw }
end
```

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript (similar concept)
let playerName: string = "Warrior";
let level: number = 15;
let experience: number = 2500.75;
let isAlive: boolean = true;
let inventory: string[] = ["sword", "shield", "potion"];
let position: { x: number, y: number } = { x: 100, y: 200 };
```

**Key Difference:** In TypeScript, arrays use `string[]` or `Array<string>`. In Luau, it's `{string}` with curly braces.

### Exercise 3: Function Type Annotations

**Goal:** Learn how to annotate function parameters and return types.

**Why This Matters:** When you call `calculateDamage(50, "armor")` by mistake, strict mode catches it immediately. Without types, this bug might only appear in specific gameplay scenarios.

**Real-World Use:** Game logic functions like damage calculation, collision detection, and animation timing all benefit from typed parameters.

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add the `--!strict` directive
3. Implement the functions with proper type annotations
4. Test by calling them in `init()`

**Rive setup:** Attach the script to any node and open the Console panel.

**Expected result:** The Console prints the function outputs, and type errors surface if any signatures are wrong.

**Task**: Add complete type annotations (parameters AND return types):

```lua
--!strict

-- 1. Takes two numbers, returns their sum
local function add(a: number, b: number): number
    return a + b
end

-- 2. Takes a number array, returns the average (or 0 if empty)
local function average(numbers: {number}): number
    if #numbers == 0 then return 0 end
    local sum = 0
    for _, n in ipairs(numbers) do
        sum += n
    end
    return sum / #numbers
end

-- 3. Takes damage and armor, returns reduced damage (minimum 0)
local function calculateDamage(baseDamage: number, armor: number): number
    local reduced = baseDamage - armor
    if reduced < 0 then return 0 end
    return reduced
end

-- 4. Takes a name string, returns a greeting string
local function createGreeting(name: string): string
    return `Welcome, {name}!`
end

export type FunctionTypes = {}

function init(self: FunctionTypes): boolean
    print(add(10, 20))                        -- 30
    print(average({10, 20, 30}))              -- 20
    print(calculateDamage(50, 20))            -- 30
    print(calculateDamage(10, 50))            -- 0
    print(createGreeting("Hero"))             -- Welcome, Hero!
    return true
end

function draw(self: FunctionTypes, renderer: Renderer)
end

return function(): Node<FunctionTypes>
    return { init = init, draw = draw }
end
```

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript
function add(a: number, b: number): number {
    return a + b;
}

function average(numbers: number[]): number {
    if (numbers.length === 0) return 0;
    return numbers.reduce((sum, n) => sum + n, 0) / numbers.length;
}

function calculateDamage(baseDamage: number, armor: number): number {
    return Math.max(0, baseDamage - armor);
}

function createGreeting(name: string): string {
    return `Welcome, ${name}!`;
}
```

### Exercise 4: Type Inference Investigation

**Goal:** Understand when Luau can infer types and when you must provide them explicitly.

**Why This Matters:** You don't want to over-annotate (clutters code), but you also can't under-annotate (causes errors). This exercise teaches the balance.

**Real-World Use:** Professional code uses inference for obvious cases (like `local x = 5`) but explicit types for function signatures and empty collections.

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add the `--!strict` directive
3. Try uncommenting the problem lines to see errors

**Rive setup:** Attach the script to any node and watch the Problems tab as you toggle the commented lines.

**Expected result:** The editor flags inference failures (like empty tables) until you add explicit types.

**Task**: For each variable, predict what type Luau infers:

```lua
--!strict

export type InferenceTest = {}

function init(self: InferenceTest): boolean
    -- Part A: What types does Luau infer?
    local a = 42                              -- number
    local b = "hello"                         -- string
    local c = true                            -- boolean
    local d = {1, 2, 3}                       -- {number}
    local e = {name = "test", value = 10}    -- {name: string, value: number}
    local f = function(x: number) return x * 2 end  -- (number) -> number

    -- Part B: This empty table needs a type - Luau can't infer it!
    -- local emptyArray = {}  -- Error in strict mode!

    -- Fix it:
    local emptyArray: {number} = {}

    -- Part C: Mixed arrays
    local mixed = {1, "two", 3}  -- {number | string}

    return true
end

function draw(self: InferenceTest, renderer: Renderer)
end

return function(): Node<InferenceTest>
    return { init = init, draw = draw }
end
```

:::danger Critical Rule
**Empty tables (`{}`) MUST have explicit type annotations in strict mode** because Luau cannot infer what type of elements they will contain.

```lua
-- WRONG - Error in strict mode
local items = {}

-- CORRECT - Explicit type
local items: {string} = {}
```
:::

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript has the same inference behavior
let a = 42;              // number (inferred)
let b = "hello";         // string (inferred)

// Empty arrays also need types in TypeScript
let items: string[] = [];  // Must specify type
```

### Exercise 5: Type Refinement

**Goal:** Learn how Luau automatically narrows types based on control flow checks.

**Why This Matters:** When you have a `string?` (optional string), you can't use it directly—it might be nil. But after an `if value then` check, Luau knows it's definitely a string. This is called "type narrowing" or "refinement."

**Real-World Use:** When loading user data, many fields might be optional. Type refinement lets you handle missing data safely.

**Context**: Luau tracks types through control flow. This is called "type refinement" or "narrowing."

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add the `--!strict` directive
3. Study how the `if` checks affect what types Luau allows

**Rive setup:** Attach the script to any node and open the Console panel.

**Expected result:** The Console prints messages based on optional values; type errors appear if you remove the nil checks.

```lua
--!strict

-- A user might or might not have an email
type UserProfile = {
    name: string,
    email: string?  -- The ? means optional (string | nil)
}

local function sendEmail(email: string)
    print(`Sending email to: {email}`)
end

local function processUser(user: UserProfile)
    print(`Processing: {user.name}`)

    -- This would ERROR without the check:
    -- sendEmail(user.email)  -- Error: string? is not string

    -- Type refinement: after the check, Luau knows email is string
    if user.email then
        sendEmail(user.email)  -- OK! Luau knows it's a string here
    else
        print("No email on file")
    end
end

-- Function 1: Takes a value that might be number or string
local function processValue(value: number | string): number
    if type(value) == "number" then
        return value * 2
    else
        return #value  -- string length
    end
end

-- Function 2: Safely get the length of an optional array
local function safeLength(arr: {number}?): number
    if arr then
        return #arr
    else
        return 0
    end
end

export type RefinementTest = {}

function init(self: RefinementTest): boolean
    local user1: UserProfile = {name = "Alice", email = "alice@example.com"}
    local user2: UserProfile = {name = "Bob"}  -- No email

    processUser(user1)
    processUser(user2)

    print(processValue(10))         -- 20
    print(processValue("hello"))    -- 5
    print(safeLength({1, 2, 3}))    -- 3
    print(safeLength(nil))          -- 0

    return true
end

function draw(self: RefinementTest, renderer: Renderer)
end

return function(): Node<RefinementTest>
    return { init = init, draw = draw }
end
```

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript has the same type narrowing feature
type UserProfile = {
    name: string;
    email?: string;  // Optional (string | undefined)
};

function processUser(user: UserProfile) {
    if (user.email) {
        // TypeScript knows email is string here, not undefined
        sendEmail(user.email);
    }
}

function processValue(value: number | string): number {
    if (typeof value === "number") {
        return value * 2;
    } else {
        return value.length;
    }
}
```

### Exercise 6: Real-World Rive Types

**Goal:** Learn how to use Rive's built-in types correctly with proper constructors.

**Why This Matters:** Rive has special types like `Vector`, `Color`, `Path`, and `Paint`. You can't just use plain tables—you must use the constructors. This exercise teaches the correct patterns.

**Real-World Use:** Every Rive animation that draws custom graphics uses `Path` and `Paint`. Every animation that positions elements uses `Vector`.

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add the `--!strict` directive
3. Note the use of `late()` for values set in `init()`

**Rive setup:** Attach the script to any node and open the Console panel.

**Expected result:** The Console prints the constructed values. If you revert to plain tables, the editor raises type errors.

**Task**: Fix the type errors in this Rive script:

```lua
--!strict

export type RiveTypesDemo = {
    position: Vector,
    color: Color,
    path: Path,
    paint: Paint,
}

function init(self: RiveTypesDemo): boolean
    -- CORRECT way to create Rive types:
    self.position = Vector.xy(100, 50)           -- Not {x = 100, y = 50}
    self.color = Color.rgba(255, 0, 0, 255)      -- Not "#FF0000"
    self.path = Path.new()
    self.paint = Paint.new()

    print("Position:", self.position.x, self.position.y)

    return true
end

function draw(self: RiveTypesDemo, renderer: Renderer)
end

return function(): Node<RiveTypesDemo>
    return {
        init = init,
        draw = draw,
        position = late(),
        color = late(),
        path = late(),
        paint = late(),
    }
end
```

:::danger Common Mistake - Plain Tables vs Rive Constructors
```lua
-- WRONG - Plain table is NOT a Vector
self.position = {x = 100, y = 50}  -- Type error!

-- CORRECT - Use the Vector constructor
self.position = Vector.xy(100, 50)

-- WRONG - String is NOT a Color
self.color = "#FF0000"  -- Type error!

-- CORRECT - Use the Color constructor
self.color = Color.rgba(255, 0, 0, 255)
```
:::

**JavaScript Equivalent (conceptually):**
```javascript
// In JavaScript, you might use plain objects:
let position = { x: 100, y: 50 };

// In Rive/Luau, you MUST use constructors:
// self.position = Vector.xy(100, 50)

// This is similar to how you'd use a class in JS:
// let position = new Vector(100, 50);
```

## Common Mistakes

:::danger Avoid These Errors

1. **Forgetting `--!strict`**: Always add it as the first line
   ```lua
   -- WRONG: No directive
   export type MyScript = {}

   -- CORRECT: Strict mode enabled
   --!strict
   export type MyScript = {}
   ```

2. **Empty tables without types**:
   ```lua
   -- WRONG
   local t = {}

   -- CORRECT
   local t: {string} = {}
   ```

3. **Wrong Rive constructors**:
   ```lua
   -- WRONG
   self.position = {x = 100, y = 50}

   -- CORRECT
   self.position = Vector.xy(100, 50)
   ```

4. **Not checking optionals**:
   ```lua
   -- WRONG: email might be nil
   sendEmail(user.email)

   -- CORRECT: Check first
   if user.email then
       sendEmail(user.email)
   end
   ```

5. **Redundant annotations**: Don't annotate when inference is obvious
   ```lua
   -- Unnecessary (Luau knows it's number)
   local x: number = 5

   -- Better (let Luau infer)
   local x = 5
   ```

:::
