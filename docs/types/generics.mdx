# Lesson 2.3: Generics & Advanced Types

## Learning Objectives
- Understand generic type parameters (`<T>`)
- Create reusable generic functions
- Define generic type aliases
- Use Rive's generic types (`Input<T>`, `Node<T>`)
- Apply intersection types for composition

---

## AE/JS Syntax Comparison

If you're coming from TypeScript, Luau generics will feel very familiar:

| Concept | TypeScript | Luau (Rive) | Notes |
|---------|-----------|-------------|-------|
| Generic function | `function foo<T>(x: T): T` | `function foo<T>(x: T): T` | Same syntax! |
| Generic type | `type Box<T> = { value: T }` | `type Box<T> = { value: T }` | Same syntax! |
| Multiple type params | `<A, B>` | `<A, B>` | Same syntax! |
| Constraint | `<T extends Foo>` | Not supported | Luau lacks constraints |
| Default type | `<T = string>` | Not supported | Luau lacks defaults |
| Intersection | `A & B` | `A & B` | Same syntax! |

:::tip If You Know TypeScript
Luau generics work almost identically to TypeScript generics. The main differences:
- No generic constraints (`<T extends Foo>`)
- No default type parameters (`<T = string>`)
- The `<T>` must appear before the parameter list: `function foo<T>(...)` not `const foo = <T>(...)`
:::

---

## Rive Context

Rive uses generics heavily throughout its API:
- `Node<T>` wraps your script type
- `Input<T>` exposes values to the editor
- `Artboard<Data.X>` and `Input<Artboard<Data.X>>` are used for dynamic instantiation

**Why does this matter?** Understanding generics lets you:
1. Read Rive's API signatures correctly
2. Create reusable utility functions
3. Build type-safe data structures

---

## What Are Generics?

Generics let you write code that works with multiple types while maintaining type safety. Instead of writing separate functions for each type:

```lua
function getFirstString(arr: {string}): string? ... end
function getFirstNumber(arr: {number}): number? ... end
```

You write one generic function:

```lua
function getFirst<T>(arr: {T}): T? ... end
```

The `<T>` is a **type parameter**—a placeholder that gets filled in when you use the function.

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript - identical concept
function getFirst<T>(arr: T[]): T | undefined {
    return arr[0];
}

// When called, T is inferred from the argument:
getFirst(["a", "b"]);  // T = string
getFirst([1, 2, 3]);   // T = number
```

---

## Generic Function Syntax

```lua
-- Generic function
function identity<T>(value: T): T
    return value
end

-- Generic type alias
type Container<T> = { value: T, count: number }

-- Multiple type parameters
function pair<A, B>(first: A, second: B): (A, B)
    return first, second
end

-- Rive uses generics extensively
Input<number>
Input<Color>
Node<MyScriptType>
Artboard<Data.MyViewModel>
```

## Practice Exercises

### Exercise 1: Generic Functions Basics

**Goal:** Write functions that work with any type while maintaining type safety.

**Why This Matters:** Without generics, you'd write `getFirstString`, `getFirstNumber`, `getFirstEnemy`... With generics, you write ONE function that works for ALL types.

**Real-World Use:** Utility functions (get first, get last, wrap value), data structure operations (push, pop, peek), safe access patterns (default if nil).

**Step-by-Step Setup:**
1. Create a new Node Script in Rive
2. Add `--!strict` at the top
3. Define generic functions using `<T>` syntax
4. Call them with different types to see type inference in action

**Task**: Implement these generic functions:

```lua
--!strict

-- EXAMPLE: A generic identity function (returns what it receives)
local function identity<T>(value: T): T
    return value
end

-- 1. getFirst: Returns the first element of any array
local function getFirst<T>(arr: {T}): T?
    if #arr > 0 then
        return arr[1]
    end
    return nil
end

-- 2. getLast: Returns the last element of any array
local function getLast<T>(arr: {T}): T?
    if #arr > 0 then
        return arr[#arr]
    end
    return nil
end

-- 3. wrapInArray: Wraps any single value in an array
local function wrapInArray<T>(value: T): {T}
    return {value}
end

-- 4. defaultIfNil: Returns value if not nil, otherwise returns default
local function defaultIfNil<T>(value: T?, default: T): T
    if value then
        return value
    end
    return default
end

export type GenericsBasics = {}

function init(self: GenericsBasics): boolean
    -- Test with strings
    local names = {"Alice", "Bob", "Charlie"}
    print(`First name: {getFirst(names)}`)
    print(`Last name: {getLast(names)}`)

    -- Test with numbers
    local scores = {100, 85, 92}
    print(`First score: {getFirst(scores)}`)
    print(`Last score: {getLast(scores)}`)

    -- Test wrapInArray
    local wrapped = wrapInArray(42)
    print(`Wrapped: {wrapped[1]}`)

    -- Test defaultIfNil
    local maybeValue: string? = nil
    local result = defaultIfNil(maybeValue, "default")
    print(`Default result: {result}`)

    local actualValue: string? = "actual"
    local result2 = defaultIfNil(actualValue, "default")
    print(`Actual result: {result2}`)

    return true
end

function draw(self: GenericsBasics, renderer: Renderer)
end

return function(): Node<GenericsBasics>
    return { init = init, draw = draw }
end
```

**Expected Output:**
```
First name: Alice
Last name: Charlie
First score: 100
Last score: 92
Wrapped: 42
Default result: default
Actual result: actual
```

:::note Rive Result
Attach the script to any node and press Play. The Console prints generic helper outputs so you can see type inference working with strings and numbers.
:::

**JavaScript/TypeScript Equivalent:**
```typescript
function getFirst<T>(arr: T[]): T | undefined {
    return arr.length > 0 ? arr[0] : undefined;
}

function defaultIfNil<T>(value: T | null, defaultVal: T): T {
    return value !== null ? value : defaultVal;
}
```

### Exercise 2: Generic Type Aliases

**Goal:** Create reusable type structures that work with any inner type.

**Why This Matters:** A `Box<string>` and `Box<number>` share the same structure but hold different types. Generic types let you define the structure once.

**Real-World Use:** Result types (success/error), container types (stack, queue), wrapper types (observable, cached).

**Step-by-Step Setup:**
1. Define generic types with `<T>` or `<T, E>` syntax
2. Create instances by specifying the concrete type
3. Write functions that operate on generic types

**Task**: Create and use generic type aliases:

```lua
--!strict

-- A container that holds a value of any type
type Box<T> = {
    value: T,
    label: string,
}

-- A result type that's either success or error
type Result<T, E> = {
    success: boolean,
    value: T?,
    error: E?,
}

-- Pair: Holds two values of different types
type Pair<A, B> = {
    first: A,
    second: B,
}

-- Stack: A stack with items array
type Stack<T> = {
    items: {T},
    top: number,
}

-- Optional: Simple wrapper with hasValue flag
type Optional<T> = {
    hasValue: boolean,
    value: T?,
}

-- Create values using these types
local function createBox<T>(value: T, label: string): Box<T>
    return { value = value, label = label }
end

local function createPair<A, B>(first: A, second: B): Pair<A, B>
    return { first = first, second = second }
end

local function createStack<T>(): Stack<T>
    return { items = {}, top = 0 }
end

local function pushStack<T>(stack: Stack<T>, value: T)
    stack.top += 1
    stack.items[stack.top] = value
end

local function popStack<T>(stack: Stack<T>): T?
    if stack.top > 0 then
        local value = stack.items[stack.top]
        stack.items[stack.top] = nil :: any
        stack.top -= 1
        return value
    end
    return nil
end

export type GenericTypes = {}

function init(self: GenericTypes): boolean
    -- Test Box
    local numberBox = createBox(42, "Answer")
    local stringBox = createBox("Hello", "Greeting")
    print(`Number box: {numberBox.label} = {numberBox.value}`)
    print(`String box: {stringBox.label} = {stringBox.value}`)

    -- Test Pair
    local coords = createPair(100, 200)
    local mixed = createPair("name", 42)
    print(`Coords: ({coords.first}, {coords.second})`)
    print(`Mixed: {mixed.first} = {mixed.second}`)

    -- Test Stack
    local numStack: Stack<number> = createStack()
    pushStack(numStack, 1)
    pushStack(numStack, 2)
    pushStack(numStack, 3)
    print(`Pop: {popStack(numStack)}`)  -- 3
    print(`Pop: {popStack(numStack)}`)  -- 2

    return true
end

function draw(self: GenericTypes, renderer: Renderer)
end

return function(): Node<GenericTypes>
    return { init = init, draw = draw }
end
```

:::note Rive Result
Attach the script to any node and press Play. The Console prints example outputs from the Box, Pair, and Stack types, showing how generic structures behave.
:::

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript generic types
type Box<T> = {
    value: T;
    label: string;
};

type Result<T, E> = {
    success: boolean;
    value?: T;
    error?: E;
};

type Pair<A, B> = {
    first: A;
    second: B;
};

// Usage
const numberBox: Box<number> = { value: 42, label: "Answer" };
const stringBox: Box<string> = { value: "Hello", label: "Greeting" };
```

### Exercise 3: Understanding Rive's Generic Types

**Goal:** Understand how Rive uses generics in its API, especially `Input<T>` and `Node<T>`.

**Why This Matters:** Every Rive script uses `Node<T>` and most use `Input<T>`. Understanding these generics helps you read and write Rive code correctly.

**Real-World Use:** Every single Rive Node Script uses these patterns. This is fundamental knowledge.

**Step-by-Step Setup:**
1. Look at the `export type` with `Input<T>` properties
2. Understand that inputs are read directly (you get the `T`)
3. See how `Node<T>` wraps your script type in the factory

**Context**: Rive uses generics extensively. Understanding them helps you use the API correctly.

```lua
--!strict

-- Rive's Input<T> is generic - it declares an editor-exposed value
-- The T parameter specifies what type you read directly from self

export type RiveGenerics = {
    -- Different Input types
    speed: Input<number>,
    playerName: Input<string>,
    isActive: Input<boolean>,
    tint: Input<Color>,

    -- Path and Paint (not generic, but used with generics)
    myPath: Path,
    myPaint: Paint,
}

function init(self: RiveGenerics): boolean
    -- Accessing generic Input values directly
    local speedValue: number = self.speed       -- number
    local nameValue: string = self.playerName   -- string
    local activeValue: boolean = self.isActive  -- boolean
    local colorValue: Color = self.tint         -- Color

    print(`Speed (number): {speedValue}`)
    print(`Name (string): {nameValue}`)
    print(`Active (boolean): {activeValue}`)
    print(`Tint: R={Color.red(colorValue)}`)

    -- Initialize non-generic types
    self.myPath = Path.new()
    self.myPaint = Paint.new()
    self.myPaint.color = self.tint  -- Use the Input value

    return true
end

-- The factory function uses Node<T> - also generic!
-- Node<RiveGenerics> tells Rive this Node has RiveGenerics properties

function draw(self: RiveGenerics, renderer: Renderer)
end

return function(): Node<RiveGenerics>
    return {
        init = init,
        draw = draw,
        -- Inputs with default values
        speed = 100,
        playerName = "Hero",
        isActive = true,
        tint = Color.rgba(255, 128, 0, 255),
        -- late() for things initialized in init
        myPath = late(),
        myPaint = late(),
    }
end
```

**Key Questions Answered:**

| Question | Answer |
|----------|--------|
| What is `self.speed`? | An editor-exposed input value (read as a `number`) |
| What is `self.speed.value`? | Not used in this course (inputs are read directly) |
| Why `late()` for some properties? | They're created in `init()`, not the factory |
| What does `Node<RiveGenerics>` mean? | The Node script has `RiveGenerics` properties |

:::note Rive Result
Attach the script to any node, then press Play. The Console prints the input values and a color channel read, confirming how `Input<T>` values are read directly.
:::

### Exercise 4: Generic Cache System

**Goal:** Build a practical, type-safe generic data structure.

**Why This Matters:** Caches, pools, and registries are common in game development. Generic types let you build one cache that works for any value type.

**Real-World Use:** Animation caches, asset pools, memoization, computed value storage.

**Task**: Build a type-safe generic cache:

```lua
--!strict

type CacheEntry<T> = {
    value: T,
    timestamp: number,
    key: string,
}

type Cache<T> = {
    entries: {[string]: CacheEntry<T>},
    maxAge: number,
}

local function createCache<T>(maxAge: number): Cache<T>
    return {
        entries = {},
        maxAge = maxAge
    }
end

local function setCache<T>(cache: Cache<T>, key: string, value: T)
    cache.entries[key] = {
        value = value,
        timestamp = os.clock(),
        key = key
    }
end

local function getCache<T>(cache: Cache<T>, key: string): T?
    local entry = cache.entries[key]
    if entry then
        local age = os.clock() - entry.timestamp
        if age < cache.maxAge then
            return entry.value
        else
            -- Expired, remove it
            cache.entries[key] = nil
        end
    end
    return nil
end

export type CacheDemo = {}

function init(self: CacheDemo): boolean
    -- Test the cache with strings
    local stringCache: Cache<string> = createCache(10)  -- 10 second max age

    setCache(stringCache, "greeting", "Hello!")
    setCache(stringCache, "farewell", "Goodbye!")

    local greeting = getCache(stringCache, "greeting")
    print(`Cached greeting: {greeting or "not found"}`)

    local missing = getCache(stringCache, "missing")
    print(`Missing key: {missing or "not found"}`)

    -- Test with numbers
    local numberCache: Cache<number> = createCache(5)
    setCache(numberCache, "score", 100)
    setCache(numberCache, "level", 5)

    print(`Cached score: {getCache(numberCache, "score") or 0}`)
    print(`Cached level: {getCache(numberCache, "level") or 0}`)

    return true
end

function draw(self: CacheDemo, renderer: Renderer)
end

return function(): Node<CacheDemo>
    return { init = init, draw = draw }
end
```

:::note Rive Result
Attach the script to any node and press Play. The Console prints cached values and missing keys, showing how a typed cache would back animation data.
:::

### Exercise 5: Intersection Types

**Goal:** Combine multiple types into one using the `&` operator.

**Why This Matters:** Intersection types let you compose behaviors. An object can be `Named & Positioned & Drawable`—having all properties from all three types.

**Real-World Use:** Game entity systems, component composition, mixin patterns.

**Step-by-Step Setup:**
1. Define small, focused types
2. Combine them with `&`
3. Create objects that satisfy the combined type
4. Write functions that accept specific combinations

**Context**: Intersection types (`&`) combine multiple types into one. The result must satisfy ALL combined types.

```lua
--!strict

-- Base types
type Named = { name: string }
type Positioned = { x: number, y: number }
type Sized = { width: number, height: number }
type Colored = { color: Color }

-- Intersection: Must have ALL properties from both types
type NamedPosition = Named & Positioned

-- More complex intersection
type GameObject = Named & Positioned & Sized

-- Full intersection
type VisualObject = Named & Positioned & Sized & Colored

-- Functions that work with different intersection levels
local function printName(obj: Named)
    print(`Name: {obj.name}`)
end

local function printPosition(obj: Positioned)
    print(`Position: ({obj.x}, {obj.y})`)
end

local function printBounds(obj: Positioned & Sized)
    print(`Bounds: ({obj.x}, {obj.y}) to ({obj.x + obj.width}, {obj.y + obj.height})`)
end

local function printColor(obj: Colored)
    print(`Color: R={Color.red(obj.color)}, G={Color.green(obj.color)}, B={Color.blue(obj.color)}`)
end

export type IntersectionDemo = {}

function init(self: IntersectionDemo): boolean
    -- Create objects with different intersection types
    local simple: NamedPosition = {
        name = "Point A",
        x = 10,
        y = 20,
    }

    local gameObj: GameObject = {
        name = "Player",
        x = 100,
        y = 100,
        width = 32,
        height = 48,
    }

    local visual: VisualObject = {
        name = "Enemy",
        x = 200,
        y = 150,
        width = 24,
        height = 24,
        color = Color.rgba(255, 0, 0, 255),
    }

    -- All objects with Named work with printName
    printName(simple)
    printName(gameObj)
    printName(visual)

    -- All objects with Positioned work with printPosition
    printPosition(simple)
    printPosition(gameObj)
    printPosition(visual)

    -- Only objects with Positioned & Sized work with printBounds
    -- printBounds(simple)  -- Error! simple doesn't have width/height
    printBounds(gameObj)
    printBounds(visual)

    -- Only Colored objects work with printColor
    printColor(visual)
    -- printColor(gameObj)  -- Error! no color property

    return true
end

function draw(self: IntersectionDemo, renderer: Renderer)
end

return function(): Node<IntersectionDemo>
    return { init = init, draw = draw }
end
```

:::note Rive Result
Attach the script to any node and press Play. The Console logs names, positions, bounds, and colors, demonstrating how intersected types control which helpers can be called.
:::

**JavaScript/TypeScript Equivalent:**
```typescript
// TypeScript intersection types - identical concept
type Named = { name: string };
type Positioned = { x: number; y: number };

type NamedPosition = Named & Positioned;

const obj: NamedPosition = {
    name: "Point",
    x: 10,
    y: 20,
};
```

### Exercise 6: Entity System

**Goal:** Build a complete entity system using generics and composition.

**Why This Matters:** This exercise combines everything: generic types, intersection types, and factory functions. It's a realistic example of how professional game code is structured.

**Real-World Use:** Every game with multiple entity types (players, enemies, items, projectiles) benefits from this pattern.

**Task**: Build a mini entity system using all type features:

```lua
--!strict

-- Base entity type with generic data
type Entity<T> = {
    id: number,
    name: string,
    data: T,
    active: boolean,
}

-- Specific data types
type PlayerData = {
    health: number,
    score: number,
    inventory: {string},
}

type EnemyData = {
    health: number,
    damage: number,
    speed: number,
}

type ItemData = {
    value: number,
    rarity: "common" | "rare" | "epic" | "legendary",
}

-- Type aliases for specific entities
type Player = Entity<PlayerData>
type Enemy = Entity<EnemyData>
type Item = Entity<ItemData>

-- Entity registry with generics
type EntityRegistry<T> = {
    entities: {[number]: Entity<T>},
    nextId: number,
}

local function createRegistry<T>(): EntityRegistry<T>
    return {
        entities = {},
        nextId = 1
    }
end

local function addEntity<T>(registry: EntityRegistry<T>, name: string, data: T): Entity<T>
    local entity: Entity<T> = {
        id = registry.nextId,
        name = name,
        data = data,
        active = true
    }
    registry.entities[registry.nextId] = entity
    registry.nextId += 1
    return entity
end

local function getEntity<T>(registry: EntityRegistry<T>, id: number): Entity<T>?
    return registry.entities[id]
end

local function removeEntity<T>(registry: EntityRegistry<T>, id: number): boolean
    if registry.entities[id] then
        registry.entities[id] = nil
        return true
    end
    return false
end

export type EntitySystem = {
    players: EntityRegistry<PlayerData>,
    enemies: EntityRegistry<EnemyData>,
    items: EntityRegistry<ItemData>,
}

function init(self: EntitySystem): boolean
    -- Initialize registries
    self.players = createRegistry()
    self.enemies = createRegistry()
    self.items = createRegistry()

    -- Add some entities
    local player1 = addEntity(self.players, "Hero", {
        health = 100,
        score = 0,
        inventory = {"Sword", "Shield"}
    })

    local enemy1 = addEntity(self.enemies, "Goblin", {
        health = 30,
        damage = 5,
        speed = 2
    })

    local item1 = addEntity(self.items, "Gold Coin", {
        value = 10,
        rarity = "common"
    })

    print(`Created player: {player1.name} (ID: {player1.id})`)
    print(`Created enemy: {enemy1.name} (ID: {enemy1.id})`)
    print(`Created item: {item1.name} (ID: {item1.id})`)

    -- Retrieve entity
    local retrieved = getEntity(self.players, player1.id)
    if retrieved then
        print(`Retrieved: {retrieved.name} with {retrieved.data.health} HP`)
    end

    return true
end

function draw(self: EntitySystem, renderer: Renderer)
end

return function(): Node<EntitySystem>
    return {
        init = init,
        draw = draw,
        players = late(),
        enemies = late(),
        items = late(),
    }
end
```

:::note Rive Result
Attach the script to any node and press Play. The Console prints created entities and a retrieval log, showing how a typed registry can back animation logic.
:::

## Common Mistakes

:::danger Avoid These Errors

1. **Forgetting the `<T>` in function definition**:
   ```lua
   -- WRONG: T is undefined
   function foo(x: T): T

   -- CORRECT: Declare T as a type parameter
   function foo<T>(x: T): T
   ```

2. **Confusing union and intersection**:
   ```lua
   -- Union: A OR B (either type)
   type StringOrNumber = string | number

   -- Intersection: A AND B (all properties from both)
   type NamedPosition = Named & Positioned
   ```

3. **Not specifying type parameters when needed**:
   ```lua
   -- WRONG: What type of elements?
   local cache: Cache = createCache()

   -- CORRECT: Specify the type parameter
   local cache: Cache<string> = createCache()
   ```

4. **Trying to access properties without narrowing**:
   ```lua
   -- If you have a union, check first!
   if type(value) == "number" then
       -- Now you can use value as number
   end
   ```

:::
