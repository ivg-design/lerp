## Rive Context: ViewModels Connect Data to Graphics

ViewModels are Rive's data binding system. They let you expose properties (numbers, strings, booleans, colors, enums, lists) that can be controlled from:

- The Rive runtime (your app)
- State machines
- Other Node Scripts

**Key concepts:**
- ViewModels define a **schema** of properties
- Properties are **reactive**: changes propagate automatically
- Scripts can **read**, **write**, and **listen** to <Term>ViewModel</Term> properties
- Use `context:viewModel()` for the current node's immediate data-context ViewModel
- Use `context:rootViewModel()` when you explicitly need root/artboard-level state
- Use `Input<Data.X>` for nested ViewModel references

---

## Accessing the Data-Context ViewModel

Access the nearest bound ViewModel through `context:viewModel()` in `init()`. In Artboard List items, this is typically the item-level ViewModel, not the root.

```lua
export type VMReader = {}

function init(self: VMReader, context: Context): boolean
    local vm = context:viewModel()
    if vm then
        print("Data-context ViewModel found!")
    else
        print("No ViewModel in this node's data context.")
    end
    return true
end

function draw(self: VMReader, renderer: Renderer)
end

return function(): Node<VMReader>
    return {
        init = init,
        draw = draw,
    }
end
```

## ViewModel Property Access Methods

| Method | Returns | Description |
|--------|---------|-------------|
| `vm:getNumber(name)` | `Property<number>?` | Get a numeric property |
| `vm:getString(name)` | `Property<string>?` | Get a string property |
| `vm:getBoolean(name)` | `Property<boolean>?` | Get a boolean property |
| `vm:getColor(name)` | `Property<Color>?` | Get a color property |
| `vm:getEnum(name)` | `Property<string>?` | Get an enum property (returns string) |
| `vm:getList(name)` | `List?` | Get a list property |
| `vm:getTrigger(name)` | `Trigger?` | Get a trigger |

All getters return `nil` if the property doesn't exist. Always check before using.

## Context Type Reference

The `Context` object is passed to `init()` and provides access to the script's environment.

```lua
function init(self: MyNode, context: Context): boolean
    -- Context methods available here
    return true
end
```

### Context Methods

| Method | Returns | Description |
|--------|---------|-------------|
| `context:viewModel()` | `ViewModel?` | Get the immediate ViewModel bound at this node's data context |
| `context:rootViewModel()` | `ViewModel?` | Get the root ViewModel in the data hierarchy |
| `context:dataContext()` | `DataContext?` | Traverse data-binding context hierarchy |
| `context:image(name)` | `Image?` | Get an image asset by name |
| `context:blob(name)` | `Blob?` | Get a blob asset by name |
| `context:audio(name)` | `AudioSource?` | Get an audio asset by name |
| `context:markNeedsUpdate()` | `()` | Request an update on the next frame |

### Context Usage Patterns

```lua
function init(self: MyNode, context: Context): boolean
    -- Get the ViewModel for data binding
    local vm = context:viewModel()
    if vm then
        self.score = vm:getNumber("score")
    end

    -- Optionally inspect hierarchy-level data context
    local dataContext = context:dataContext()
    local root = context:rootViewModel()

    -- Trigger a rerun when you know external data changed
    context:markNeedsUpdate()

    return true
end
```

:::tip Context is Only Available in init()
The `context` parameter is only passed to `init()`. If you need ViewModel access in other callbacks, store the ViewModel reference in your script's state during init.
:::

## Trigger Type Reference

Triggers are one-shot signals in ViewModels. Unlike properties, they don't hold a value - they fire an event that listeners respond to.

### Getting a Trigger

```lua
local trigger = vm:getTrigger("onClick")
```

### Trigger Methods

| Method | Parameters | Description |
|--------|------------|-------------|
| `trigger:addListener(callback)` | `() -> ()` | Subscribe to trigger fires |
| `trigger:removeListener(callback)` | `() -> ()` | Unsubscribe from trigger |
| `trigger:fire()` | none | Manually fire the trigger |

### Trigger Example

```lua
function init(self: MyNode, context: Context): boolean
    local vm = context:viewModel()
    if not vm then return false end

    local onClick = vm:getTrigger("onClick")
    if onClick then
        onClick:addListener(function()
            print("Trigger fired!")
            self.clickCount += 1
        end)
    end

    return true
end
```

### When to Use Triggers vs Properties

| Use Case | Use Trigger | Use Property |
|----------|-------------|--------------|
| Button click | Yes | No |
| Animation complete | Yes | No |
| Score value | No | Yes (number) |
| Toggle state | No | Yes (boolean) |
| One-time events | Yes | No |
| Persistent state | No | Yes |

## List Type Reference

Lists are ordered collections of ViewModel instances. Each item in a list has its own set of properties defined by the list's item schema.

:::tip Component List Binding Rule
When using a Component List bound to a ViewModel list, the list container auto-generates child component instances at runtime. Do not manually add children inside that list container.
:::

### Getting a List

```lua
local items = vm:getList("inventory")
```

### List Properties and Methods

| Property/Method | Returns | Description |
|-----------------|---------|-------------|
| `list.length` | `number` | Number of items in the list (read-only) |
| `list[index]` | `ViewModel?` | Get item at index (1-based) |
| `list:clear()` | `()` | Remove all list items |
| `list:removeAt(index)` | `()` | Remove item at a 1-based index |
| `list:removeAllOf(vm)` | `()` | Remove all matching instances of a ViewModel |
| `list:addListener(callback)` | `() -> ()` | Listen for list changes |
| `list:removeListener(callback)` | `() -> ()` | Stop listening |

### List Example

```lua
function init(self: MyNode, context: Context): boolean
    local vm = context:viewModel()
    if not vm then return false end

    local inventory = vm:getList("items")
    if inventory then
        print("Inventory has", inventory.length, "items")

        -- Iterate through items
        for i = 1, inventory.length do
            local item = inventory[i]
            if item then
                local name = item:getString("name")
                local qty = item:getNumber("quantity")
                if name and qty then
                    print(name.value, "x", qty.value)
                end
            end
        end

        -- Listen for changes
        inventory:addListener(function()
            print("Inventory changed! New count:", inventory.length)
        end)
    end

    return true
end
```

### List Indexing

:::warning Lists Use 1-Based Indexing
Like all Luau arrays, list indices start at 1, not 0.
```lua
local first = list[1]   -- First item
local last = list[list.length]  -- Last item
```
:::

## Key Takeaway

ViewModels are the bridge between animation data and scripts. Use `context:viewModel()` for the current node's data context, `context:rootViewModel()` for root-level state, and `Input<Data.X>` with `late()` for explicit component bindings.
