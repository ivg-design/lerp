# Operators

## Learning Objectives

By the end of this lesson, you will be able to:
- Use all arithmetic operators including floor division
- Compare values using Luau's comparison operators (including `~=`)
- Combine conditions with logical operators (`and`, `or`, `not`)
- Simplify code with compound assignment operators (`+=`, `-=`, etc.)
- Concatenate strings and use interpolation
- Understand operator precedence to write predictable expressions

---

## AE/JS Syntax Comparison

Here's a quick reference for how operators differ between languages:

| Operation | After Effects | JavaScript | Luau |
|-----------|---------------|------------|------|
| Not equal | `!=` | `!==` or `!=` | `~=` |
| Logical AND | `&&` | `&&` | `and` |
| Logical OR | `\|\|` | `\|\|` | `or` |
| Logical NOT | `!` | `!` | `not` |
| String concat | `+` | `+` | `..` |
| Exponent | `Math.pow(x,y)` | `**` or `Math.pow()` | `^` |
| Floor divide | `Math.floor(x/y)` | `Math.floor(x/y)` | `//` |
| Increment | `x++` or `x += 1` | `x++` or `x += 1` | `x += 1` |

:::warning Critical Differences from JavaScript
- **Not Equal**: Use `~=` instead of `!=` or `!==`
- **Logical operators**: Use words `and`, `or`, `not` instead of symbols `&&`, `||`, `!`
- **String concatenation**: Use `..` instead of `+`
- **No increment/decrement**: No `++` or `--` operators; use `+= 1` or `-= 1`
- **Exponentiation**: Use `^` instead of `**`
:::

## Rive Context

Operators are fundamental to every calculation in your Rive animations. Whether you're computing damage values, lerping positions, checking collision bounds, or animating properties over time, you'll use operators constantly. Understanding operator precedence and behavior is essential for writing predictable animation logic.

In Rive Node Scripts, operators work inside lifecycle functions (`init`, `advance`, `draw`). Results of calculations often get stored on `self` to persist across frames or drive visual properties.

## Arithmetic Operators

These perform mathematical calculations on numbers.

| Operator | Name | Example | Result |
|----------|------|---------|--------|
| `+` | Addition | `10 + 5` | `15` |
| `-` | Subtraction | `10 - 5` | `5` |
| `*` | Multiplication | `10 * 5` | `50` |
| `/` | Division | `10 / 3` | `3.333...` |
| `//` | Floor Division | `10 // 3` | `3` |
| `%` | Modulo (remainder) | `10 % 3` | `1` |
| `^` | Exponentiation | `2 ^ 3` | `8` |
| `-` | Unary Negation | `-5` | `-5` |

### Floor Division vs Regular Division

```lua
local regular = 10 / 3   -- 3.3333...
local floored = 10 // 3  -- 3 (rounds down)
```

**JavaScript Equivalent**:
```javascript
// JavaScript requires Math.floor for floor division
const regular = 10 / 3;           // 3.3333...
const floored = Math.floor(10 / 3); // 3
```

**Floor division is useful for**:
- Grid-based calculations (converting pixel position to tile index)
- Frame counting (every Nth frame)
- Integer-only operations

### Exponentiation

```lua
-- Luau uses ^ for exponents
local squared = 5 ^ 2   -- 25
local cubed = 2 ^ 3     -- 8
local sqRoot = 9 ^ 0.5  -- 3 (square root)
```

**JavaScript Equivalent**:
```javascript
// JavaScript uses ** or Math.pow()
const squared = 5 ** 2;    // 25
const cubed = 2 ** 3;      // 8
const sqRoot = 9 ** 0.5;   // 3
// or
const squared = Math.pow(5, 2);
```

## Comparison Operators

These compare two values and return a boolean (`true` or `false`).

| Operator | Name | Example | Result |
|----------|------|---------|--------|
| `==` | Equal | `5 == 5` | `true` |
| `~=` | Not Equal | `5 ~= 3` | `true` |
| `<` | Less Than | `3 < 5` | `true` |
| `>` | Greater Than | `5 > 3` | `true` |
| `<=` | Less Than or Equal | `5 <= 5` | `true` |
| `>=` | Greater Than or Equal | `5 >= 5` | `true` |

:::danger Luau Uses `~=` for Not Equal
Unlike JavaScript which uses `!=` or `!==`, Luau uses `~=` for inequality. This is the #1 source of syntax errors when coming from other languages.

```lua
-- CORRECT in Luau:
if score ~= 0 then print("Has score") end

-- WRONG (will cause error):
if score != 0 then print("Has score") end  -- ERROR!
```
:::

**JavaScript Comparison**:
```javascript
// JavaScript
if (score !== 0) { console.log("Has score"); }
if (score != 0) { console.log("Has score"); }

// Luau
if score ~= 0 then print("Has score") end
```

## Logical Operators

These work with boolean values and are essential for complex conditions.

| Operator | Name | Description |
|----------|------|-------------|
| `and` | Logical AND | True if both operands are true |
| `or` | Logical OR | True if at least one operand is true |
| `not` | Logical NOT | Inverts the boolean value |

### Word Operators vs Symbol Operators

```lua
-- Luau uses WORDS for logic:
local canAttack = hasWeapon and notStunned
local isVulnerable = isLowHealth or isPoisoned
local isSafe = not isInDanger
```

```javascript
// JavaScript uses SYMBOLS for logic:
const canAttack = hasWeapon && notStunned;
const isVulnerable = isLowHealth || isPoisoned;
const isSafe = !isInDanger;
```

### Short-Circuit Evaluation

Logical operators use short-circuit evaluation - they stop as soon as the result is determined:

```lua
-- 'and' stops at the first false value
local result = false and expensiveFunction()  -- expensiveFunction never called

-- 'or' stops at the first true value
local result = true or expensiveFunction()    -- expensiveFunction never called
```

**Practical Use - Default Values**:
```lua
-- Common pattern: provide default value
local name = inputName or "Anonymous"
local health = inputHealth or 100

-- Works because 'or' returns first truthy value
```

### Truthy and Falsy Values

:::warning Remember: Only `false` and `nil` are falsy!
In Luau, `0`, `""`, and `{}` are all truthy. This affects logical operators:

```lua
local x = 0
if x then
    print("0 is truthy!")  -- This prints!
end

-- Common mistake from JavaScript:
local count = 0
local display = count or "no count"  -- display = 0, NOT "no count"!
-- Because 0 is truthy in Luau, 'or' returns 0

-- Correct approach:
local display = if count == 0 then "no count" else count
```
:::

## Compound Assignment Operators

These combine an operation with assignment for cleaner code.

| Operator | Equivalent | Example |
|----------|------------|---------|
| `+=` | `x = x + y` | `score += 10` |
| `-=` | `x = x - y` | `health -= damage` |
| `*=` | `x = x * y` | `scale *= 2` |
| `/=` | `x = x / y` | `speed /= 2` |
| `//=` | `x = x // y` | `index //= 2` |
| `%=` | `x = x % y` | `angle %= 360` |
| `^=` | `x = x ^ y` | `value ^= 2` |
| `..=` | `x = x .. y` | `text ..= "!"` |

:::info No `++` or `--` in Luau
Unlike JavaScript, Luau does not have increment (`++`) or decrement (`--`) operators. Use `+= 1` and `-= 1` instead.

```lua
-- JavaScript:
// count++;
// count--;

-- Luau:
count += 1
count -= 1
```
:::

## String Operators

| Operator | Name | Example | Result |
|----------|------|---------|--------|
| `..` | Concatenation | `"Hello" .. " World"` | `"Hello World"` |
| `#` | Length | `#"Hello"` | `5` |

### String Concatenation

:::warning Use `..` not `+`
This is a common source of errors for JavaScript developers:

```lua
-- CORRECT in Luau:
local greeting = "Hello" .. " " .. "World"

-- WRONG (error or unexpected behavior):
local greeting = "Hello" + " " + "World"  -- ERROR!
```
:::

### String Interpolation

Luau supports string interpolation with backticks - the cleanest approach:

```lua
local name = "Player"
local score = 100
local message = `{name} scored {score} points!`  -- "Player scored 100 points!"
```

**JavaScript Comparison**:
```javascript
// JavaScript uses ${} for interpolation
const message = `${name} scored ${score} points!`;

// Luau uses {} (no $ needed)
// const message = `{name} scored {score} points!`
```

## Operator Precedence

From highest to lowest precedence:

1. `^` (exponentiation, right associative)
2. Unary: `not`, `-`, `#`
3. `*`, `/`, `//`, `%`
4. `+`, `-`
5. `..` (concatenation, right associative)
6. `<`, `>`, `<=`, `>=`, `~=`, `==`
7. `and`
8. `or`

### Why Precedence Matters

```lua
-- Without understanding precedence, this is confusing:
local result = 2 + 3 * 4 ^ 2  -- What is this?

-- With precedence knowledge:
-- Step 1: 4 ^ 2 = 16 (exponents first)
-- Step 2: 3 * 16 = 48 (multiplication next)
-- Step 3: 2 + 48 = 50 (addition last)
local result = 2 + 3 * 4 ^ 2  -- = 50

-- Always use parentheses for clarity:
local result = 2 + (3 * (4 ^ 2))  -- Clear: 50
```

### Exponentiation is Right-Associative

```lua
-- This is a gotcha! Exponentiation chains right-to-left:
local a = 2 ^ 3 ^ 2     -- = 2 ^ (3 ^ 2) = 2 ^ 9 = 512
-- NOT (2 ^ 3) ^ 2 = 8 ^ 2 = 64

-- When in doubt, use parentheses:
local explicit = 2 ^ (3 ^ 2)  -- 512, clearly right-to-left
local explicit2 = (2 ^ 3) ^ 2 -- 64, clearly left-to-right
```

### Exercise 1: Arithmetic Operators in Action

**Goal**: Practice all arithmetic operators in a damage calculation system.

**Why This Matters**: Game damage calculations combine multiple operators - multiplication for crits, subtraction for armor, modulo for even/odd effects. This exercise builds fluency with all arithmetic operators.

**Real-World Use**: Damage formulas, experience point calculations, currency conversions, physics simulations.

**Step-by-Step Setup**:
1. Create a new Rive file with a Node Script
2. Copy the code below into your script
3. Run the animation and check the console output
4. Try modifying the values to see how calculations change

```lua
--!strict

export type DamageCalc = {}

function init(self: DamageCalc): boolean
    print("=== Damage Calculation System ===\n")

    local baseDamage = 100
    local critMultiplier = 2.5
    local armorReduction = 30
    local penetration = 0.2

    print(`Base damage: {baseDamage}`)
    print(`Crit multiplier: {critMultiplier}x`)
    print(`Armor: {armorReduction}`)
    print(`Armor penetration: {penetration * 100}%\n`)

    -- Calculate damage with crit (multiplication)
    local critDamage = baseDamage * critMultiplier
    print(`Step 1 - Crit damage: {baseDamage} × {critMultiplier} = {critDamage}`)

    -- Apply armor reduction with penetration (multiple operations)
    local effectiveArmor = armorReduction * (1 - penetration)
    print(`Step 2 - Effective armor: {armorReduction} × {1 - penetration} = {effectiveArmor}`)

    local finalDamage = critDamage - effectiveArmor
    print(`Step 3 - Final damage: {critDamage} - {effectiveArmor} = {finalDamage}`)

    -- Calculate overkill (if target has 200 HP)
    local targetHP = 200
    local overkill = finalDamage - targetHP
    print(`\nTarget HP: {targetHP}`)
    print(`Overkill damage: {finalDamage} - {targetHP} = {overkill}`)

    -- Use floor division for whole damage numbers
    local wholeDamage = finalDamage // 1
    print(`\nWhole damage (floor division): {finalDamage} // 1 = {wholeDamage}`)

    -- Use modulo to check if damage is even
    local isEven = wholeDamage % 2 == 0
    print(`Damage {wholeDamage} is even: {isEven} (checked with % 2)`)

    -- Exponentiation for scaling
    local scaledDamage = baseDamage * (1.1 ^ 10)  -- 10 level-ups at 10% each
    print(`\nDamage after 10 level-ups (×1.1 each): {scaledDamage // 1}`)

    return true
end

function draw(self: DamageCalc, renderer: Renderer)
end

return function(): Node<DamageCalc>
    return {
        init = init,
        draw = draw,
    }
end
```

**Expected Output**:
```
=== Damage Calculation System ===

Base damage: 100
Crit multiplier: 2.5x
Armor: 30
Armor penetration: 20%

Step 1 - Crit damage: 100 × 2.5 = 250
Step 2 - Effective armor: 30 × 0.8 = 24
Step 3 - Final damage: 250 - 24 = 226

Target HP: 200
Overkill damage: 226 - 200 = 26

Whole damage (floor division): 226 // 1 = 226
Damage 226 is even: true (checked with % 2)

Damage after 10 level-ups (×1.1 each): 259
```

**JavaScript Equivalent**:
```javascript
const critDamage = baseDamage * critMultiplier;
const effectiveArmor = armorReduction * (1 - penetration);
const wholeDamage = Math.floor(finalDamage);
const isEven = wholeDamage % 2 === 0;
const scaledDamage = baseDamage * Math.pow(1.1, 10);
```

### Exercise 2: Comparison Operators for Game Logic

**Goal**: Use comparison operators to determine game states.

**Why This Matters**: Every game needs to check conditions - is the player alive? Can they afford this item? Are they in range? Mastering comparisons enables responsive, dynamic animations.

**Real-World Use**: Health checks, level requirements, distance calculations, timer expiration.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Predict the output before running
4. Verify your predictions by running the script

```lua
--!strict

export type GameState = {}

function init(self: GameState): boolean
    print("=== Game State Checks ===\n")

    local playerHealth = 25
    local maxHealth = 100
    local enemyHealth = 0
    local playerLevel = 5
    local bossLevel = 10

    print(`Player Health: {playerHealth}/{maxHealth}`)
    print(`Enemy Health: {enemyHealth}`)
    print(`Player Level: {playerLevel}`)
    print(`Boss Level: {bossLevel}\n`)

    -- Health checks (using >, <=, ==)
    local isAlive = playerHealth > 0
    local isDead = playerHealth <= 0
    local isFullHealth = playerHealth == maxHealth
    local isLowHealth = playerHealth <= maxHealth * 0.3

    print("=== Health Status ===")
    print(`Is alive (health > 0): {isAlive}`)
    print(`Is dead (health <= 0): {isDead}`)
    print(`Full health (health == max): {isFullHealth}`)
    print(`Low health (health <= 30%): {isLowHealth}`)

    -- Enemy checks
    local enemyDefeated = enemyHealth <= 0
    print(`\nEnemy defeated (health <= 0): {enemyDefeated}`)

    -- Level comparison (using >=, ~=)
    local canFightBoss = playerLevel >= bossLevel
    local levelDifference = bossLevel - playerLevel
    local notMaxLevel = playerLevel ~= 100

    print("\n=== Level Status ===")
    print(`Can fight boss (level >= {bossLevel}): {canFightBoss}`)
    print(`Levels until boss: {levelDifference}`)
    print(`Not max level (level ~= 100): {notMaxLevel}`)

    -- Range checks
    local playerX = 50
    local enemyX = 75
    local attackRange = 30

    local distance = math.abs(enemyX - playerX)
    local inRange = distance <= attackRange

    print("\n=== Range Check ===")
    print(`Player position: {playerX}`)
    print(`Enemy position: {enemyX}`)
    print(`Distance: {distance}`)
    print(`Attack range: {attackRange}`)
    print(`In attack range: {inRange}`)

    return true
end

function draw(self: GameState, renderer: Renderer)
end

return function(): Node<GameState>
    return {
        init = init,
        draw = draw,
    }
end
```

### Exercise 3: Logical Operators for Complex Conditions

**Goal**: Combine multiple conditions using `and`, `or`, and `not`.

**Why This Matters**: Real game logic requires multiple conditions - "can attack if has weapon AND not stunned AND has target". This exercise builds complex conditional thinking.

**Real-World Use**: Ability availability, permission checks, state validation, multi-factor authentication.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Trace through each logical expression mentally
4. Run and verify your understanding

```lua
--!strict

export type AbilityCheck = {}

function init(self: AbilityCheck): boolean
    print("=== Ability System ===\n")

    -- Character state
    local mana = 30
    local manaCost = 25
    local cooldown = 0
    local isStunned = false
    local isSilenced = false
    local hasTarget = true

    print("Character State:")
    print(`  Mana: {mana}/{manaCost} required`)
    print(`  Cooldown: {cooldown}s`)
    print(`  Stunned: {isStunned}`)
    print(`  Silenced: {isSilenced}`)
    print(`  Has target: {hasTarget}`)

    -- Individual checks
    local hasMana = mana >= manaCost
    local isReady = cooldown <= 0
    local canAct = not isStunned      -- Using 'not'
    local canCast = not isSilenced    -- Using 'not'

    print("\n=== Individual Checks ===")
    print(`Has enough mana: {hasMana}`)
    print(`Ability ready: {isReady}`)
    print(`Can act (not stunned): {canAct}`)
    print(`Can cast (not silenced): {canCast}`)

    -- Combined conditions with 'and'
    local canUseAbility = hasMana and isReady and canAct and canCast and hasTarget
    print("\n=== Combined Check (using 'and') ===")
    print(`Can use ability: {canUseAbility}`)
    print("(requires: mana AND ready AND can act AND can cast AND has target)")

    -- Alternative paths with 'or'
    local hasEscape = mana >= 10 or cooldown <= 0
    print("\n=== Alternative Check (using 'or') ===")
    print(`Has escape option: {hasEscape}`)
    print("(requires: enough mana for blink OR dash is ready)")

    -- Complex nested logic
    local shouldRetreat = (isStunned or isSilenced) and hasTarget
    local shouldHeal = mana < 50 and not isStunned
    local isVulnerable = isStunned or (mana < manaCost and cooldown > 0)

    print("\n=== Complex Conditions ===")
    print(`Should retreat: {shouldRetreat}`)
    print(`Should heal: {shouldHeal}`)
    print(`Is vulnerable: {isVulnerable}`)

    -- Short-circuit demonstration
    print("\n=== Short-Circuit Behavior ===")
    local function expensiveCheck(): boolean
        print("  (expensiveCheck was called)")
        return true
    end

    print("Testing: false and expensiveCheck()")
    local result1 = false and expensiveCheck()  -- expensiveCheck NOT called
    print(`Result: {result1}`)

    print("\nTesting: true or expensiveCheck()")
    local result2 = true or expensiveCheck()    -- expensiveCheck NOT called
    print(`Result: {result2}`)

    return true
end

function draw(self: AbilityCheck, renderer: Renderer)
end

return function(): Node<AbilityCheck>
    return {
        init = init,
        draw = draw,
    }
end
```

### Exercise 4: Compound Assignment for Animation State

**Goal**: Use compound assignment operators to update animation values over time.

**Why This Matters**: Animation is all about changing values over time - incrementing rotation, scaling up/down, fading opacity. Compound operators make this code clean and readable.

**Real-World Use**: Continuous rotation, breathing/pulsing effects, fade in/out, score counters.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. This exercise uses `advance()` for per-frame updates
4. Watch the console output as values change over time

```lua
--!strict

export type AnimState = {
    rotation: number,
    scale: number,
    alpha: number,
    frameCount: number,
}

function init(self: AnimState): boolean
    self.rotation = 0
    self.scale = 1
    self.alpha = 1
    self.frameCount = 0

    print("=== Animation State Demo ===")
    print("Using compound assignment operators for smooth animation\n")
    print("Initial state:")
    print(`  Rotation: {self.rotation}°`)
    print(`  Scale: {self.scale}x`)
    print(`  Alpha: {self.alpha}`)
    print("\nWatch values change every second (60 frames)...")

    return true
end

function advance(self: AnimState, seconds: number): boolean
    self.frameCount += 1  -- Increment frame counter

    -- Rotate continuously (+=)
    self.rotation += 90 * seconds  -- 90 degrees per second

    -- Keep rotation in 0-360 range (%=)
    self.rotation %= 360

    -- Pulse scale up and down (*= and /=)
    if self.frameCount % 60 < 30 then
        self.scale *= 1.002  -- Grow by 0.2% per frame
    else
        self.scale /= 1.002  -- Shrink by 0.2% per frame
    end

    -- Fade alpha with bounds checking (-= and +=)
    if self.frameCount % 120 < 60 then
        self.alpha -= 0.005
        if self.alpha < 0.2 then self.alpha = 0.2 end
    else
        self.alpha += 0.005
        if self.alpha > 1 then self.alpha = 1 end
    end

    -- Log every second (assuming ~60fps)
    if self.frameCount % 60 == 0 then
        print(`\nFrame {self.frameCount}:`)
        print(`  Rotation: {self.rotation // 1}° (using +=, %=)`)
        print(`  Scale: {string.format("%.2f", self.scale)}x (using *=, /=)`)
        print(`  Alpha: {string.format("%.2f", self.alpha)} (using -=, +=)`)
    end

    return true
end

function draw(self: AnimState, renderer: Renderer)
end

return function(): Node<AnimState>
    return {
        init = init,
        advance = advance,
        draw = draw,
        rotation = 0,
        scale = 1,
        alpha = 1,
        frameCount = 0,
    }
end
```

**Expected Output** (after a few seconds):
```
=== Animation State Demo ===
Using compound assignment operators for smooth animation

Initial state:
  Rotation: 0°
  Scale: 1x
  Alpha: 1

Watch values change every second (60 frames)...

Frame 60:
  Rotation: 90° (using +=, %=)
  Scale: 1.06x (using *=, /=)
  Alpha: 0.70 (using -=, +=)

Frame 120:
  Rotation: 180° (using +=, %=)
  Scale: 1.00x (using *=, /=)
  Alpha: 1.00 (using -=, +=)
```

**JavaScript Equivalent**:
```javascript
// JavaScript compound operators are identical

rotation %= 360;
scale *= 1.002;
scale /= 1.002;
alpha -= 0.005;
```

### Exercise 5: String Operators for UI Text

**Goal**: Build dynamic UI text using string concatenation and interpolation.

**Why This Matters**: Every UI needs dynamic text - score displays, health bars, item descriptions, dialogue. String operations are essential for user-facing content.

**Real-World Use**: Score displays, player stats, inventory tooltips, achievement notifications.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Notice the difference between concatenation (`..`) and interpolation (backticks)
4. Interpolation is usually cleaner for complex strings

```lua
--!strict

export type UIText = {}

function init(self: UIText): boolean
    print("=== UI Text Building ===\n")

    local playerName = "DragonSlayer"
    local level = 42
    local gold = 15750
    local playtime = 3.5

    -- Method 1: Basic concatenation with ..
    print("Method 1: Concatenation (..) operator")
    print("--------------------------------------")
    local greeting = "Welcome, " .. playerName .. "!"
    print(greeting)

    -- Numbers auto-convert in concatenation
    local goldDisplay = "Gold: " .. gold .. " coins"
    print(goldDisplay)

    -- String length with #
    local nameLength = #playerName
    print(`Your name "{playerName}" has {nameLength} characters`)

    -- Method 2: String interpolation (cleaner!)
    print("\nMethod 2: String Interpolation (backticks)")
    print("-------------------------------------------")
    local statsLine = `Level {level} | Gold: {gold} | Hours: {playtime}`
    print(statsLine)

    -- Expressions inside interpolation
    local healthPercent = 75
    local maxHealth = 100
    local healthBar = `HP: {healthPercent}/{maxHealth} ({healthPercent}%)`
    print(healthBar)

    -- Method 3: Building formatted displays
    print("\nMethod 3: Formatted UI Panel")
    print("----------------------------")
    local separator = string.rep("-", 30)  -- Repeat character
    print(separator)
    print(`| Player: {playerName}`)
    print(`| Level:  {level}`)
    print(`| Gold:   {gold}`)
    print(`| Time:   {playtime}h`)
    print(separator)

    -- Method 4: Compound string assignment (..=)
    print("\nMethod 4: Building Log with ..= operator")
    print("-----------------------------------------")
    local log = ""

    log ..= `[{os.clock() // 1}s] Player "{playerName}" loaded\n`
    log ..= `[{os.clock() // 1}s] Level: {level}, Gold: {gold}\n`
    print(log)

    -- Comparison: Concatenation vs Interpolation
    print("Comparison: Same output, different methods")
    print("------------------------------------------")

    local damage = 150
    local target = "Goblin"

    -- Concatenation (messier)
    local msg1 = playerName .. " dealt " .. damage .. " damage to " .. target .. "!"
    print(`Concatenation: {msg1}`)

    -- Interpolation (cleaner)
    local msg2 = `{playerName} dealt {damage} damage to {target}!`
    print(`Interpolation: {msg2}`)

    return true
end

end
```

### Exercise 6: Operator Precedence Challenge

**Goal**: Understand and predict operator precedence to write bug-free expressions.

**Why This Matters**: Incorrect precedence assumptions cause subtle bugs. This exercise builds intuition for how Luau evaluates complex expressions.

**Real-World Use**: Damage formulas, physics calculations, conditional logic chains.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Before running, predict each result on paper
3. Run and compare your predictions
4. If any surprised you, trace through with precedence rules

```lua
--!strict

export type Precedence = {}

function init(self: Precedence): boolean
    print("=== Operator Precedence Challenge ===")
    print("Try to predict each result BEFORE looking!\n")

    -- Challenge 1: Exponentiation (right-associative!)
    print("Challenge 1: Exponentiation")
    print("---------------------------")
    local a = 2 ^ 3 ^ 2
    print(`2 ^ 3 ^ 2 = {a}`)
    print("Explanation: ^ is RIGHT-associative")
    print("  = 2 ^ (3 ^ 2)")
    print("  = 2 ^ 9")
    print("  = 512")
    print(`NOT (2 ^ 3) ^ 2 = {(2 ^ 3) ^ 2}\n`)

    -- Challenge 2: Multiplication before addition
    print("Challenge 2: PEMDAS")
    print("-------------------")
    local b = 2 + 3 * 4
    print(`2 + 3 * 4 = {b}`)
    print("Explanation: * before +")
    print("  = 2 + (3 * 4)")
    print("  = 2 + 12")
    print("  = 14\n")

    -- Challenge 3: Comparison before logical
    print("Challenge 3: Comparisons then Logic")
    print("------------------------------------")
    local c = 5 > 3 and 2 < 4
    print(`5 > 3 and 2 < 4 = {c}`)
    print("Explanation: Comparisons evaluate first")
    print("  = (5 > 3) and (2 < 4)")
    print("  = true and true")
    print("  = true\n")

    -- Challenge 4: 'and' before 'or'
    print("Challenge 4: 'and' before 'or'")
    print("------------------------------")
    local d = true or false and false
    print(`true or false and false = {d}`)
    print("Explanation: 'and' binds tighter than 'or'")
    print("  = true or (false and false)")
    print("  = true or false")
    print("  = true\n")

    -- Challenge 5: Parentheses change everything
    print("Challenge 5: Parentheses Override")
    print("----------------------------------")
    local e = (true or false) and false
    print(`(true or false) and false = {e}`)
    print("Explanation: Parentheses force 'or' first")
    print("  = (true or false) and false")
    print("  = true and false")
    print("  = false\n")

    -- Challenge 6: Real-world damage formula
    print("Challenge 6: Real Damage Formula")
    print("--------------------------------")
    local damage = 100
    local armor = 20
    local pen = 0.25

    -- Without parentheses (might not be what you expect!)
    local wrong = damage - armor * 1 - pen
    print(`damage - armor * 1 - pen = {wrong}`)
    print("This is probably wrong! Let's trace it:")
    print("  = damage - (armor * 1) - pen")
    print("  = 100 - 20 - 0.25")
    print("  = 79.75")

    -- With parentheses (correct intent)
    local correct = damage - armor * (1 - pen)
    print(`\ndamage - armor * (1 - pen) = {correct}`)
    print("This is correct:")
    print("  = 100 - (20 * 0.75)")
    print("  = 100 - 15")
    print("  = 85")

    print("\n=== Key Takeaway ===")
    print("When in doubt, use parentheses!")
    print("Clear code > clever code")

    return true
end

function draw(self: Precedence, renderer: Renderer)
end

return function(): Node<Precedence>
    return {
        init = init,
        draw = draw,
    }
end
```

## Common Mistakes

:::danger Common Operator Errors
1. **Using `!=` instead of `~=`** - Luau uses `~=` for not-equal
2. **Using `&&`, `||`, `!`** - Luau uses `and`, `or`, `not` (words, not symbols)
3. **Assuming 0 is falsy** - In Luau, 0 is truthy; use explicit `== 0` checks
4. **Using `+` for strings** - Luau uses `..` for string concatenation
5. **Forgetting exponent precedence** - `^` is right-associative: `2^3^2` = 512, not 64
6. **Using `++` or `--`** - Luau has no increment/decrement; use `+= 1` or `-= 1`
7. **Division precision** - `/` returns float, use `//` for integer division
8. **String concat in interpolation** - Inside backticks, don't use `..`; use `{a}{b}`
:::
