## The Standard Script Template

Every script in this course uses this template. **Copy this and keep it handy!**

```lua
--!strict

export type MyScript = {
    -- Your persistent data goes here
}

function init(self: MyScript): boolean
    -- One-time setup code goes here
    return true
end

function draw(self: MyScript, renderer: Renderer)
    -- Drawing code goes here (can be empty)
end

return function(): Node<MyScript>
    return {
        init = init,
        draw = draw,
    }
end
```

## Understanding Variables

### What Is a Variable?

A variable is a named container for data. Think of it like a labeled box that holds a value.

```lua
local playerName = "Hero"   -- A box labeled "playerName" containing "Hero"
local health = 100          -- A box labeled "health" containing 100
local isAlive = true        -- A box labeled "isAlive" containing true
```

### The `local` Keyword

In Luau, you **must** use `local` when declaring variables inside functions.

```lua
-- CORRECT: Use local for variables inside functions
function init(self: MyScript): boolean
    local score = 0         -- Good!
    local name = "Player"   -- Good!
    return true
end

-- WRONG: Without local, the variable becomes global (bad practice!)
function init(self: MyScript): boolean
    score = 0               -- Creates a GLOBAL variable - avoid this!
    return true
end
```

:::note JavaScript Comparison
| Luau | JavaScript |
|------|------------|
| `local x = 5` | `let x = 5;` or `const x = 5;` |
| No `local` = global | `var x = 5;` (function-scoped) or global if outside function |

**Key difference:** In JavaScript, forgetting `let`/`const`/`var` in strict mode causes an error. In Luau, forgetting `local` silently creates a global variable, which can cause hard-to-find bugs.
:::

## Local Variables vs Persistent State

This is a **critical concept** that trips up many beginners.

### Local Variables (Temporary)

Variables declared with `local` inside a function exist **only while that function runs**. They disappear when the function ends.

```lua
function init(self: MyScript): boolean
    local score = 100  -- Created here
    print(score)       -- Works: 100
    return true
end  -- score is DESTROYED here

function advance(self: MyScript, elapsed: number): boolean
    print(score)       -- ERROR! score doesn't exist here!
    return true
end
```

### Persistent State (Using `self`)

To keep data across frames (between `init`, `advance`, and `draw`), store it on `self`:

```lua
export type MyScript = {
    score: number,  -- Declare the property in the type
}

function init(self: MyScript): boolean
    self.score = 100  -- Store on self
    print(self.score) -- Works: 100
    return true
end

function advance(self: MyScript, elapsed: number): boolean
    self.score += 1   -- Still works! Data persists
    print(self.score) -- Works: 101, 102, 103...
    return true
end
```

:::note After Effects Comparison
In After Effects expressions, you can't easily persist data between frames. The expression re-evaluates completely each frame.

**After Effects workaround:** Use layer markers, text layers, or the `posterizeTime()` function to approximate persistence.

**Rive advantage:** `self.variableName` persists naturally across frames.
:::

## Basic Data Types

Luau has these fundamental data types:

| Type | Example | Description |
|------|---------|-------------|
| `nil` | `nil` | Absence of value (like `null` in JS) |
| `boolean` | `true`, `false` | Logical values |
| `number` | `42`, `3.14`, `0xFF` | All numbers (integers and decimals) |
| `string` | `"hello"`, `'world'` | Text |
| `table` | `{}`, `{1,2,3}` | Arrays and objects |
| `function` | `function() end` | Callable code |

:::note JavaScript Comparison
| Luau | JavaScript |
|------|------------|
| `nil` | `null` or `undefined` |
| `boolean` | `boolean` |
| `number` | `number` (no separate int/float) |
| `string` | `string` |
| `table` (array) | `Array` |
| `table` (dict) | `Object` |
| `function` | `function` |

**Key difference:** Luau has only `nil` for "no value", while JavaScript has both `null` and `undefined`.
:::

## Operators

### Arithmetic Operators

These perform mathematical calculations.

```lua
local a = 10 + 5      -- Addition: 15
local b = 10 - 5      -- Subtraction: 5
local c = 10 * 5      -- Multiplication: 50
local d = 10 / 3      -- Division: 3.333...
local e = 10 // 3     -- Floor division: 3 (rounds down)
local f = 10 % 3      -- Modulo (remainder): 1
local g = 2 ^ 3       -- Exponentiation: 8
local h = -5          -- Negation: -5
```

:::note JavaScript Comparison
| Operation | Luau | JavaScript |
|-----------|------|------------|
| Floor division | `10 // 3` → `3` | `Math.floor(10 / 3)` → `3` |
| Exponentiation | `2 ^ 3` → `8` | `2 ** 3` → `8` |
| All others | Same | Same |
:::

### Compound Assignment Operators

These combine an operation with assignment for cleaner code.

```lua
local x = 10
x += 5   -- x = x + 5   → 15
x -= 3   -- x = x - 3   → 12
x *= 2   -- x = x * 2   → 24
x /= 4   -- x = x / 4   → 6
x //= 2  -- x = x // 2  → 3
x %= 2   -- x = x % 2   → 1
```

:::note JavaScript Comparison
JavaScript has `+=`, `-=`, `*=`, `/=`, `%=` but **not** `//=` (floor division assignment).
Luau has all of these plus `//=` and `..=` (string concatenation assignment).
:::

### Comparison Operators

These compare values and return `true` or `false`.

```lua
local a = 5 == 5      -- Equal: true
local b = 5 ~= 3      -- NOT equal: true (note: ~= not !=)
local c = 5 < 10      -- Less than: true
local d = 5 > 3       -- Greater than: true
local e = 5 <= 5      -- Less than or equal: true
local f = 5 >= 5      -- Greater than or equal: true
```

:::danger Critical Difference: Not Equal
**Luau uses `~=` for "not equal", NOT `!=`!**

| Luau | JavaScript / After Effects |
|------|---------------------------|
| `x ~= y` | `x !== y` |

This is the #1 syntax mistake when coming from other languages!
:::

### Logical Operators

These work with boolean values.

```lua
local a = true and false   -- Both must be true: false
local b = true or false    -- At least one true: true
local c = not true         -- Negation: false
```

:::note JavaScript Comparison
| Luau | JavaScript |
|------|------------|
| `and` | `&&` |
| `or` | `||` |
| `not` | `!` |

Example:
```lua
-- Luau
if health > 0 and hasWeapon then

-- JavaScript
if (health > 0 && hasWeapon) {
```
:::

### String Operators

```lua
-- Concatenation (joining strings)
local full = "Hello" .. " " .. "World"  -- "Hello World"

-- String length
local len = #"Hello"  -- 5

-- String interpolation (backticks!)
local name = "Player"
local score = 100
local msg = `{name} scored {score}!`  -- "Player scored 100!"
```

:::note JavaScript Comparison
| Luau | JavaScript |
|------|------------|
| `"a" .. "b"` | `"a" + "b"` |
| `#str` | `str.length` |
| `` `{name}` `` | `` `${name}` `` |

**Key difference:** Luau uses `..` for string concatenation, not `+`. Using `+` with strings in Luau will try to convert them to numbers!
:::

## Exercises

### Exercise 1: Variable Declaration ⭐

**Goal:** Declare local variables and print them from `init`.

**Why this matters:** Every script starts by setting up variables. This exercise ensures you understand the basics before moving on.

**Real-world use:** In a game, you'd declare character stats, position, speed, etc. In an interactive graphic, you'd declare animation progress, colors, sizes.

---

#### Step-by-Step Setup

1. **Create a new Node Script in Rive:**
   - Open the Rive Editor
   - In the Assets panel, click `+` → `Script` → `Node Script`
   - Name it "Exercise1_Variables"

2. **Copy and paste this code:**

```lua
--!strict

export type Exercise1 = {}

function init(self: Exercise1): boolean
    -- Declare variables of different types
    local characterName = "Warrior"   -- string
    local level = 5                   -- number (integer)
    local experience = 1250.5         -- number (decimal)
    local hasShield = true            -- boolean

    -- Print each variable to the Console
    print(characterName)
    print(level)
    print(experience)
    print(hasShield)

    return true  -- Keep the script running
end

function draw(self: Exercise1, renderer: Renderer)
    -- Empty - we're not drawing anything yet
end

return function(): Node<Exercise1>
    return {
        init = init,
        draw = draw,
    }
end
```

3. **Attach the script to a node:**
   - Draw a simple rectangle on the artboard
   - Drag the script onto the rectangle (or select the rectangle and assign the script)

4. **View the output:**
   - Open the Console panel (View → Console)
   - Press Play in the State Machine
   - You should see the printed values

**Expected Console Output:**
```
Warrior
5
1250.5
true
```

---

#### Understanding the Code

```lua
local characterName = "Warrior"
```

| Part | Meaning |
|------|---------|
| `local` | This variable only exists inside this function |
| `characterName` | The name we chose for this variable |
| `=` | Assignment operator (puts the value into the variable) |
| `"Warrior"` | A string value (text in quotes) |

:::note JavaScript Equivalent
```javascript
let characterName = "Warrior";
let level = 5;
let experience = 1250.5;
let hasShield = true;

console.log(characterName);
console.log(level);
console.log(experience);
console.log(hasShield);
```

### Exercise 2: Arithmetic Operations ⭐

**Goal:** Do math inside `init` and print results.

**Why this matters:** Animation and games are built on math. You'll constantly calculate positions, speeds, damage, progress, etc.

**Real-world use:** Calculate damage in a game, compute animation progress, convert units, determine percentages.

---

#### Step-by-Step Setup

1. **Create a new Node Script** named "Exercise2_Arithmetic"

2. **Copy and paste:**

```lua
--!strict

export type Exercise2 = {}

function init(self: Exercise2): boolean
    local baseDamage = 50
    local critMultiplier = 2.5
    local armorReduction = 15

    -- Calculate final damage
    local critDamage = baseDamage * critMultiplier
    local finalDamage = critDamage - armorReduction

    -- Calculate what percentage was blocked
    local percentBlocked = armorReduction / critDamage * 100

    -- Print results using string interpolation
    print(`Base damage: {baseDamage}`)
    print(`Crit multiplier: {critMultiplier}x`)
    print(`Crit damage: {critDamage}`)
    print(`Armor reduction: {armorReduction}`)
    print(`Final damage: {finalDamage}`)
    print(`Percent blocked: {percentBlocked}%`)

    return true
end

function draw(self: Exercise2, renderer: Renderer)
end

return function(): Node<Exercise2>
    return {
        init = init,
        draw = draw,
    }
end
```

3. **Attach to a node and run**

**Expected Console Output:**
```
Base damage: 50
Crit multiplier: 2.5x
Crit damage: 125
Armor reduction: 15
Final damage: 110
Percent blocked: 12%
```

---

#### Understanding the Code

```lua
local critDamage = baseDamage * critMultiplier
```

This multiplies `baseDamage` (50) by `critMultiplier` (2.5) to get 125.

```lua
print(`Percent blocked: {percentBlocked}%`)
```

The backticks (`` ` ``) create an **interpolated string**. Anything inside `{}` is evaluated and inserted into the string.

:::note JavaScript Equivalent
```javascript
const baseDamage = 50;
const critMultiplier = 2.5;
const armorReduction = 15;

const critDamage = baseDamage * critMultiplier;
const finalDamage = critDamage - armorReduction;
const percentBlocked = (armorReduction / critDamage) * 100;

console.log(`Final damage: ${finalDamage}`);
console.log(`Percent blocked: ${percentBlocked}%`);
```
:::

### Exercise 3: Compound Assignments ⭐

**Goal:** Practice `+=`, `-=`, `*=`, and `//=` for numeric updates.

**Why this matters:** In animation and games, you constantly update values incrementally. Compound operators make this clean and readable.

**Real-world use:** Increment score, decrease health, scale size, update position.

---

#### Code

```lua
--!strict

export type Exercise3 = {}

function init(self: Exercise3): boolean
    local score = 100

    -- Add 50 to score
    score += 50
    print(`After +50: {score}`)  -- 150

    -- Multiply by 2
    score *= 2
    print(`After *2: {score}`)   -- 300

    -- Subtract 75
    score -= 75
    print(`After -75: {score}`)  -- 225

    -- Floor divide by 3 (rounds down)
    score //= 3
    print(`After //3: {score}`)  -- 75

    return true
end

function draw(self: Exercise3, renderer: Renderer)
end

return function(): Node<Exercise3>
    return {
        init = init,
        draw = draw,
    }
end
```

**Expected Console Output:**
```
After +50: 150
After *2: 300
After -75: 225
After //3: 75
```

---

#### Understanding Compound Assignment

| Expression | Equivalent To | Result |
|------------|---------------|--------|
| `score += 50` | `score = score + 50` | 100 → 150 |
| `score *= 2` | `score = score * 2` | 150 → 300 |
| `score -= 75` | `score = score - 75` | 300 → 225 |
| `score //= 3` | `score = score // 3` | 225 → 75 |

:::note Floor Division
`//` is **floor division** — it divides and rounds DOWN to the nearest integer.

- `225 / 3 = 75.0` (regular division)
- `225 // 3 = 75` (floor division)
- `226 // 3 = 75` (not 75.33, rounds down!)
:::

### Exercise 4: String Interpolation ⭐⭐

**Goal:** Use Luau string interpolation to format output.

**Why this matters:** Clear, formatted output helps you debug and verify your code is working correctly.

**Real-world use:** Create dynamic text displays, debug output, formatted logs.

---

#### Code

```lua
--!strict

export type Exercise4 = {}

function init(self: Exercise4): boolean
    local playerName = "Shadowblade"
    local goldCollected = 250
    local enemiesDefeated = 12
    local timePlayed = 45.7

    -- Simple interpolation
    print(`Player: {playerName}`)

    -- Multiple values in one string
    print(`Gold: {goldCollected} | Enemies: {enemiesDefeated}`)

    -- Expressions inside braces
    print(`Time: {timePlayed} minutes ({timePlayed / 60} hours)`)

    -- Building complex output
    print("---Player Stats---")
    print(`  Name: {playerName}`)
    print(`  Gold: {goldCollected}`)
    print(`  Kills: {enemiesDefeated}`)
    print(`  Hours: {timePlayed / 60}`)

    return true
end

function draw(self: Exercise4, renderer: Renderer)
end

return function(): Node<Exercise4>
    return {
        init = init,
        draw = draw,
    }
end
```

**Expected Console Output:**
```
Player: Shadowblade
Gold: 250 | Enemies: 12
Time: 45.7 minutes (0.7616666666666667 hours)
---Player Stats---
  Name: Shadowblade
  Gold: 250
  Kills: 12
  Hours: 0.7616666666666667
```

---

#### String Interpolation Syntax

```lua
`Text {expression} more text`
```

- Use **backticks** (`` ` ``) not regular quotes
- Put variables or expressions inside `{}`
- The expression is evaluated and converted to a string

:::note JavaScript Comparison
| Luau | JavaScript |
|------|------------|
| `` `Hello {name}` `` | `` `Hello ${name}` `` |

**Key difference:** Luau uses just `{}`, JavaScript uses `${}`.
:::

### Exercise 5: Logical Operators ⭐⭐

**Goal:** Use boolean logic to compute game conditions.

**Why this matters:** Games and interactive graphics are full of conditions. "Can the player attack?" depends on multiple factors.

**Real-world use:** Check if actions are allowed, determine animation states, trigger events.

---

#### Code

```lua
--!strict

export type Exercise5 = {}

function init(self: Exercise5): boolean
    local health = 25
    local maxHealth = 100
    local hasPotion = true
    local stunned = false

    -- Individual conditions
    local isLowHealth = health <= 30
    local healthPercent = health / maxHealth

    -- Combined conditions with AND
    -- Can heal only if: low health AND has potion AND not stunned
    local canHeal = isLowHealth and hasPotion and not stunned

    -- Combined conditions with OR
    -- Critical state if: health <= 10 OR health percent <= 10%
    local isCritical = health <= 10 or healthPercent <= 0.1

    -- Print all results
    print(`Health: {health}/{maxHealth} ({healthPercent * 100}%)`)
    print(`Low health (<=30): {isLowHealth}`)
    print(`Has potion: {hasPotion}`)
    print(`Stunned: {stunned}`)
    print(`Can heal: {canHeal}`)
    print(`Critical: {isCritical}`)

    return true
end

function draw(self: Exercise5, renderer: Renderer)
end

return function(): Node<Exercise5>
    return {
        init = init,
        draw = draw,
    }
end
```

**Expected Console Output:**
```
Health: 25/100 (25%)
Low health (<=30): true
Has potion: true
Stunned: false
Can heal: true
Critical: false
```

---

#### Understanding Logical Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `and` | Both must be true | `true and true` → `true` |
| `or` | At least one true | `false or true` → `true` |
| `not` | Inverts the value | `not true` → `false` |

```lua
local canHeal = isLowHealth and hasPotion and not stunned
```

This is `true` only if ALL of these are true:
- `isLowHealth` is `true`
- `hasPotion` is `true`
- `stunned` is `false` (because `not false` is `true`)

:::note JavaScript Comparison
```javascript
// JavaScript equivalent
const canHeal = isLowHealth && hasPotion && !stunned;
const isCritical = health <= 10 || healthPercent <= 0.1;
```
:::

## Common Mistakes to Avoid

:::danger Top 5 Mistakes
1. **Forgetting `local`** — Always declare with `local` to avoid globals
2. **Using `!=` instead of `~=`** — Luau uses `~=` for not-equal
3. **Using `+` for strings** — Use `..` for concatenation: `"a" .. "b"`
4. **Expecting 0 to be falsy** — In Luau, `0` is truthy!
5. **Forgetting `.value` on Inputs** — `self.speed.value`, not `self.speed`
:::
