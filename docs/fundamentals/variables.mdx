# Variables and Scope

Luau syntax is clean and minimalist. Statements do not require semicolons at the end of lines.

## Comments

```lua
-- This is a single-line comment

--[[
This is a
multi-line comment
]]
```

## Variable Declaration

In Luau, the concept of **scope** is critical. Scope determines where a variable is accessible.

```lua
-- Global variable (AVOID THIS!)
gravity = 9.8

-- Local variable (PREFERRED)
local speed = 50
```

### Global vs Local Variables

| Type | Declaration | Scope | Recommendation |
|------|-------------|-------|----------------|
| **Global** | `name = value` | Everywhere | ❌ Avoid |
| **Local** | `local name = value` | Current block | ✅ Always use |

:::danger Avoid Global Variables
Global variables can lead to naming collisions and make code harder to trace and debug. Always use `local` unless you have a very specific reason not to.
:::

## Block Scope

Variables are scoped to the **block** where they are defined (a function, loop, or `do...end` block):

```lua
local function calculate()
    local result = 10  -- Only exists inside this function

    if result > 5 then
        local message = "High"  -- Only exists inside this if block
        print(message)
    end

    -- print(message)  -- Error: 'message' is out of scope here
end
```

### Explicit Scope with `do ... end`

Create explicit scopes to limit variable lifetime:

```lua
do
    local temp = 42
    print(temp)
end
-- print(temp)  -- Error: temp is out of scope
```

## Closures and Upvalues

Functions capture variables from their surrounding scope (**upvalues**). This enables **closures**:

```lua
local function makeCounter()
    local count = 0
    return function()
        count += 1
        return count
    end
end

local nextCount = makeCounter()
print(nextCount())  -- 1
print(nextCount())  -- 2
print(nextCount())  -- 3
```

:::tip Closures in Rive
Closures are especially useful in Rive for callbacks, stateful helpers, and maintaining state between frames.
:::
