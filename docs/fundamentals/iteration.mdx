# Iteration

## Learning Objectives

By the end of this lesson, you will be able to:
- Write numeric `for` loops with custom start, end, and step values
- Use `while` and `repeat until` loops appropriately
- Control loop execution with `break` and `continue`
- Iterate over arrays with `ipairs` preserving order
- Iterate over dictionaries with generalized iteration
- Write nested loops for multi-dimensional data
- Implement per-frame iteration in `advance()` for animations

---

## AE/JS Syntax Comparison

Here's how iteration differs between languages:

| Concept | JavaScript | Luau |
|---------|------------|------|
| Basic for loop | `for (let i = 0; i < 5; i++)` | `for i = 1, 5 do` |
| Loop with step | `for (let i = 0; i <= 10; i += 2)` | `for i = 0, 10, 2 do` |
| Countdown | `for (let i = 5; i >= 1; i--)` | `for i = 5, 1, -1 do` |
| While loop | `while (x > 0) { }` | `while x > 0 do ... end` |
| Do-while | `do { } while (x > 0)` | `repeat ... until x <= 0` |
| Array iteration | `arr.forEach((v, i) => {})` | `for i, v in ipairs(arr) do` |
| Object iteration | `for (const k in obj) {}` | `for k, v in obj do` |
| Break | `break;` | `break` |
| Continue | `continue;` | `continue` |

:::warning Critical Differences from JavaScript
- **1-based indexing**: Luau arrays start at index 1, not 0
- **Inclusive ranges**: `for i = 1, 5 do` includes both 1 AND 5 (runs 5 times)
- **End keyword**: Every loop ends with `end`
- **Countdown needs step**: `for i = 5, 1 do` won't run - need `for i = 5, 1, -1 do`
- **No C-style for**: Can't write `for (init; condition; update)` syntax
- **Condition inversion**: `repeat until` uses "until condition is TRUE" (opposite of while)
:::

## Rive Context

Iteration is essential in Rive animations for processing collections of objects. You'll iterate over:
- **Arrays of enemies/particles** to update positions each frame
- **Waypoints** to calculate paths
- **Animation keyframes** to interpolate values
- **Input events** to process user interactions
- **Child nodes** to apply transformations

Loops run inside lifecycle functions (`init`, `advance`, `draw`). For per-frame iteration over persistent collections, store them on `self` and iterate in `advance`.

## Numeric For Loop

The most common loop for counting or stepping through ranges.

### Basic Syntax

```lua
-- Basic: count from start to end (INCLUSIVE!)
for i = 1, 5 do
    print(i)  -- 1, 2, 3, 4, 5
end
```

**JavaScript Equivalent**:
```javascript
// JavaScript (exclusive end, 0-based)
for (let i = 1; i <= 5; i++) {
    console.log(i);  // 1, 2, 3, 4, 5
}
```

### With Step Value

```lua
-- Count by 2s
for i = 0, 10, 2 do
    print(i)  -- 0, 2, 4, 6, 8, 10
end

-- Countdown (MUST specify negative step!)
for i = 5, 1, -1 do
    print(i)  -- 5, 4, 3, 2, 1
end
```

**JavaScript Equivalent**:
```javascript
// Step by 2
for (let i = 0; i <= 10; i += 2) {
    console.log(i);
}

// Countdown
for (let i = 5; i >= 1; i--) {
    console.log(i);
}
```

### Common Gotcha: Missing Step for Countdown

:::danger Countdown Loops Need Negative Step!
```lua
-- This loop does NOTHING!
for i = 5, 1 do
    print(i)  -- Never runs! Default step is +1
end

-- This is correct:
for i = 5, 1, -1 do
    print(i)  -- 5, 4, 3, 2, 1
end
```
:::

### Loop Variable Scope

The loop variable is local to the loop body and **cannot be modified**:

```lua
for i = 1, 5 do
    i = i + 10  -- ERROR: cannot modify loop variable
end

-- If you need to skip values, use continue instead:
for i = 1, 10 do
    if i % 2 == 0 then continue end  -- Skip even numbers
    print(i)  -- 1, 3, 5, 7, 9
end
```

## While Loop

Repeats while a condition is true. The condition is checked **before** each iteration.

```lua
local health = 100
while health > 0 do
    health -= 10
    print(`Health: {health}`)
end
-- Runs 10 times, prints 90, 80, 70... 0
```

**JavaScript Equivalent**:
```javascript
let health = 100;
while (health > 0) {
    health -= 10;
    console.log(`Health: ${health}`);
}
```

:::warning Infinite Loop Danger
If the condition never becomes false, the loop runs forever and freezes your animation. Always ensure loop conditions can eventually become false.

```lua
-- DANGER: Infinite loop!
local x = 1
while x > 0 do
    x += 1  -- x only gets bigger, never <= 0
end

-- SAFE: Has exit condition
local x = 100
while x > 0 do
    x -= 1  -- Eventually reaches 0
end
```
:::

---

## Repeat Until

Like `while`, but the condition is checked **after** each iteration. The body always runs at least once.

```lua
local attempts = 0
repeat
    attempts += 1
    print(`Attempt {attempts}`)
until attempts >= 3
-- Always runs at least once, prints 1, 2, 3
```

**JavaScript Equivalent**:
```javascript
// JavaScript do-while
let attempts = 0;
do {
    attempts++;
    console.log(`Attempt ${attempts}`);
} while (attempts < 3);  // Note: condition is INVERTED
```

:::warning Condition is INVERTED from JavaScript!
JavaScript `do-while` continues WHILE condition is true.
Luau `repeat until` stops WHEN condition becomes true.

```javascript
// JavaScript: continues while attempts < 3
do { } while (attempts < 3);

// Luau: stops when attempts >= 3 (same logic, opposite syntax)
repeat until attempts >= 3
```
:::

### While vs Repeat Until

| `while` | `repeat until` |
|---------|----------------|
| Checks condition **first** | Checks condition **after** |
| May not run at all | Always runs at least once |
| `while condition do` | `repeat ... until condition` |
| Stops when false | Stops when true |

## Break and Continue

Control loop execution flow:

### Break: Exit Loop Immediately

```lua
-- Search for first match, then stop
for i = 1, 100 do
    if i > 10 then
        print("Found it, stopping!")
        break  -- Exit loop immediately
    end
    print(i)  -- Only prints 1-10
end
print("Loop finished")
```

### Continue: Skip to Next Iteration

```lua
-- Skip even numbers
for i = 1, 10 do
    if i % 2 == 0 then continue end  -- Skip this iteration
    print(i)  -- Only odd numbers: 1, 3, 5, 7, 9
end
```

**JavaScript Equivalent**:
```javascript
// Break
for (let i = 1; i <= 100; i++) {
    if (i > 10) break;
    console.log(i);
}

// Continue
for (let i = 1; i <= 10; i++) {
    if (i % 2 === 0) continue;
    console.log(i);
}
```

## Iterating Over Arrays (ipairs)

Use `ipairs` for sequential arrays where order matters:

```lua
local enemies = {"Slime", "Goblin", "Mage", "Boss"}

for index, enemy in ipairs(enemies) do
    print(`{index}: {enemy}`)
end
-- 1: Slime
-- 2: Goblin
-- 3: Mage
-- 4: Boss
```

**JavaScript Equivalent**:
```javascript
const enemies = ["Slime", "Goblin", "Mage", "Boss"];

enemies.forEach((enemy, index) => {
    console.log(`${index}: ${enemy}`);  // Note: 0-based in JS!
});

// Or with for...of (no index)
for (const enemy of enemies) {
    console.log(enemy);
}
```

### When to Use ipairs

- You need the numeric index
- Order must be preserved (1, 2, 3...)
- Array has no gaps (nil values)
- Processing sequential collections

:::warning ipairs Stops at First nil
```lua
local arr = {1, 2, nil, 4, 5}

for i, v in ipairs(arr) do
    print(v)  -- Only prints 1, 2 (stops at nil!)
end
```
:::

## Iterating Over Dictionaries (Generalized Iteration)

For key-value tables, use generalized iteration (or `pairs()`):

```lua
local stats = {
    health = 100,
    mana = 50,
    speed = 12
}

-- Generalized iteration (Luau style - preferred)
for key, value in stats do
    print(`{key}: {value}`)
end
-- Order is NOT guaranteed!
```

**JavaScript Equivalent**:
```javascript
const stats = {
    health: 100,
    mana: 50,
    speed: 12
};

// for...in (keys only)
for (const key in stats) {
    console.log(`${key}: ${stats[key]}`);
}

// Object.entries (key-value pairs)
for (const [key, value] of Object.entries(stats)) {
    console.log(`${key}: ${value}`);
}
```

### pairs vs Generalized Iteration

Luau supports both `pairs()` and generalized iteration (without `pairs`):

```lua
-- Traditional (Lua style)
for k, v in pairs(tbl) do ... end

-- Generalized (Luau style - preferred)
for k, v in tbl do ... end
```

Both work identically. Generalized iteration is cleaner and preferred in modern Luau.

:::warning Dictionary Order is NOT Guaranteed
```lua
local data = {a = 1, b = 2, c = 3}
for k, v in data do
    print(k)  -- Could be a, b, c or c, a, b or any order!
end
```
:::

## Nested Loops

Loops can be nested for multi-dimensional operations:

```lua
-- Create a 3x3 grid
for row = 1, 3 do
    for col = 1, 3 do
        print(`({row}, {col})`)
    end
end
```

**JavaScript Equivalent**:
```javascript
for (let row = 1; row <= 3; row++) {
    for (let col = 1; col <= 3; col++) {
        console.log(`(${row}, ${col})`);
    }
}
```

:::tip Breaking Out of Nested Loops
`break` only exits the **innermost** loop. To exit multiple levels, use a flag variable:

```lua
local found = false
for row = 1, 10 do
    for col = 1, 10 do
        if grid[row][col] == target then
            found = true
            break  -- Only exits inner loop!
        end
    end
    if found then break end  -- Exit outer loop too
end
```
:::

### Exercise 2: While Loops for Game Logic

**Goal**: Use while loops for condition-based iteration.

**Why This Matters**: While loops are perfect when you don't know how many iterations you need - like waiting for a condition, processing until complete, or simulating game events.

**Real-World Use**: Ammunition systems, level progression, health regeneration, retry logic.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Trace through each while loop mentally before running
4. Verify the loop count matches your expectation

```lua
--!strict

export type WhileLoops = {}

function init(self: WhileLoops): boolean
    print("=== While Loop Patterns ===\n")

    -- Pattern 1: Countdown to zero
    print("Pattern 1: Ammunition System")
    print("----------------------------")
    local ammo = 6
    local shotsFired = 0

    print(`Starting ammo: {ammo}`)
    while ammo > 0 do
        ammo -= 1
        shotsFired += 1
        print(`  Shot {shotsFired}! Ammo remaining: {ammo}`)
    end
    print("Click! Out of ammo!")
    print(`Total shots: {shotsFired}\n`)

    -- Pattern 2: Progress toward goal
    print("Pattern 2: Level Up System")
    print("--------------------------")
    local xp = 0
    local level = 1
    local xpNeeded = 100

    print(`Starting: Level {level}, XP needed: {xpNeeded}`)
    while level < 5 do
        xp += 50  -- Gain 50 XP per iteration
        print(`  Gained 50 XP. Total: {xp}/{xpNeeded}`)

        if xp >= xpNeeded then
            level += 1
            xp -= xpNeeded
            xpNeeded = math.floor(xpNeeded * 1.5)  -- Scale XP requirement
            print(`  LEVEL UP! Now level {level}. Next: {xpNeeded} XP`)
        end
    end
    print(`Final: Level {level}\n`)

    -- Pattern 3: Approach target value
    print("Pattern 3: Health Regeneration")
    print("------------------------------")
    local health = 30
    local maxHealth = 100
    local regenRate = 15
    local ticks = 0

    print(`Starting health: {health}/{maxHealth}`)
    while health < maxHealth do
        health += regenRate
        ticks += 1

        -- Clamp to max
        if health > maxHealth then
            health = maxHealth
        end

        print(`  Tick {ticks}: Health = {health}/{maxHealth}`)
    end
    print(`Fully healed in {ticks} ticks!\n`)

    -- Pattern 4: Sentinel value (search)
    print("Pattern 4: Find First Match")
    print("---------------------------")
    local values = {3, 7, 2, 9, 5, 8, 1}
    local target = 9
    local index = 1
    local found = false

    print(`Searching for {target} in array...`)
    while index <= #values and not found do
        print(`  Checking index {index}: {values[index]}`)
        if values[index] == target then
            found = true
        else
            index += 1
        end
    end

    if found then
        print(`Found {target} at index {index}!`)
    else
        print(`{target} not found`)
    end

    return true
end

function draw(self: WhileLoops, renderer: Renderer)
end

return function(): Node<WhileLoops>
    return {
        init = init,
        draw = draw,
    }
end
```

### Exercise 3: Repeat Until for Validation

**Goal**: Use repeat-until when you need at least one iteration.

**Why This Matters**: Some scenarios require running code at least once before checking the exit condition - like user input validation, retry logic, or initialization sequences.

**Real-World Use**: Connection retries, input validation, game initialization, "roll until success" mechanics.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Notice how repeat-until guarantees at least one execution
4. Compare the condition logic to JavaScript's do-while

```lua
--!strict

export type RepeatUntil = {}

function init(self: RepeatUntil): boolean
    print("=== Repeat Until Patterns ===\n")

    -- Pattern 1: Roll until success
    print("Pattern 1: Dice Rolling (need 6)")
    print("--------------------------------")
    local rolls = 0
    local result = 0

    repeat
        rolls += 1
        -- Pseudo-random: deterministic for demo
        result = (rolls * 7 + 3) % 6 + 1
        print(`  Roll {rolls}: {result}`)
    until result == 6 or rolls >= 10

    if result == 6 then
        print(`Got a 6 in {rolls} rolls!\n`)
    else
        print(`Gave up after {rolls} rolls\n`)
    end

    -- Pattern 2: Retry with backoff
    print("Pattern 2: Connection Retry")
    print("---------------------------")
    local attempts = 0
    local connected = false
    local maxAttempts = 5

    repeat
        attempts += 1
        print(`  Attempt {attempts}...`)

        -- Simulate: succeed on attempt 3
        if attempts >= 3 then
            connected = true
            print("  Connected!")
        else
            print("  Failed, retrying...")
        end
    until connected or attempts >= maxAttempts

    print(`Connection {if connected then "succeeded" else "failed"} after {attempts} attempts\n`)

    -- Pattern 3: Input validation
    print("Pattern 3: Find Valid Input")
    print("---------------------------")
    local validInputs = {5, -1, 0, 42, 100}
    local inputIndex = 0
    local validValue = 0

    print("Looking for value > 0 and <= 50...")
    repeat
        inputIndex += 1
        local testValue = validInputs[inputIndex]
        print(`  Testing: {testValue}`)

        if testValue > 0 and testValue <= 50 then
            validValue = testValue
            print(`  Valid! Using {validValue}`)
        end
    until validValue > 0 or inputIndex >= #validInputs

    print(`Result: {if validValue > 0 then validValue else "none found"}\n`)

    -- Comparison: while vs repeat
    print("Comparison: while vs repeat-until")
    print("----------------------------------")

    local x = 10
    local whileCount = 0
    print(`While (x < 5) with x = {x}:`)
    while x < 5 do  -- Condition false immediately
        whileCount += 1
        print("  Inside while")
    end
    print(`  Ran {whileCount} times (may be 0)\n`)

    local y = 10
    local repeatCount = 0
    print(`Repeat until (y >= 5) with y = {y}:`)
    repeat
        repeatCount += 1
        print("  Inside repeat")
    until y >= 5  -- Even though y >= 5, runs once
    print(`  Ran {repeatCount} time (always at least 1)`)

    return true
end

function draw(self: RepeatUntil, renderer: Renderer)
end

return function(): Node<RepeatUntil>
    return {
        init = init,
        draw = draw,
    }
end
```

**Expected Output**:
```

Pattern 1: Dice Rolling (need 6)
--------------------------------
  Roll 1: 4
  Roll 2: 5
  Roll 3: 6
Got a 6 in 3 rolls!

Pattern 2: Connection Retry
---------------------------
  Attempt 1...
  Failed, retrying...
  Attempt 2...
  Failed, retrying...
  Attempt 3...
  Connected!
Connection succeeded after 3 attempts

...

Comparison: while vs repeat-until
----------------------------------
While (x < 5) with x = 10:
  Ran 0 times (may be 0)

Repeat until (y >= 5) with y = 10:
  Inside repeat
  Ran 1 time (always at least 1)
```

**JavaScript Equivalent**:
```javascript

```

### Exercise 4: Break and Continue

**Goal**: Control loop flow with break and continue.

**Why This Matters**: Efficient loops often need early exits (break) when found, or to skip certain iterations (continue). These make your code cleaner than complex nested conditions.

**Real-World Use**: Search algorithms, filtering data, early termination, skipping invalid entries.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Trace through each example to understand flow control
4. Notice how break exits completely while continue just skips

```lua
--!strict

export type LoopControl = {}

function init(self: LoopControl): boolean
    print("=== Loop Control: break and continue ===\n")

    -- Break: Find first match and stop
    print("Part 1: break - Find First Match")
    print("---------------------------------")
    local targets = {10, 25, 50, 75, 100}
    local searchFor = 50
    local foundAt = 0

    print(`Searching for {searchFor}...`)
    for i, value in ipairs(targets) do
        print(`  Checking index {i}: {value}`)
        if value == searchFor then
            foundAt = i
            print(`  Found! Breaking out of loop.`)
            break  -- Exit immediately
        end
    end
    print(`Result: Found {searchFor} at index {foundAt}\n`)

    -- Continue: Skip invalid entries
    print("Part 2: continue - Skip Invalid Scores")
    print("--------------------------------------")
    local scores = {85, -1, 92, 0, 78, -5, 95}
    local validTotal = 0
    local validCount = 0

    print("Processing scores (skipping invalid <= 0)...")
    for i, score in ipairs(scores) do
        if score <= 0 then
            print(`  Index {i}: {score} - SKIPPED (invalid)`)
            continue  -- Skip to next iteration
        end

        validTotal += score
        validCount += 1
        print(`  Index {i}: {score} - Added (total: {validTotal})`)
    end
    print(`Average of {validCount} valid scores: {validTotal / validCount}\n`)

    -- Break in while loop
    print("Part 3: break in while (infinite loop escape)")
    print("---------------------------------------------")
    local i = 0
    print("Running 'infinite' loop with break at 5...")
    while true do  -- Infinite loop!
        i += 1
        print(`  Iteration {i}`)
        if i >= 5 then
            print(`  Reached {i}, breaking!`)
            break  -- Escape the infinite loop
        end
    end
    print(`Escaped after {i} iterations\n`)

    -- Continue with complex condition
    print("Part 4: continue with condition")
    print("-------------------------------")
    print("Printing 1-10, skipping multiples of 3:")
    local output = ""
    for n = 1, 10 do
        if n % 3 == 0 then
            continue  -- Skip 3, 6, 9
        end
        output ..= `{n} `
    end
    print(`Result: {output}\n`)

    -- Nested loop with break
    print("Part 5: break in nested loops")
    print("-----------------------------")
    print("Breaking only exits INNER loop:")
    for outer = 1, 3 do
        print(`Outer {outer}:`)
        for inner = 1, 5 do
            if inner > 2 then
                print(`  Inner {inner} - breaking inner loop`)
                break  -- Only breaks inner loop!
            end
            print(`  Inner {inner}`)
        end
    end

    return true
end

function draw(self: LoopControl, renderer: Renderer)
end

return function(): Node<LoopControl>
    return {
        init = init,
        draw = draw,
    }
end
```

```

  Checking index 1: 10

  Checking index 3: 50

Result: Found 50 at index 3

--------------------------------------
Processing scores (skipping invalid <= 0)...
  Index 1: 85 - Added (total: 85)
```

### Exercise 5: Iterating Over Arrays with ipairs

**Goal**: Process collections using ipairs for ordered iteration.

**Why This Matters**: Most game data comes in arrays - enemy lists, inventory items, waypoints. ipairs gives you both the index and value while guaranteeing order.

**Real-World Use**: Enemy wave processing, inventory management, particle systems, animation sequences.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Pay attention to the index values (start at 1!)
4. Notice how ipairs preserves insertion order

```lua
--!strict

export type ArrayIteration = {}

function init(self: ArrayIteration): boolean
    print("=== Array Iteration with ipairs ===\n")

    -- Basic array iteration
    print("Part 1: Enemy Wave Processing")
    print("-----------------------------")
    local enemies = {"Slime", "Goblin", "Orc", "Troll", "Dragon"}

    print("Enemy roster:")
    for i, enemy in ipairs(enemies) do
        print(`  {i}. {enemy}`)  -- Note: index starts at 1!
    end

    print("\nProcessing wave (damage scales with position):")
    for i, enemy in ipairs(enemies) do
        local damage = i * 10  -- Later enemies hit harder
        print(`  {enemy} attacks for {damage} damage!`)
    end

    -- Nested table iteration
    print("\nPart 2: Inventory Management")
    print("----------------------------")
    local inventory = {
        {name = "Sword", damage = 50},
        {name = "Shield", armor = 30},
        {name = "Potion", healing = 100},
        {name = "Bow", damage = 35},
    }

    local totalDamage = 0
    local totalArmor = 0
    local totalHealing = 0

    print("Inventory contents:")
    for i, item in ipairs(inventory) do
        print(`  Slot {i}: {item.name}`)

        if item.damage then
            totalDamage += item.damage
            print(`    → Damage: +{item.damage}`)
        end
        if item.armor then
            totalArmor += item.armor
            print(`    → Armor: +{item.armor}`)
        end
        if item.healing then
            totalHealing += item.healing
            print(`    → Healing: +{item.healing}`)
        end
    end

    print(`\nInventory totals:`)
    print(`  Total damage: {totalDamage}`)
    print(`  Total armor: {totalArmor}`)
    print(`  Total healing: {totalHealing}`)

    -- Modifying during iteration
    print("\nPart 3: Position Updates (modifying tables)")
    print("-------------------------------------------")
    local positions = {
        {x = 0, y = 0},
        {x = 10, y = 5},
        {x = 20, y = 10},
    }

    print("Moving all positions by (5, 5):")
    for i, pos in ipairs(positions) do
        print(`  Before: Position {i} = ({pos.x}, {pos.y})`)
        pos.x += 5  -- Safe to modify table contents
        pos.y += 5
        print(`  After:  Position {i} = ({pos.x}, {pos.y})`)
    end

    return true
end

function draw(self: ArrayIteration, renderer: Renderer)
end

return function(): Node<ArrayIteration>
    return {
        init = init,
        draw = draw,
    }
end
```

### Exercise 6: Iterating Over Dictionaries

**Goal**: Process key-value data using generalized iteration.

**Why This Matters**: Game configuration, player stats, and entity properties are often stored as dictionaries. Understanding unordered iteration is crucial.

**Real-World Use**: Stats display, config loading, buff/debuff systems, loot tables.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Note that iteration order is NOT guaranteed for dictionaries
4. Run multiple times - order may vary!

```lua
--!strict

export type DictIteration = {}

function init(self: DictIteration): boolean
    print("=== Dictionary Iteration ===\n")

    -- Basic dictionary iteration
    print("Part 1: Character Stats")
    print("-----------------------")
    local stats = {
        health = 100,
        mana = 50,
        strength = 15,
        agility = 12,
        intelligence = 18,
    }

    print("Current stats (order may vary!):")
    for stat, value in stats do  -- Generalized iteration
        print(`  {stat}: {value}`)
    end

    -- Applying modifiers
    print("\nPart 2: Buff Application")
    print("------------------------")
    local buffs = {
        strength = 5,
        agility = 3,
        intelligence = 2,
    }

    print("Applying buffs:")
    for stat, bonus in buffs do
        if stats[stat] then
            local oldValue = stats[stat]
            stats[stat] += bonus
            print(`  {stat}: {oldValue} → {stats[stat]} (+{bonus})`)
        end
    end

    -- Nested dictionary
    print("\nPart 3: Loot Table")
    print("------------------")
    local lootTable = {
        gold = {min = 10, max = 50},
        gems = {min = 0, max = 3},
        keys = {min = 0, max = 1},
    }

    print("Possible drops:")
    for item, range in lootTable do
        print(`  {item}: {range.min}-{range.max}`)
    end

    -- Type checking during iteration
    print("\nPart 4: Config Validation")
    print("-------------------------")
    local config = {
        volume = 0.8,
        brightness = 1.2,  -- Invalid: > 1.0
        difficulty = 0.5,
        musicEnabled = true,  -- Not a number
    }

    print("Validating numeric settings (0.0 - 1.0):")
    for setting, value in config do
        if type(value) == "number" then
            if value >= 0 and value <= 1.0 then
                print(`  {setting}: {value} ✓ valid`)
            else
                print(`  {setting}: {value} ✗ INVALID (out of range)`)
            end
        else
            print(`  {setting}: skipped (not numeric)`)
        end
    end

    return true
end

function draw(self: DictIteration, renderer: Renderer)
end

return function(): Node<DictIteration>
    return {
        init = init,
        draw = draw,
    }
end
```

```lua
    local grid: {{number}} = {}

        grid[row] = {}  -- Create row
```

### Exercise 8: Per-Frame Iteration with advance

**Goal**: Iterate over collections every frame for animation updates.

**Why This Matters**: Animation requires updating multiple objects each frame - particles moving, enemies patrolling, effects fading. This exercise shows the pattern for per-frame collection processing.

**Real-World Use**: Particle systems, enemy AI, projectile movement, physics simulation.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. This uses `advance()` which runs every frame
4. Watch the particles move in the console output

```lua
--!strict

export type FrameIteration = {
    particles: {{x: number, y: number, vx: number, vy: number}},
    frameCount: number,
}

function init(self: FrameIteration): boolean
    -- Create some particles with different velocities
    self.particles = {}
    for i = 1, 5 do
        table.insert(self.particles, {
            x = i * 20,           -- Spread out horizontally
            y = 50,               -- Start at same height
            vx = (i - 3) * 2,     -- Velocities: -4, -2, 0, 2, 4
            vy = -5,              -- All moving up initially
        })
    end
    self.frameCount = 0

    print("=== Per-Frame Particle System ===")
    print(`Created {#self.particles} particles`)
    print("Simulating with gravity and bounce...\n")

    return true
end

function advance(self: FrameIteration, seconds: number): boolean
    self.frameCount += 1

    -- Update all particles every frame
    for i, p in ipairs(self.particles) do
        -- Apply velocity (scaled by delta time)
        p.x += p.vx * seconds * 60
        p.y += p.vy * seconds * 60

        -- Apply gravity
        p.vy += 0.5

        -- Bounce off bottom
        if p.y > 200 then
            p.y = 200
            p.vy *= -0.8  -- Lose energy on bounce
        end

        -- Wrap horizontally
        if p.x < 0 then p.x = 200 end
        if p.x > 200 then p.x = 0 end
    end

    -- Log every 30 frames (roughly 0.5 seconds at 60fps)
    if self.frameCount % 30 == 0 then
        print(`Frame {self.frameCount}:`)
        for i, p in ipairs(self.particles) do
            print(`  Particle {i}: pos=({p.x // 1}, {p.y // 1}) vel=({p.vx // 1}, {p.vy // 1})`)
        end
    end

    -- Stop logging after a few seconds
    if self.frameCount > 180 then
        return false  -- Returning false stops advance calls
    end

    return true
end

function draw(self: FrameIteration, renderer: Renderer)
    -- In a real implementation, you'd render particles here
end

return function(): Node<FrameIteration>
    return {
        init = init,
        advance = advance,
        draw = draw,
        particles = {},  -- Will be initialized in init()
        frameCount = 0,
    }
end
```

## Common Mistakes

:::danger Common Iteration Errors
1. **Missing step for countdown** - `for i = 10, 1 do` won't run; need `for i = 10, 1, -1 do`
2. **Forgetting 1-based indexing** - Arrays start at 1, not 0
3. **Modifying loop variable** - Can't change `i` inside a numeric for loop
4. **Infinite while loops** - Ensure condition can eventually become false
5. **break in nested loops** - Only exits innermost loop
6. **Assuming dictionary order** - Key-value iteration order is NOT guaranteed
7. **Modifying array during iteration** - Can cause unexpected behavior; iterate in reverse or collect indices first
8. **Using 0-based index** - `arr[0]` is nil in Luau; use `arr[1]` for first element
:::

## Iteration Patterns Summary

| Pattern | When to Use | Example |
|---------|-------------|---------|
| `for i = start, end do` | Counting, fixed iterations | `for i = 1, 10 do` |
| `for i = start, end, step do` | Custom increments, countdowns | `for i = 10, 1, -1 do` |
| `while condition do` | Unknown iteration count, may not run | `while x > 0 do` |
| `repeat until condition` | Must run at least once | `repeat until done` |
| `for i, v in ipairs(arr)` | Ordered array traversal | `for i, enemy in ipairs(enemies)` |
| `for k, v in tbl do` | Dictionary traversal | `for name, value in config` |

## Quick Reference

```lua
-- Numeric for loop (INCLUSIVE range!)
for i = 1, 10 do end       -- 1 through 10
for i = 1, 10, 2 do end    -- 1, 3, 5, 7, 9
for i = 10, 1, -1 do end   -- 10 down to 1 (NEED -1!)

-- While and repeat
while condition do end
repeat until condition     -- Runs at least once!

-- Array iteration (1-based!)
for index, value in ipairs(array) do end

-- Dictionary iteration (unordered!)
for key, value in table do end

-- Loop control
break      -- Exit loop immediately
continue   -- Skip to next iteration
```
