## Syntax Note: Coming from JavaScript or After Effects?

:::note JavaScript / After Effects Comparison
| Concept | Luau | JavaScript |
|---------|------|------------|
| Array | `{1, 2, 3}` | `[1, 2, 3]` |
| Object/Dict | `{a = 1, b = 2}` | `{a: 1, b: 2}` |
| First index | `1` (one-based) | `0` (zero-based) |
| Length | `#arr` | `arr.length` |
| Add to end | `table.insert(arr, v)` | `arr.push(v)` |
| Remove last | `table.remove(arr)` | `arr.pop()` |
| Key check | `tbl.key ~= nil` | `"key" in obj` |

**Critical difference:** Luau arrays start at index **1**, not **0**!
:::

## What Is a Table?

A **table** is Luau's only data structure. It's incredibly flexible — the same syntax creates:

- **Arrays**: Ordered lists of values (like JS arrays)
- **Dictionaries**: Key-value pairs (like JS objects)
- **Mixed tables**: Both at once
- **Everything else**: Sets, matrices, objects, etc.

```lua
-- Array (sequential numeric keys)
local enemies = {"Slime", "Goblin", "Mage"}

-- Dictionary (string keys)
local player = { name = "Hero", health = 100 }

-- Mixed (both!)
local mixed = {
    "first",           -- index 1
    "second",          -- index 2
    name = "mixed",    -- key "name"
}
```

## Arrays (Sequential Tables)

### Creating Arrays

```lua
-- Create with values
local fruits = {"Apple", "Banana", "Cherry"}

-- Create empty and add later
local scores = {}
table.insert(scores, 100)
table.insert(scores, 95)
table.insert(scores, 87)
```

### Index Starts at 1!

This is the **#1 confusion** for JavaScript developers:

```lua
local items = {"Sword", "Shield", "Potion"}

print(items[1])  -- "Sword" (FIRST element!)
print(items[2])  -- "Shield"
print(items[3])  -- "Potion"
print(items[0])  -- nil (doesn't exist!)
```

:::danger Arrays Start at 1
```lua
-- WRONG mental model (JavaScript)
-- items[0] = "Sword"  ❌

-- CORRECT mental model (Luau)
-- items[1] = "Sword"  ✓
```

Every time you write a loop, remember: `for i = 1, #arr` not `for i = 0, #arr - 1`
:::

:::note JavaScript Comparison
```javascript
// JavaScript (0-indexed)
const items = ["Sword", "Shield", "Potion"];
console.log(items[0]);  // "Sword"

for (let i = 0; i < items.length; i++) {
    console.log(items[i]);
}
```

```lua
-- Luau (1-indexed)
local items = {"Sword", "Shield", "Potion"}
print(items[1])  -- "Sword"

for i = 1, #items do
    print(items[i])
end
```
:::

### Array Length

```lua
local arr = {10, 20, 30, 40, 50}
print(#arr)  -- 5
```

:::note JavaScript Comparison
```javascript
// JavaScript
arr.length  // Property

// Luau
#arr  -- Operator (like #string for string length)
```
:::

### Modifying Arrays

```lua
local items = {"Sword", "Shield"}

-- Add to end
table.insert(items, "Potion")
-- items = {"Sword", "Shield", "Potion"}

-- Add at position 2
table.insert(items, 2, "Armor")
-- items = {"Sword", "Armor", "Shield", "Potion"}

-- Remove last element
local last = table.remove(items)
-- last = "Potion", items = {"Sword", "Armor", "Shield"}

-- Remove at position 1
local first = table.remove(items, 1)
-- first = "Sword", items = {"Armor", "Shield"}

-- Modify directly
items[1] = "Heavy Armor"
-- items = {"Heavy Armor", "Shield"}
```

:::note JavaScript Comparison
| Operation | JavaScript | Luau |
|-----------|------------|------|
| Add to end | `arr.push(x)` | `table.insert(arr, x)` |
| Add at index | `arr.splice(i, 0, x)` | `table.insert(arr, i, x)` |
| Remove last | `arr.pop()` | `table.remove(arr)` |
| Remove at index | `arr.splice(i, 1)` | `table.remove(arr, i)` |
| Find index | `arr.indexOf(x)` | `table.find(arr, x)` |
:::

## Dictionaries (Key-Value Tables)

### Creating Dictionaries

```lua
-- Object-like syntax
local player = {
    name = "Hero",
    health = 100,
    level = 5,
}

-- Access with dot notation
print(player.name)    -- "Hero"
print(player.health)  -- 100

-- Access with bracket notation (same result)
print(player["name"])    -- "Hero"
print(player["health"])  -- 100
```

### When to Use Bracket Notation

Use brackets when:
- Key is a variable
- Key has spaces or special characters
- Key is computed at runtime

```lua
local stats = { hp = 100, mp = 50 }

-- Key from variable
local statName = "hp"
print(stats[statName])  -- 100

-- Key with space (must use brackets)
local labels = {
    ["health points"] = 100,
    ["mana points"] = 50,
}
print(labels["health points"])  -- 100
```

:::note JavaScript Comparison
This works exactly like JavaScript objects:

```javascript
// JavaScript
const player = { name: "Hero", health: 100 };
console.log(player.name);       // dot notation
console.log(player["name"]);    // bracket notation
console.log(player[varName]);   // variable key
```

```lua
-- Luau
local player = { name = "Hero", health = 100 }
print(player.name)       -- dot notation
print(player["name"])    -- bracket notation
print(player[varName])   -- variable key
```

**Only difference:** Luau uses `=` not `:` in definitions.
:::

### Adding and Modifying

```lua
local inventory = {}

-- Add new keys
inventory.gold = 500
inventory.gems = 10
inventory["magic crystals"] = 3

-- Modify existing
inventory.gold = inventory.gold + 100

-- Remove key (set to nil)
inventory.gems = nil
```

## Iterating Over Tables

### Arrays: Use `ipairs` or Numeric Loop

```lua
local items = {"Sword", "Shield", "Potion"}

-- Method 1: ipairs (index and value)
for i, item in ipairs(items) do
    print(`{i}: {item}`)
end

-- Method 2: numeric loop (most control)
for i = 1, #items do
    print(`{i}: {items[i]}`)
end
```

**Output:**
```
1: Sword
2: Shield
3: Potion
```

:::note JavaScript Comparison
```javascript
// JavaScript forEach
items.forEach((item, index) => {
    console.log(`${index}: ${item}`);  // 0: Sword, 1: Shield...
});

// JavaScript for...of
for (const item of items) {
    console.log(item);
}

// JavaScript traditional for
for (let i = 0; i < items.length; i++) {
    console.log(items[i]);
}
```

```lua
-- Luau ipairs
for i, item in ipairs(items) do
    print(`{i}: {item}`)  -- 1: Sword, 2: Shield...
end

-- Luau numeric
for i = 1, #items do
    print(items[i])
end
```
:::

### Dictionaries: Use `pairs`

```lua
local stats = { health = 100, mana = 50, stamina = 75 }

-- Method 1: pairs (key and value)
for key, value in pairs(stats) do
    print(`{key}: {value}`)
end

```

**Output** (order may vary):
```
health: 100
mana: 50
stamina: 75
```

:::warning Dictionary Order is Not Guaranteed
Unlike arrays, dictionaries don't maintain insertion order. The loop may iterate in any order.
:::

:::note JavaScript Comparison
```javascript
// JavaScript Object.entries
for (const [key, value] of Object.entries(stats)) {
    console.log(`${key}: ${value}`);
}

// JavaScript for...in (keys only)
for (const key in stats) {
    console.log(`${key}: ${stats[key]}`);
}
```

```lua
-- Luau pairs
for key, value in pairs(stats) do
    print(`{key}: {value}`)
end
```
:::

## Table References vs Copies

**Critical concept:** When you assign a table to a variable, you're copying the **reference**, not the data!

```lua
local original = {1, 2, 3}
local reference = original  -- NOT a copy!

reference[1] = 999

print(original[1])   -- 999 (also changed!)
print(reference[1])  -- 999
```

### Creating True Copies

```lua
-- Shallow copy (one level deep)
local original = {1, 2, 3}
local copy = table.clone(original)

copy[1] = 999
print(original[1])  -- 1 (unchanged!)
print(copy[1])      -- 999

-- For nested tables, you need deep copy
local function deepCopy(t)
    if type(t) ~= "table" then return t end
    local copy = {}
    for k, v in pairs(t) do
        copy[k] = deepCopy(v)
    end
    return copy
end
```

:::note JavaScript Comparison
Same behavior in JavaScript:

```javascript
// JavaScript - reference, not copy
const original = [1, 2, 3];
const reference = original;
reference[0] = 999;
console.log(original[0]); // 999

// JavaScript - shallow copy
const copy = [...original];
// or: const copy = Object.assign({}, original);
// or: const copy = JSON.parse(JSON.stringify(original));
```

```lua
-- Luau - reference, not copy
local original = {1, 2, 3}
local reference = original
reference[1] = 999
print(original[1])  -- 999

-- Luau - shallow copy
local copy = table.clone(original)
```
:::

## Common Table Operations

| Operation | Syntax | Description |
|-----------|--------|-------------|
| Length | `#tbl` | Number of sequential elements |
| Insert at end | `table.insert(tbl, value)` | Add to end |
| Insert at position | `table.insert(tbl, idx, value)` | Insert at index |
| Remove from end | `table.remove(tbl)` | Remove and return last |
| Remove at position | `table.remove(tbl, idx)` | Remove and return at index |
| Find value | `table.find(tbl, value)` | Returns index or nil |
| Clear all | `table.clear(tbl)` | Remove all elements |
| Shallow copy | `table.clone(tbl)` | Copy one level |
| Sort | `table.sort(tbl)` | Sort in place |
| Concatenate | `table.concat(tbl, sep)` | Join strings |

```lua
    return true
```

### Exercise 4: Persistent Tables on `self` ⭐⭐

**Goal:** Store tables on `self` for data that persists across frames.

**Why this matters:** Animation state, game entities, and accumulated data need to persist.

**Rive setup:** Create a Node Script named "Exercise4_PersistentTables", attach it to any node, and let it run for a few seconds.

**Expected result:** The Console logs particle counts and positions every second as the system updates.

---

#### Code

```lua
--!strict

export type Exercise4 = {
    particles: {Vector},
    velocities: {Vector},
    frameCount: number,
}

function init(self: Exercise4): boolean
    -- Initialize particle system
    self.particles = {}
    self.velocities = {}
    self.frameCount = 0

    -- Create 5 particles at random positions
    for i = 1, 5 do
        table.insert(self.particles, Vector.xy(
            math.random(50, 350),
            math.random(50, 250)
        ))
        table.insert(self.velocities, Vector.xy(
            math.random(-3, 3),
            math.random(-3, 3)
        ))
    end

    print(`Created {#self.particles} particles`)
    return true
end

function advance(self: Exercise4, elapsed: number): boolean
    self.frameCount += 1

    -- Update particle positions
    for i = 1, #self.particles do
        local pos = self.particles[i]
        local vel = self.velocities[i]

        -- Move particle
        local newX = pos.x + vel.x
        local newY = pos.y + vel.y

        -- Bounce off edges
        if newX < 0 or newX > 400 then
            self.velocities[i] = Vector.xy(-vel.x, vel.y)
            newX = math.max(0, math.min(400, newX))
        end
        if newY < 0 or newY > 300 then
            self.velocities[i] = Vector.xy(vel.x, -vel.y)
            newY = math.max(0, math.min(300, newY))
        end

        self.particles[i] = Vector.xy(newX, newY)
    end

    -- Log every second
    if self.frameCount % 60 == 0 then
        print(`Frame {self.frameCount}: {#self.particles} particles active`)
        for i, p in ipairs(self.particles) do
            print(`  Particle {i}: ({p.x // 1}, {p.y // 1})`)
        end
    end

    return true
end

function draw(self: Exercise4, renderer: Renderer)
end

return function(): Node<Exercise4>
    return {
        init = init,
        advance = advance,
        draw = draw,
        particles = late(),
        velocities = late(),
        frameCount = late(),
    }
end
```

**Goal:** Use common table operations to manipulate data.

**Why this matters:** Sorting, clearing, and cloning tables are core operations when you manage lists of nodes, scores, or dynamic elements in a Rive script.

**Rive setup:** Create a Node Script named "Exercise5_TableUtilities", attach it to any node, and open the Console panel.

```lua
--!strict

export type Exercise5 = {}

function init(self: Exercise5): boolean
    print("=== Table Operations ===")

    -- Sorting
    local scores = {87, 92, 78, 95, 88, 73}
    print(`Original: {table.concat(scores, ", ")}`)

    table.sort(scores)
    print(`Sorted (asc): {table.concat(scores, ", ")}`)

    local index = table.find(scores, 92)

    -- Clearing
    local temp = {1, 2, 3, 4, 5}
    print(`\nBefore clear: {#temp} items`)
    table.clear(temp)
    print(`After clear: {#temp} items`)

    -- Cloning
    local original = {"a", "b", "c"}
    local clone = table.clone(original)
    clone[1] = "X"
    print(`\nOriginal[1]: {original[1]}`)  -- Still "a"
    print(`Clone[1]: {clone[1]}`)          -- "X"

    local words = {"Hello", "Luau", "World"}

    print("\n=== Custom Sorting ===")

        { name = "Bob", score = 200 },
        { name = "Charlie", score = 175 },

    -- Sort by score (highest first)
    table.sort(players, function(a, b)
        return a.score > b.score
    end)

    print("Leaderboard:")
    for i, p in ipairs(players) do
        print(`  {i}. {p.name}: {p.score}`)
    end

    return true
end

end
```

### Exercise 6: Building a Simple Database ⭐⭐⭐

**Goal:** Combine arrays and dictionaries for a practical lookup system.

**Why this matters:** Rive scripts often combine fast lookup tables (by name or ID) with ordered arrays (for waves, lists, or draw order).

**Real-world use:** Mapping node names to data, spawning sequences, config tables keyed by ID.

**Rive setup:** Create a Node Script named "Exercise6_Database", attach it to any node, and open the Console panel.

**Expected result:** The Console prints a lookup, a full list, filtered enemies, and spawn-wave totals.

---

#### Code

```lua
--!strict

export type Exercise6 = {}

-- Enemy data type
type EnemyData = {
    id: string,
    name: string,
    health: number,
    damage: number,
    xpReward: number,
}

function init(self: Exercise6): boolean
    -- Enemy database (dictionary for fast lookup by ID)
    local enemyDB: {[string]: EnemyData} = {
        slime = { id = "slime", name = "Slime", health = 20, damage = 5, xpReward = 10 },
        goblin = { id = "goblin", name = "Goblin", health = 40, damage = 10, xpReward = 25 },
        orc = { id = "orc", name = "Orc", health = 80, damage = 20, xpReward = 50 },
        dragon = { id = "dragon", name = "Dragon", health = 500, damage = 100, xpReward = 500 },
    }

    -- Lookup by ID
    print("=== Lookup by ID ===")
    local enemy = enemyDB["goblin"]
    if enemy then
        print(`Found: {enemy.name}`)
        print(`  Health: {enemy.health}`)
        print(`  Damage: {enemy.damage}`)
        print(`  XP Reward: {enemy.xpReward}`)
    end

    -- List all enemies
    print("\n=== All Enemies ===")
    for id, data in pairs(enemyDB) do
        print(`{id}: {data.name} (HP: {data.health})`)
    end

    -- Find enemies by criteria
    print("\n=== Enemies with HP > 50 ===")
    local strongEnemies: {EnemyData} = {}
    for _, data in pairs(enemyDB) do
        if data.health > 50 then
            table.insert(strongEnemies, data)
        end
    end

    for _, enemy in ipairs(strongEnemies) do
        print(`  {enemy.name}: {enemy.health} HP`)
    end
```

## Common Mistakes

:::danger Top Mistakes
1. **Using index 0** — Arrays start at 1 in Luau!
2. **Forgetting `#` is only for sequential arrays** — It counts until the first nil
3. **Thinking `=` copies tables** — It only copies the reference
4. **Modifying while iterating** — Can cause skipped elements
5. **Expecting dictionary order** — Dictionaries don't guarantee order
:::

## Quick Reference

```lua
-- Arrays
local arr = {1, 2, 3}
arr[1]                    -- First element
#arr                      -- Length
table.insert(arr, v)      -- Add to end
table.insert(arr, i, v)   -- Add at index
table.remove(arr)         -- Remove last
table.remove(arr, i)      -- Remove at index
table.find(arr, v)        -- Find index

-- Dictionaries
local dict = { a = 1, b = 2 }
dict.a                    -- Get by key
dict["a"]                 -- Same thing
dict.c = 3                -- Add/modify
dict.a = nil              -- Remove

-- Iteration
for i, v in ipairs(arr) do ... end   -- Array
for k, v in pairs(dict) do ... end   -- Dictionary
for k, v in pairs(tbl) do ... end

-- Utilities
table.sort(arr)           -- Sort ascending
table.sort(arr, fn)       -- Sort with comparator
table.clone(tbl)          -- Shallow copy
table.clear(tbl)          -- Remove all
table.concat(arr, sep)    -- Join strings
```
