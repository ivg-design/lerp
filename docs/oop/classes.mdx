# Lesson 3.2: Building Classes

## Learning Objectives
- Create proper class constructors using metatables
- Type your classes correctly with `--!strict`
- Use the double-cast pattern for type safety
- Implement methods with proper `self` handling
- Build reusable simulation and drawing classes

---

## AE/JS Syntax Comparison

| Concept | After Effects | JavaScript/TypeScript | Luau (Rive) |
|---------|--------------|----------------------|-------------|
| Class definition | N/A | `class MyClass {}` | `local MyClass = {}; MyClass.__index = MyClass` |
| Constructor | N/A | `constructor(x) { this.x = x; }` | `function MyClass.new(x) ... end` |
| Type annotation | N/A | `class MyClass { x: number; }` | `export type MyClass = { x: number }` |
| Create instance | N/A | `new MyClass(10)` | `MyClass.new(10)` |
| Method definition | N/A | `method() { ... }` | `function MyClass:method() ... end` |
| Access `this`/`self` | `this` | `this.x` | `self.x` |

:::danger Critical Difference: The Double-Cast Pattern
In Luau's strict mode, you can't directly return a table with a metatable as a typed object.

**TypeScript** infers constructor return types automatically.
**Luau** requires explicit type assertions: `(self :: any) :: MyType`.

This looks strange but is **required** for type safety. Think of it as telling Luau: "Trust me, this table is the shape I defined."
:::

---

## Rive Context

Rive does not have built-in classes, so you build your own with metatables. In real Rive projects, **class-like objects belong in Util scripts** and are **instantiated by Node scripts**.

Use classes when you need:
- Reusable simulation objects (springs, timers, particles)
- Consistent drawing logic across multiple elements
- Clean separation between math/logic and rendering

---

## The Strict Class Pattern (Rive-Friendly)

In Lesson 3.1, we learned how `__index` enables shared behavior. Now we'll formalize this into a reusable class pattern that:

1. Works with `--!strict` type checking
2. Has a clear constructor (`new()`)
3. Defines a proper type for instances
4. Supports methods with the colon syntax

```lua
--!strict

local MyClass = {}
MyClass.__index = MyClass

export type MyClass = {
    value: number,
    step: (MyClass, number) -> (),
}

function MyClass.new(value: number): MyClass
    local self = setmetatable({}, MyClass)
    self.value = value
    return (self :: any) :: MyClass
end

function MyClass:step(dt: number)
    self.value += dt
end

return MyClass
```

**Key detail:** In `--!strict`, the double cast `(self :: any) :: MyClass` is required so Luau accepts the metatable instance.

## Exercise 1: Build a Spring Class in a Util Script

**Goal**: Create a reusable physics spring that can be imported into any Node script.

**Why This Matters**: Springs are fundamental to smooth animations. Rather than hardcoding spring math everywhere, you create a class once and reuse it. This is the professional approach—write once, use everywhere.

**Real-World Use**: UI animations use springs constantly: bouncy buttons, elastic menus, smooth scroll deceleration. A Spring class lets you animate any value with physics instead of linear interpolation.

**Step-by-Step Setup**:
1. In Rive, create a new **Util Script** named "Spring"
2. Copy the code below
3. This becomes your reusable spring library

**File: `Spring.luau` (Util Script)**

```lua
--!strict

local Spring = {}
Spring.__index = Spring

export type Spring = {
    position: number,
    velocity: number,
    target: number,
    stiffness: number,
    damping: number,
    step: (Spring, number) -> (),
    snap: (Spring, number) -> (),
}

function Spring.new(position: number, stiffness: number, damping: number): Spring
    local self = setmetatable({}, Spring)
    self.position = position
    self.velocity = 0
    self.target = position
    self.stiffness = stiffness
    self.damping = damping
    return (self :: any) :: Spring
end

function Spring:step(dt: number)
    local displacement = self.target - self.position
    self.velocity += displacement * self.stiffness * dt
    self.velocity *= math.max(0, 1 - self.damping * dt)
    self.position += self.velocity * dt
end

function Spring:snap(value: number)
    self.position = value
    self.target = value
    self.velocity = 0
end

return Spring
```

**JavaScript/TypeScript Equivalent**:
```typescript
// TypeScript class version
class Spring {
    position: number;
    velocity: number = 0;
    target: number;
    stiffness: number;
    damping: number;

    constructor(position: number, stiffness: number, damping: number) {
        this.position = position;
        this.target = position;
        this.stiffness = stiffness;
        this.damping = damping;
    }

    step(dt: number): void {
        const displacement = this.target - this.position;
        this.velocity += displacement * this.stiffness * dt;
        this.velocity *= Math.max(0, 1 - this.damping * dt);
        this.position += this.velocity * dt;
    }

    snap(value: number): void {
        this.position = value;
        this.target = value;
        this.velocity = 0;
    }
}
```

## Exercise 2: Use the Class in a Node Script

**Goal**: Animate a square using the Spring class and a script input.

**Why This Matters**: This shows the Rive workflow: Util scripts contain reusable logic, Node scripts consume them. Changing the Spring class updates ALL animations that use it.

**Real-World Use**: You might have a Spring for position, one for scale, one for rotation—all using the same class. Adjusting `stiffness` and `damping` lets you fine-tune the feel without rewriting physics.

**Step-by-Step Setup**:
1. Create a Node Script for Exercise 2
2. Attach it to a Node in Rive
3. Adjust the `target` input in the sidebar
4. Watch the square spring to the new position!

```lua
--!strict

local SpringLib = require("Spring")

export type SpringDemo = {
    target: Input<number>,
    spring: SpringLib.Spring,
    path: Path,
    paint: Paint,
}

function init(self: SpringDemo): boolean
    self.path = Path.new()
    self.path:moveTo(Vector.xy(-12, -12))
    self.path:lineTo(Vector.xy(12, -12))
    self.path:lineTo(Vector.xy(12, 12))
    self.path:lineTo(Vector.xy(-12, 12))
    self.path:close()

    self.paint = Paint.with({
        style = "fill",
        color = Color.rgb(255, 200, 0),
    })

    return true
end

function update(self: SpringDemo)
    self.spring.target = self.target.value
end

function advance(self: SpringDemo, seconds: number): boolean
    self.spring:step(seconds)
    return true
end

function draw(self: SpringDemo, renderer: Renderer)
    renderer:save()
    renderer:transform(Mat2D.withTranslation(self.spring.position, 0))
    renderer:drawPath(self.path, self.paint)
    renderer:restore()
end

return function(): Node<SpringDemo>
    return {
        init = init,
        update = update,
        advance = advance,
        draw = draw,
        target = 160,
        spring = SpringLib.new(0, 30, 6),
        path = Path.new(),
        paint = Paint.new(),
    }
end
```

**JavaScript Equivalent** (conceptually):
```javascript
// In a web app, you'd import the Spring class
import { Spring } from './Spring';

class SpringDemo {
    target = 160;
    spring = new Spring(0, 30, 6);

    update() {
        this.spring.target = this.target;
    }

    advance(seconds) {
        this.spring.step(seconds);
    }

    draw(ctx) {
        ctx.save();
        ctx.translate(this.spring.position, 0);
        // draw square...
        ctx.restore();
    }
}
```

**Rive workflow:**
1. Create a Util Script named `Spring` and paste Exercise 1.
2. Create a Node Script for Exercise 2 and attach it to a Node.
3. Adjust the `target` input in the sidebar and observe the spring motion.

**Note:** The `Spring` type is exported by the Util script and can be used directly in this Node script.

## Exercise 3: Complete Drawable Sprite Class

**Goal**: Build a sprite class that handles its own path, paint, and drawing.

**Why This Matters**: In real projects, you'll have many drawable objects (characters, bullets, particles). Each needs position, appearance, and a draw method. A Sprite class bundles all of this.

**Real-World Use**: A game might have 50 sprites on screen. Each sprite manages its own state, and you just loop through calling `sprite:draw(renderer)`. Clean, organized, efficient.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Attach to a node
4. You'll see two colored rectangles bouncing horizontally

```lua
--!strict

local Sprite = {}
Sprite.__index = Sprite

export type SpriteType = {
    x: number,
    y: number,
    width: number,
    height: number,
    color: Color,
    path: Path,
    paint: Paint,
}

function Sprite.new(x: number, y: number, width: number, height: number, color: Color): SpriteType
    local self = setmetatable({}, Sprite)
    self.x = x
    self.y = y
    self.width = width
    self.height = height
    self.color = color
    self.path = Path.new()
    self.paint = Paint.new()
    self.paint.style = "fill"
    self.paint.color = color
    Sprite._rebuildPath(self)
    return (self :: any) :: SpriteType
end

function Sprite:_rebuildPath()
    local hw = self.width / 2
    local hh = self.height / 2
    self.path:reset()
    self.path:moveTo(Vector.xy(-hw, -hh))
    self.path:lineTo(Vector.xy(hw, -hh))
    self.path:lineTo(Vector.xy(hw, hh))
    self.path:lineTo(Vector.xy(-hw, hh))
    self.path:close()
end

function Sprite:setColor(color: Color)
    self.color = color
    self.paint.color = color
end

function Sprite:draw(renderer: Renderer)
    renderer:save()
    renderer:transform(Mat2D.withTranslation(self.x, self.y))
    renderer:drawPath(self.path, self.paint)
    renderer:restore()
end

export type SpriteDemo = {
    sprites: {SpriteType},
    elapsed: number,
}

function init(self: SpriteDemo): boolean
    self.sprites = {
        Sprite.new(-60, 0, 50, 50, Color.rgb(255, 0, 0)),
        Sprite.new(60, 0, 30, 60, Color.rgb(0, 255, 0)),
    }
    self.elapsed = 0
    return true
end

function advance(self: SpriteDemo, seconds: number): boolean
    self.elapsed += seconds
    for i, sprite in self.sprites do
        sprite.x += math.sin(self.elapsed + i) * 50 * seconds
    end
    return true
end

function draw(self: SpriteDemo, renderer: Renderer)
    for _, sprite in self.sprites do
        sprite:draw(renderer)
    end
end

return function(): Node<SpriteDemo>
    return {
        init = init,
        advance = advance,
        draw = draw,
        sprites = {},
        elapsed = 0,
    }
end
```

**TypeScript Equivalent**:
```typescript
class Sprite {
    x: number;
    y: number;
    width: number;
    height: number;
    color: string;

    constructor(x: number, y: number, w: number, h: number, color: string) {
        this.x = x;
        this.y = y;
        this.width = w;
        this.height = h;
        this.color = color;
    }

    setColor(color: string): void {
        this.color = color;
    }

    draw(ctx: CanvasRenderingContext2D): void {
        ctx.save();
        ctx.translate(this.x, this.y);
        ctx.fillStyle = this.color;
        ctx.fillRect(-this.width/2, -this.height/2, this.width, this.height);
        ctx.restore();
    }
}
```

## Exercise 4: The Double Cast Pattern Explained

**Goal**: Understand why `(self :: any) :: MyType` is necessary in strict mode.

**Why This Matters**: Without this pattern, your code won't compile in strict mode. Understanding WHY it's needed helps you write it confidently rather than just copying it blindly.

**Real-World Use**: Every class you create in Rive needs this pattern. Once you understand it, you'll write it automatically.

**Step-by-Step Explanation**:

```lua
--!strict

local BadClass = {}
BadClass.__index = BadClass

type BadType = { name: string }

function BadClass.new(): BadType
    local self = setmetatable({}, BadClass)
    self.name = "test"
    -- return self  -- Error! Type is not compatible
    return (self :: any) :: BadType  -- This works
end

-- Why?
-- 1. setmetatable({}, BadClass) returns a table with metatable
-- 2. Luau sees it as a generic table, not BadType
-- 3. :: any tells Luau "trust me, forget the current type"
-- 4. :: BadType tells Luau "treat this as BadType"
```

**TypeScript Comparison**:
```typescript
// TypeScript handles this automatically
class MyClass {
    name: string;
    constructor() {
        this.name = "test";
        // No cast needed - TypeScript infers the type
    }
}

// If you needed a similar pattern in TypeScript:
function createBadType(): BadType {
    const self = { name: "test" };
    return self as unknown as BadType;  // Similar to (self :: any) :: BadType
}
```

**Key Insight**: The double cast doesn't change runtime behavior - it only satisfies the type checker. Your code runs exactly the same with or without it.

## Exercise 5: Factory Functions (Multiple Constructors)

**Goal**: Create multiple constructor variants for flexible object creation.

**Why This Matters**: Sometimes you want to create objects in different ways: from coordinates, from corners, centered, as squares. Factory functions let you provide all these options without confusing the API.

**Real-World Use**: A Rectangle might be created `centered(x, y, w, h)`, `fromCorners(x1, y1, x2, y2)`, or just `square(x, y, size)`. Same class, multiple convenient ways to construct it.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Watch the console to see different creation patterns

```lua
--!strict

local Rectangle = {}
Rectangle.__index = Rectangle

export type RectangleType = {
    x: number,
    y: number,
    width: number,
    height: number,
}

function Rectangle.new(x: number, y: number, width: number, height: number): RectangleType
    local self = setmetatable({}, Rectangle)
    self.x = x
    self.y = y
    self.width = width
    self.height = height
    return (self :: any) :: RectangleType
end

function Rectangle.fromCorners(x1: number, y1: number, x2: number, y2: number): RectangleType
    return Rectangle.new(math.min(x1, x2), math.min(y1, y2), math.abs(x2 - x1), math.abs(y2 - y1))
end

function Rectangle.centered(centerX: number, centerY: number, width: number, height: number): RectangleType
    return Rectangle.new(centerX - width / 2, centerY - height / 2, width, height)
end

function Rectangle.square(x: number, y: number, size: number): RectangleType
    return Rectangle.new(x, y, size, size)
end

function Rectangle:area(): number
    return self.width * self.height
end

function Rectangle:contains(px: number, py: number): boolean
    return px >= self.x and px <= self.x + self.width
       and py >= self.y and py <= self.y + self.height
end

Rectangle.__tostring = function(r: RectangleType): string
    return `Rect({r.x}, {r.y}, {r.width}x{r.height})`
end

export type FactoryDemo = {}

function init(self: FactoryDemo): boolean
    local r1 = Rectangle.new(0, 0, 100, 50)
    local r2 = Rectangle.fromCorners(-50, -25, 50, 25)
    local r3 = Rectangle.centered(0, 0, 80, 40)
    local r4 = Rectangle.square(-20, -20, 40)

    print(`r1: {r1}  area: {r1:area()}`)
    print(`r2: {r2}  area: {r2:area()}`)
    print(`r3: {r3}  area: {r3:area()}`)
    print(`r4: {r4}  area: {r4:area()}`)

    print(`\nr1 contains (10, 10)? {r1:contains(10, 10)}`)
    print(`r1 contains (200, 200)? {r1:contains(200, 200)}`)

    return true
end

function draw(self: FactoryDemo, renderer: Renderer)
end

return function(): Node<FactoryDemo>
    return {
        init = init,
        draw = draw,
    }
end
```

**TypeScript Equivalent**:
```typescript
class Rectangle {
    x: number;
    y: number;
    width: number;
    height: number;

    constructor(x: number, y: number, width: number, height: number) {
        this.x = x;
        this.y = y;
        this.width = width;
        this.height = height;
    }

    // Static factory methods
    static fromCorners(x1: number, y1: number, x2: number, y2: number): Rectangle {
        return new Rectangle(Math.min(x1, x2), Math.min(y1, y2), Math.abs(x2-x1), Math.abs(y2-y1));
    }

    static centered(cx: number, cy: number, w: number, h: number): Rectangle {
        return new Rectangle(cx - w/2, cy - h/2, w, h);
    }

    static square(x: number, y: number, size: number): Rectangle {
        return new Rectangle(x, y, size, size);
    }

    area(): number {
        return this.width * this.height;
    }

    contains(px: number, py: number): boolean {
        return px >= this.x && px <= this.x + this.width
            && py >= this.y && py <= this.y + this.height;
    }
}
```

## Exercise 6: When to Use Classes vs. Plain Tables

**Goal**: Understand when classes add value and when simple tables are better.

**Why This Matters**: Over-engineering with classes when you don't need them makes code harder to understand. Under-engineering with tables when you need classes leads to duplicated code. Knowing when to use each is professional judgment.

**Use classes for:**
- Objects with behavior (`step`, `draw`, `reset`)
- Complex state updates across frames
- Multiple instances that share the same logic

**Use plain tables for:**
- Static configuration (`style`, `palette`, `layout`)
- One-off data passed into a function

**Example - When to use classes**:
```lua
-- Multiple particles, all need to update and draw
-- Class is perfect here
local Particle = {}
Particle.__index = Particle

function Particle.new(x, y)
    local self = setmetatable({}, Particle)
    self.x = x
    self.y = y
    return self
end

function Particle:update(dt)
    self.y += self.vy * dt
end

function Particle:draw(renderer)
    -- draw particle
end

-- Create 100 particles, all share methods
local particles = {}
for i = 1, 100 do
    particles[i] = Particle.new(math.random()*200, 0)
end
```

**Example - When to use plain tables**:
```lua
-- Configuration - just data, no behavior
local config = {
    backgroundColor = Color.rgb(20, 20, 30),
    lineThickness = 2,
    animationSpeed = 1.5,
}

-- Pass to functions, no methods needed
local paint = Paint.with({
    style = "fill",
    color = config.backgroundColor,
})
```

In Rive, this keeps your Node scripts lean and your Util scripts reusable.

## Common Mistakes

### 1. Forgetting `__index` Setup

```lua
-- WRONG: No __index, methods won't be found
local MyClass = {}

function MyClass.new()
    return setmetatable({}, MyClass)  -- Missing __index!
end

function MyClass:greet()
    print("Hello")
end

local obj = MyClass.new()
obj:greet()  -- ERROR: attempt to call nil value

-- CORRECT: Set __index
local MyClass = {}
MyClass.__index = MyClass  -- Add this line!
```

### 2. Putting Methods in the Type Definition

```lua
-- WRONG: Type includes method signatures unnecessarily
export type MyClass = {
    value: number,
    increment: (MyClass) -> (),  -- Optional, but not required
}

-- The type describes the shape. Methods are found via __index.
-- You CAN include method signatures for documentation, but
-- the actual functions live on the class table.
```

### 3. Using Dot Instead of Colon for Method Calls

```lua
-- WRONG: Dot doesn't pass self
obj.method()  -- self is nil!

-- CORRECT: Colon passes obj as self
obj:method()  -- self is obj
```

### 4. Missing Double Cast in Strict Mode

```lua
-- WRONG: Strict mode rejects this
function MyClass.new(): MyClass
    local self = setmetatable({}, MyClass)
    return self  -- Type error!
end

-- CORRECT: Double cast
function MyClass.new(): MyClass
    local self = setmetatable({}, MyClass)
    return (self :: any) :: MyClass
end
```
