# Prototype-Based OOP

## Learning Objectives
- Understand the difference between class-based and prototype-based OOP
- Learn how Lua/Luau uses prototypes instead of classes
- See how Rive leverages metatables for prototype chains
- Build reusable object patterns for Rive Node Scripts

---

## AE/JS Syntax Comparison

| Concept | After Effects | JavaScript | Luau (Rive) |
|---------|--------------|------------|-------------|
| Create class | N/A | `class Dog {}` | `local Dog = {}` + metatable |
| Inheritance | N/A | `class Poodle extends Dog {}` | `setmetatable(Poodle, {__index = Dog})` |
| Create instance | N/A | `new Dog()` | `setmetatable({}, {__index = Dog})` |
| Method lookup | N/A | Automatic via prototype chain | Via `__index` metamethod |
| `this`/`self` | `this` | `this` | `self` (explicit or via `:`) |

:::danger Critical Difference: No Built-in Classes
**After Effects** expressions don't have OOP at all—they're purely functional.
**JavaScript** has the `class` keyword that hides prototype mechanics.
**Luau has NO classes**—just tables that delegate to other tables via `__index`.

This isn't a limitation—it's **more flexible**. You can modify "classes" at runtime, mix and match behaviors, and create inheritance chains without any keywords.
:::

---

## Rive Context

Rive scripts don't have classes. Instead, you use **prototype-based patterns** where objects inherit behavior directly from other objects (prototypes) via metatables. This is perfect for Rive because:

- **Lightweight**: No class boilerplate, just tables and metatables
- **Flexible**: Prototypes can be modified at runtime
- **Memory efficient**: Methods are shared, not duplicated per instance

In Rive, you typically:
1. Define a prototype table with shared methods
2. Create instances that delegate to the prototype via `__index`
3. Use these instances in `advance` and `draw` for reusable behavior

---

## Class-Based vs Prototype-Based

Most popular languages (Java, C#, Python) use **class-based** OOP:
- Classes are blueprints
- Objects are instances of classes
- Inheritance happens between classes

Lua uses **prototype-based** OOP:
- No classes - just objects (tables)
- Objects inherit directly from other objects
- Inheritance happens via the `__index` metamethod

**Analogy**: Class-based is like following a recipe to bake a cake. Prototype-based is like saying "make something like this other cake" and allowing modifications.

## Exercise 1: Understanding the Prototype Chain

**Goal**: See how method lookup works through the `__index` chain.

**Why This Matters**: Every object you create in Rive finds its methods through this chain. Understanding it prevents "nil" errors and helps you structure code properly.

**Real-World Use**: In a game, all enemies might share movement methods while each type (zombie, robot, alien) adds specific behaviors. The prototype chain lets enemies inherit common code automatically.

**Step-by-Step Setup**:
1. Create a new Node Script in Rive
2. Copy the code below
3. Attach to any node
4. Check the console for output explaining the lookup process

**Rive setup:** Attach the script to any node and open the Console panel.

**Expected result:** The Console logs which table provides each method in the chain.

```lua
--!strict

-- Prototype table (the "parent")
local Animal = {
    name = "Unknown",
    sound = "...",
}

-- Instance table (the "child")
local dog = setmetatable({
    name = "Rex",
}, { __index = Animal })

-- dog.name -> found in dog ("Rex")
-- dog.sound -> not in dog, found in Animal ("...")
```

**JavaScript Equivalent**:
```javascript
// JavaScript has prototypes too, but hides them behind 'class'
class Animal {
    constructor() {
        this.name = "Unknown";
        this.sound = "...";
    }
}

// Under the hood, JavaScript does similar delegation
const dog = Object.create(Animal.prototype);
dog.name = "Rex";
// dog.sound would come from the prototype chain
```

**Key Insight**: When you access `dog.sound`, Lua:
1. Checks `dog` table → not found
2. Checks metatable's `__index` → it's `Animal`
3. Checks `Animal` table → found! Returns `"..."`

## Exercise 2: Complete Node Script - Basic Prototype Pattern

**Goal**: Create a working shape system using prototypes.

**Why This Matters**: This is THE pattern you'll use for every custom object in Rive—particles, UI elements, game characters, animation helpers. Master this and you can build anything.

**Real-World Use**: A data visualization might have dozens of chart elements (bars, lines, points). Each shares drawing logic but has different data. Prototypes let you write the draw method once.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the complete code below
3. Attach to a node
4. You'll see a red circle and blue square animating

```lua
--!strict

-- The prototype table holds shared behavior
local ShapeProto = {}
ShapeProto.__index = ShapeProto

export type Shape = {
    x: number,
    y: number,
    color: Color,
    path: Path,
    paint: Paint,
    moveTo: (Shape, number, number) -> (),
    draw: (Shape, Renderer) -> (),
}

-- Factory function creates instances
function ShapeProto.new(x: number, y: number, color: Color): Shape
    local self = setmetatable({}, ShapeProto)
    self.x = x
    self.y = y
    self.color = color
    self.path = Path.new()
    self.paint = Paint.with({ style = "fill", color = color })
    return (self :: any) :: Shape
end

-- Methods are defined on the prototype
function ShapeProto:moveTo(newX: number, newY: number)
    self.x = newX
    self.y = newY
end

function ShapeProto:draw(renderer: Renderer)
    renderer:save()
    renderer:transform(Mat2D.withTranslation(self.x, self.y))
    renderer:drawPath(self.path, self.paint)
    renderer:restore()
end

-- Node script using the prototype
export type PrototypeDemo = {
    shapes: {Shape},
}

function init(self: PrototypeDemo): boolean
    -- Create instances from the prototype
    local circle = ShapeProto.new(-80, 0, Color.rgb(255, 100, 100))
    circle.path:addEllipse(Vector.xy(0, 0), 30, 30)

    local square = ShapeProto.new(80, 0, Color.rgb(100, 100, 255))
    square.path:moveTo(Vector.xy(-25, -25))
    square.path:lineTo(Vector.xy(25, -25))
    square.path:lineTo(Vector.xy(25, 25))
    square.path:lineTo(Vector.xy(-25, 25))
    square.path:close()

    self.shapes = { circle, square }
    return true
end

function advance(self: PrototypeDemo, seconds: number): boolean
    -- Both shapes share the same moveTo method via prototype
    for i, shape in ipairs(self.shapes) do
        shape:moveTo(shape.x + math.sin(os.clock() + i) * 30 * seconds, shape.y)
    end
    return true
end

function draw(self: PrototypeDemo, renderer: Renderer)
    for _, shape in ipairs(self.shapes) do
        shape:draw(renderer)  -- Shared draw method
    end
end

return function(): Node<PrototypeDemo>
    return {
        init = init,
        advance = advance,
        draw = draw,
        shapes = {},
    }
end
```

**JavaScript/TypeScript Equivalent**:
```typescript
// TypeScript version of the same pattern
interface Shape {
    x: number;
    y: number;
    color: string;
    moveTo(newX: number, newY: number): void;
    draw(ctx: CanvasRenderingContext2D): void;
}

class ShapeProto implements Shape {
    x: number;
    y: number;
    color: string;

    constructor(x: number, y: number, color: string) {
        this.x = x;
        this.y = y;
        this.color = color;
    }

    moveTo(newX: number, newY: number): void {
        this.x = newX;
        this.y = newY;
    }

    draw(ctx: CanvasRenderingContext2D): void {
        ctx.save();
        ctx.translate(this.x, this.y);
        // draw shape...
        ctx.restore();
    }
}
```

**Key insight**: Both `circle` and `square` use the same `moveTo` and `draw` functions stored in `ShapeProto`. No duplication.

## How Prototypes Save Memory

**Without prototypes (wasteful)**:
```lua
-- Each object gets its own copy of methods
local obj1 = {
    value = 10,
    increment = function(self) self.value += 1 end,  -- Copy 1
}
local obj2 = {
    value = 20,
    increment = function(self) self.value += 1 end,  -- Copy 2 (wasteful!)
}
-- 2 objects = 2 function copies in memory
```

**With prototypes (efficient)**:
```lua
-- Methods live in one place
local Proto = {}
Proto.__index = Proto
function Proto:increment() self.value += 1 end  -- Single copy

local obj1 = setmetatable({ value = 10 }, { __index = Proto })
local obj2 = setmetatable({ value = 20 }, { __index = Proto })
-- 100 objects = still just 1 function copy in memory
```

In Rive, where you might have dozens of animated elements, this difference matters.

## Exercise 3: Prototype Chain with Inheritance

**Goal**: Create a multi-level inheritance chain where specialized objects extend base objects.

**Why This Matters**: Complex applications need hierarchies. A game character might extend Entity which extends GameObject. Understanding prototype chains lets you build these cleanly.

**Real-World Use**: In a particle system: `Particle` extends `MovingEntity` extends `Entity`. Each level adds functionality without duplicating code.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Watch the console to see inheritance in action
4. Notice how `moving:deactivate()` finds the method in the parent

```lua
--!strict

-- Base prototype
local Entity = {}
Entity.__index = Entity

export type EntityType = {
    x: number,
    y: number,
    active: boolean,
}

function Entity.new(x: number, y: number): EntityType
    local self = setmetatable({}, Entity)
    self.x = x
    self.y = y
    self.active = true
    return (self :: any) :: EntityType
end

function Entity:describe(): string
    return `Entity at ({self.x}, {self.y})`
end

function Entity:deactivate()
    self.active = false
end

-- Specialized prototype that extends Entity
local MovingEntity = setmetatable({}, { __index = Entity })
MovingEntity.__index = MovingEntity

export type MovingEntityType = EntityType & {
    vx: number,
    vy: number,
}

function MovingEntity.new(x: number, y: number, vx: number, vy: number): MovingEntityType
    local self = setmetatable({}, MovingEntity)
    self.x = x
    self.y = y
    self.vx = vx
    self.vy = vy
    self.active = true
    return (self :: any) :: MovingEntityType
end

function MovingEntity:update(dt: number)
    if self.active then
        self.x += self.vx * dt
        self.y += self.vy * dt
    end
end

-- Override describe but can still access parent behavior
function MovingEntity:describe(): string
    return `MovingEntity at ({self.x}, {self.y}) moving ({self.vx}, {self.vy})`
end

export type ChainDemo = {
    entities: {EntityType | MovingEntityType},
}

function init(self: ChainDemo): boolean
    local static = Entity.new(0, 50)
    local moving = MovingEntity.new(0, -50, 20, 0)

    -- Both have describe() - but different implementations
    print(static:describe())   -- "Entity at (0, 50)"
    print(moving:describe())   -- "MovingEntity at (0, -50) moving (20, 0)"

    -- Both have deactivate() - moving inherits it from Entity
    moving:deactivate()
    print(`Moving active: {moving.active}`)  -- false

    self.entities = { static, moving }
    return true
end

function draw(self: ChainDemo, renderer: Renderer)
end

return function(): Node<ChainDemo>
    return {
        init = init,
        draw = draw,
        entities = {},
    }
end
```

**JavaScript Equivalent**:
```javascript
// JavaScript class inheritance (hides prototype mechanics)
class Entity {
    constructor(x, y) {
        this.x = x;
        this.y = y;
        this.active = true;
    }

    describe() {
        return `Entity at (${this.x}, ${this.y})`;
    }

    deactivate() {
        this.active = false;
    }
}

class MovingEntity extends Entity {
    constructor(x, y, vx, vy) {
        super(x, y);  // Luau: done manually
        this.vx = vx;
        this.vy = vy;
    }

    update(dt) {
        if (this.active) {
            this.x += this.vx * dt;
            this.y += this.vy * dt;
        }
    }

    // Override
    describe() {
        return `MovingEntity at (${this.x}, ${this.y})`;
    }
}
```

**Prototype chain lookup for `moving:deactivate()`**:
1. Look in `moving` table - not found
2. Check metatable `__index` - it's `MovingEntity`
3. Look in `MovingEntity` - not found
4. Check `MovingEntity`'s metatable `__index` - it's `Entity`
5. Look in `Entity` - found `deactivate`!

## Exercise 4: Dynamic Prototypes (Runtime Modification)

**Goal**: Modify prototype behavior at runtime to affect all instances.

**Why This Matters**: Unlike classes in Java/C#, prototypes can change. This enables features like power-ups that modify all enemies, or theme switches that update all UI elements.

**Real-World Use**: In a game, activating a "slow motion" power-up could modify the movement prototype to slow down ALL moving objects at once—without looping through each one.

**Step-by-Step Setup**:
1. Create a new Node Script
2. Copy the code below
3. Watch the circles—after 2 seconds, all radii double because we modified the prototype!

```lua
--!strict

local Drawable = {}
Drawable.__index = Drawable

export type DrawableType = {
    x: number,
    y: number,
    size: number,
}

function Drawable.new(x: number, y: number, size: number): DrawableType
    local self = setmetatable({}, Drawable)
    self.x = x
    self.y = y
    self.size = size
    return (self :: any) :: DrawableType
end

-- Initial shared method
function Drawable:getRadius(): number
    return self.size / 2
end

export type DynamicProtoDemo = {
    items: {DrawableType},
    path: Path,
    paint: Paint,
    modified: boolean,
}

function init(self: DynamicProtoDemo): boolean
    self.items = {
        Drawable.new(-60, 0, 40),
        Drawable.new(0, 0, 60),
        Drawable.new(60, 0, 30),
    }

    self.path = Path.new()
    self.paint = Paint.with({ style = "fill", color = Color.rgb(100, 200, 255) })
    self.modified = false

    -- All items use the same getRadius method
    for _, item in ipairs(self.items) do
        print(`Radius: {item:getRadius()}`)
    end

    return true
end

function advance(self: DynamicProtoDemo, seconds: number): boolean
    -- After 2 seconds, modify the prototype
    if os.clock() > 2 and not self.modified then
        -- Change behavior for ALL instances at once
        Drawable.getRadius = function(s: DrawableType): number
            return s.size  -- Now returns full size instead of half
        end
        self.modified = true
        print("Prototype modified! All radii doubled.")
    end
    return true
end

function draw(self: DynamicProtoDemo, renderer: Renderer)
    for _, item in ipairs(self.items) do
        self.path:reset()
        self.path:addEllipse(Vector.xy(item.x, item.y), item:getRadius(), item:getRadius())
        renderer:drawPath(self.path, self.paint)
    end
end

return function(): Node<DynamicProtoDemo>
    return {
        init = init,
        advance = advance,
        draw = draw,
        items = {},
        path = Path.new(),
        paint = Paint.new(),
        modified = false,
    }
end
```

**JavaScript Equivalent**:
```javascript
// JavaScript can also modify prototypes at runtime
class Drawable {
    constructor(x, y, size) {
        this.x = x;
        this.y = y;
        this.size = size;
    }

    getRadius() {
        return this.size / 2;
    }
}

// Later, modify the prototype:
Drawable.prototype.getRadius = function() {
    return this.size;  // All instances now see this change
};
```

**Rive use case**: You could modify prototype behavior based on game state - e.g., all enemies become faster when a power-up expires.

## Comparing OOP Approaches

| Feature | Class-Based (Java/C#) | Prototype-Based (Lua) |
|---------|----------------------|----------------------|
| Blueprint | Class definition | Prototype object |
| Instance creation | `new ClassName()` | `setmetatable({}, proto)` |
| Method lookup | Class hierarchy | `__index` chain |
| Runtime modification | Limited | Fully dynamic |
| Memory model | Methods on class | Methods on prototype |
| Best for | Large teams, strict contracts | Flexible, lightweight systems |

---

## When to Use Prototypes in Rive

**Use prototypes when:**
- Multiple objects share the same behavior (particles, UI elements)
- You need runtime flexibility (theme switching, behavior modes)
- Memory efficiency matters (many instances)

**Use plain tables when:**
- Objects are one-offs (main game state)
- No shared behavior needed (configuration)
- Simplicity is more important than structure

## Common Mistakes

### 1. Forgetting to Set Up the `__index` Chain

```lua
-- WRONG: No inheritance connection
local Parent = { greet = function() print("Hello") end }
local Child = {}  -- Child can't access Parent.greet!

-- CORRECT: Link via metatable
local Child = setmetatable({}, { __index = Parent })
-- Now Child:greet() works
```

### 2. Confusing Prototype Table with Instance Table

```lua
-- WRONG: Putting instance data on the prototype
local Proto = { x = 0 }  -- All instances share this x!
Proto.__index = Proto

local a = setmetatable({}, Proto)
local b = setmetatable({}, Proto)
a.x = 10
print(b.x)  -- Still 0! Because b.x doesn't exist, it reads Proto.x

-- CORRECT: Each instance gets its own data
function Proto.new()
    local self = setmetatable({}, Proto)
    self.x = 0  -- Instance's own x
    return self
end
```

### 3. Expecting Class Syntax

```lua
-- WRONG: Lua has no 'class' keyword
class MyClass {  -- Syntax error!
    constructor() {}
}

-- CORRECT: Use tables and metatables
local MyClass = {}
MyClass.__index = MyClass

function MyClass.new()
    return setmetatable({}, MyClass)
end
```

### 4. Forgetting to Call Parent Constructor

```lua
-- WRONG: Child doesn't initialize parent properties
local Parent = {}
Parent.__index = Parent

function Parent.new()
    local self = setmetatable({}, Parent)
    self.name = "Unknown"
    return self
end

local Child = setmetatable({}, { __index = Parent })
Child.__index = Child

function Child.new()
    local self = setmetatable({}, Child)
    -- self.name is nil! We forgot to initialize it
    return self
end

-- CORRECT: Initialize parent properties manually
function Child.new()
    local self = setmetatable({}, Child)
    self.name = "Unknown"  -- Copy from parent pattern
    -- Or call parent constructor logic
    return self
end
```
