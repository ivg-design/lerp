Lesson 3.1: Metatables & __index

Learning Objectives​

  • Understand what metatables are and how they work
  • Use setmetatable() to attach behavior to tables
  • Master the __index metamethod for property lookup
  • Implement prototype patterns for reusable behavior

Rive Context​

Rive scripts are not classes. When you need reusable behavior (drawing helpers, physics helpers, layout logic), you build prototype tables with metatables. This lets Node scripts share methods and data structures without leaving the Rive scripting environment.

Typical Rive pattern:

  • Put reusable logic in a Util script or a local prototype table
  • Create instances with setmetatable
  • Call shared methods from advance and draw

Why Metatables?​

Luau doesn't have built-in classes like Java or C#. Instead, it uses metatables - special tables that define custom behavior for other tables.

Think of a metatable as a "behavior manual" for a table. When Luau doesn't know how to perform an operation on a table, it consults the metatable for instructions.

Real-world analogy: If you find a device you've never seen before, you'd look for an instruction manual. The metatable is that manual.

Standard Rive Pattern (Prototype + Node Script)​

--!strict

-- Prototype table
local Thing = {}
Thing.__index = Thing

export type Thing = {
    x: number,
    y: number,
    update: (Thing, number) -> (),
}

function Thing.new(x: number, y: number): Thing
    local self = setmetatable({}, Thing)
    self.x = x
    self.y = y
    return (self :: any) :: Thing
end

function Thing:update(dt: number)
    self.x += dt
end

-- Node script
export type Demo = {
    items: {Thing},
}

function init(self: Demo): boolean
    self.items = {
        Thing.new(0, 0),
        Thing.new(100, 50),
    }
    return true
end

function advance(self: Demo, seconds: number): boolean
    for _, item in self.items do
        item:update(seconds)
    end
    return true
end

function draw(self: Demo, renderer: Renderer)
end

return function(): Node<Demo>
    return {
        init = init,
        advance = advance,
        draw = draw,
        items = {},
    }
end

Practice Exercises​

Exercise 1: Shared Drawing Methods with __index​

Goal: Use a prototype table to share draw() across multiple instances.

--!strict

local BoxProto = {}
BoxProto.__index = BoxProto

export type Box = {
    position: Vector,
    width: number,
    height: number,
    path: Path,
    paint: Paint,
    rebuild: (Box) -> (),
    draw: (Box, Renderer) -> (),
}

function BoxProto.new(position: Vector, width: number, height: number, color: Color): Box
    local self = setmetatable({}, BoxProto)
    self.position = position
    self.width = width
    self.height = height
    self.path = Path.new()
    self.paint = Paint.with({ style = "fill", color = color })
    BoxProto.rebuild(self)
    return (self :: any) :: Box
end

function BoxProto:rebuild()
    local halfW = self.width / 2
    local halfH = self.height / 2

    self.path:reset()
    self.path:moveTo(Vector.xy(self.position.x - halfW, self.position.y - halfH))
    self.path:lineTo(Vector.xy(self.position.x + halfW, self.position.y - halfH))
    self.path:lineTo(Vector.xy(self.position.x + halfW, self.position.y + halfH))
    self.path:lineTo(Vector.xy(self.position.x - halfW, self.position.y + halfH))
    self.path:close()
end

function BoxProto:draw(renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

export type BoxDemo = {
    boxes: {Box},
}

function init(self: BoxDemo): boolean
    self.boxes = {
        BoxProto.new(Vector.xy(-80, 0), 120, 80, Color.rgb(255, 80, 90)),
        BoxProto.new(Vector.xy(90, 20), 160, 60, Color.rgb(80, 170, 255)),
    }
    return true
end

function draw(self: BoxDemo, renderer: Renderer)
    for _, box in self.boxes do
        box:draw(renderer)
    end
end

return function(): Node<BoxDemo>
    return {
        init = init,
        draw = draw,
        boxes = {},
    }
end

Why this is Rive-specific: In a Node script, you often want a list of drawables that share logic but store their own Path and Paint. Metatables give you that without classes.

Exercise 2: Default Styles with __index​

Goal: Use __index fallback to keep style defaults in one place.

--!strict

export type StrokeDemo = {
    lineA: Path,
    lineB: Path,
    paintA: Paint,
    paintB: Paint,
}

function init(self: StrokeDemo): boolean
    local defaults = {
        thickness = 6,
        cap = "round",
        join = "round",
        color = Color.rgb(40, 180, 255),
    }

    local warm = setmetatable({ color = Color.rgb(255, 120, 60) }, { __index = defaults })
    local cool = setmetatable({ thickness = 10 }, { __index = defaults })

    self.paintA = Paint.with({
        style = "stroke",
        thickness = warm.thickness,
        cap = warm.cap,
        join = warm.join,
        color = warm.color,
    })

    self.paintB = Paint.with({
        style = "stroke",
        thickness = cool.thickness,
        cap = cool.cap,
        join = cool.join,
        color = cool.color,
    })

    self.lineA = Path.new()
    self.lineA:moveTo(Vector.xy(-140, -20))
    self.lineA:lineTo(Vector.xy(140, -20))

    self.lineB = Path.new()
    self.lineB:moveTo(Vector.xy(-120, 40))
    self.lineB:lineTo(Vector.xy(120, 40))

    return true
end

function draw(self: StrokeDemo, renderer: Renderer)
    renderer:drawPath(self.lineA, self.paintA)
    renderer:drawPath(self.lineB, self.paintB)
end

return function(): Node<StrokeDemo>
    return {
        init = init,
        draw = draw,
        lineA = Path.new(),
        lineB = Path.new(),
        paintA = Paint.new(),
        paintB = Paint.new(),
    }
end

Rive takeaway: Default styles help you keep a consistent look across procedural drawings.

Exercise 3: Computed Lookups with __index​

Goal: Use __index as a function to compute derived values for hit-testing.

--!strict

export type HitDemo = {
    center: Vector,
    radius: number,
}

function init(self: HitDemo): boolean
    self.center = Vector.xy(0, 0)
    self.radius = 80

    local hitbox = setmetatable({ center = self.center, radius = self.radius }, {
        __index = function(tbl, key)
            if key == "min" then
                return Vector.xy(tbl.center.x - tbl.radius, tbl.center.y - tbl.radius)
            elseif key == "max" then
                return Vector.xy(tbl.center.x + tbl.radius, tbl.center.y + tbl.radius)
            end
            return nil
        end
    })

    print(`Hitbox min: ({hitbox.min.x}, {hitbox.min.y})`)
    print(`Hitbox max: ({hitbox.max.x}, {hitbox.max.y})`)

    return true
end

function draw(self: HitDemo, renderer: Renderer)
end

return function(): Node<HitDemo>
    return {
        init = init,
        draw = draw,
        center = Vector.xy(0, 0),
        radius = 0,
    }
end

Rive takeaway: Use computed lookups to keep derived geometry centralized and consistent.

Exercise 4: The Self-Referential Pattern​

Task: Implement the canonical OOP pattern in a complete Node script.

--!strict

-- The "Class" table
local Enemy = {}
Enemy.__index = Enemy

export type EnemyType = {
    name: string,
    health: number,
}

function Enemy.new(name: string, health: number): EnemyType
    local instance = setmetatable({}, Enemy)
    instance.name = name
    instance.health = health
    return (instance :: any) :: EnemyType
end

function Enemy:takeDamage(amount: number)
    self.health -= amount
    print(`{self.name} takes {amount} damage! HP: {self.health}`)
end

function Enemy:isAlive(): boolean
    return self.health > 0
end

function Enemy:describe()
    local status = if self:isAlive() then "alive" else "dead"
    print(`{self.name}: {self.health} HP ({status})`)
end

export type SelfReferential = {
    goblin: EnemyType,
    orc: EnemyType,
}

function init(self: SelfReferential): boolean
    self.goblin = Enemy.new("Goblin", 30)
    self.orc = Enemy.new("Orc", 100)

    self.goblin:describe()
    self.orc:describe()

    self.goblin:takeDamage(15)
    self.orc:takeDamage(30)

    self.goblin:takeDamage(20)
    self.goblin:describe()

    print(`\nGoblin health: {self.goblin.health}`)
    print(`Orc health: {self.orc.health}`)

    return true
end

function draw(self: SelfReferential, renderer: Renderer)
end

return function(): Node<SelfReferential>
    return {
        init = init,
        draw = draw,
        goblin = Enemy.new("", 0),
        orc = Enemy.new("", 0),
    }
end

Trace the lookup for goblin:takeDamage(15):

  1. goblin.takeDamage - not in goblin table
  2. Check metatable - it's Enemy
  3. Check Enemy.__index - it's Enemy itself
  4. Check Enemy.takeDamage - found!
  5. Call with goblin as self

Exercise 5: Other Metamethods​

Task: Explore other common metamethods in a complete Node script.

--!strict

local VectorMeta = {
    __tostring = function(v): string
        return `Vector({v.x}, {v.y})`
    end,
    __add = function(a, b)
        return setmetatable({x = a.x + b.x, y = a.y + b.y}, VectorMeta)
    end,
    __mul = function(v, scalar)
        if type(scalar) == "number" then
            return setmetatable({x = v.x * scalar, y = v.y * scalar}, VectorMeta)
        end
        error("Can only multiply Vector by number")
    end,
    __eq = function(a, b): boolean
        return a.x == b.x and a.y == b.y
    end,
    __len = function(v): number
        return math.sqrt(v.x * v.x + v.y * v.y)
    end,
}
VectorMeta.__index = VectorMeta

local function newVector(x: number, y: number)
    return setmetatable({x = x, y = y}, VectorMeta)
end

export type OtherMetamethods = {}

function init(self: OtherMetamethods): boolean
    local v1 = newVector(3, 4)
    print(`v1 = {v1}`)

    local v2 = newVector(1, 2)
    local v3 = v1 + v2
    print(`v1 + v2 = {v3}`)

    local v4 = v1 * 2
    print(`v1 * 2 = {v4}`)

    local v5 = newVector(3, 4)
    print(`v1 == v5? {v1 == v5}`)

    print(`Length of v1: {#v1}`)

    return true
end

function draw(self: OtherMetamethods, renderer: Renderer)
end

return function(): Node<OtherMetamethods>
    return {
        init = init,
        draw = draw,
    }
end

Knowledge Check​

❓When is __index consulted?
❓What does MyClass.__index = MyClass do?
❓If __index is a function, what arguments does it receive?

Common Mistakes​

  1. Forgetting setmetatable(): Creating a metatable but not attaching it
  2. Wrong __index direction: Remember, child uses parent as __index, not vice versa
  3. Expecting __index for existing keys: It ONLY fires for missing keys
  4. Not setting __index to self: MyClass.__index = MyClass is essential for methods

Self-Assessment Checklist​

  • I can create a metatable and attach it with setmetatable()
  • I understand when __index is triggered
  • I can use __index with both tables and functions
  • I can trace the lookup chain through multiple levels
  • I can implement __tostring for better debugging
  • I understand the self-referential pattern (T.__index = T)
