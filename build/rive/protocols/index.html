Protocols Overview

Rive Context: When Your Code Runs​

Rive calls your script functions in a specific order. Understanding this lets you put logic in the right place and avoid unnecessary work every frame.

Lifecycle order:

  1. init(self, context) - runs once at startup
  2. update(self, context) - runs when any input changes
  3. advance(self, seconds, context) - runs every frame (logic)
  4. draw(self, renderer) - runs every frame after advance (rendering)

Pointer event handlers (pointerDown, pointerMove, etc.) run when the user interacts with the script node.

What Goes Where​

CallbackPurposeFrequency
initCreate paths, paints, listeners, long-lived objectsOnce
updateRespond to input changes; rebuild paths or cached valuesOn input change
advanceUpdate time-based state (movement, physics, timers)Every frame
drawIssue renderer commands onlyEvery frame
Performance Rule

Put expensive work in update or init, not in draw or advance. Rebuilding geometry every frame wastes resources if inputs haven't changed.

Lifecycle Flow Diagram​

┌─────────────────────────────────────────────────────────┐
│                    Script Attached                       │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    init(self, context)                   │
│         • Create paths, paints, listeners                │
│         • Initialize state on self                       │
│         • Return true to continue, false to disable      │
└─────────────────────────────────────────────────────────┘
                           │
           ┌───────────────┴───────────────┐
           │                               │
           ▼                               ▼
┌──────────────────────┐       ┌──────────────────────────┐
│  Input Changed?      │       │   Frame Loop             │
│                      │       │                          │
│  update(self, ctx)   │       │  advance(self, dt, ctx)  │
│  • Rebuild geometry  │       │  • Update timers         │
│  • Recalc values     │       │  • Physics/movement      │
└──────────────────────┘       │                          │
                               │  draw(self, renderer)    │
                               │  • Render commands only  │
                               └──────────────────────────┘

Exercises​

Exercise 1: Lifecycle Probe​

Goal: See when each callback runs. This helps you understand the lifecycle.

--!strict

export type LifecycleProbe = {
    speed: Input<number>,
    elapsed: number,
}

function init(self: LifecycleProbe, context: Context): boolean
    print("init")
    self.elapsed = 0
    return true
end

function update(self: LifecycleProbe, context: Context)
    print(`update -> speed is now {self.speed.value}`)
end

function advance(self: LifecycleProbe, seconds: number, context: Context): boolean
    self.elapsed += seconds
    if self.elapsed > 1 then
        print("advance tick")
        self.elapsed = 0
    end
    return true
end

function draw(self: LifecycleProbe, renderer: Renderer)
end

return function(): Node<LifecycleProbe>
    return {
        init = init,
        update = update,
        advance = advance,
        draw = draw,
        speed = 1,
        elapsed = 0,
    }
end

Try: Change the speed input in the sidebar and watch update fire. Notice that advance runs continuously while update only fires on changes.

Exercise 2: Rebuild Only on Updates​

Goal: Recompute geometry only when inputs change, not every frame.

--!strict

export type OnDemandShape = {
    width: Input<number>,
    height: Input<number>,
    path: Path,
    paint: Paint,
}

local function rebuild(self: OnDemandShape)
    local halfW = self.width.value / 2
    local halfH = self.height.value / 2

    self.path:reset()
    self.path:moveTo(Vector.xy(-halfW, -halfH))
    self.path:lineTo(Vector.xy(halfW, -halfH))
    self.path:lineTo(Vector.xy(halfW, halfH))
    self.path:lineTo(Vector.xy(-halfW, halfH))
    self.path:close()
end

function init(self: OnDemandShape): boolean
    rebuild(self)
    return true
end

function update(self: OnDemandShape)
    rebuild(self)
end

function draw(self: OnDemandShape, renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

return function(): Node<OnDemandShape>
    return {
        init = init,
        update = update,
        draw = draw,
        width = 120,
        height = 80,
        path = Path.new(),
        paint = Paint.with({ style = "fill", color = Color.rgb(120, 220, 140) }),
    }
end

Key insight: The rebuild function is called in both init and update, but NOT in draw. This means geometry is only rebuilt when needed.

Exercise 3: Combining Lifecycle Callbacks​

Goal: Create a shape that responds to inputs AND animates over time.

--!strict

export type AnimatedShape = {
    baseSize: Input<number>,
    pulseSpeed: Input<number>,
    color: Input<Color>,
    time: number,
    path: Path,
    paint: Paint,
}

local function rebuildPath(self: AnimatedShape, size: number)
    local half = size / 2
    self.path:reset()
    self.path:moveTo(Vector.xy(-half, -half))
    self.path:lineTo(Vector.xy(half, -half))
    self.path:lineTo(Vector.xy(half, half))
    self.path:lineTo(Vector.xy(-half, half))
    self.path:close()
end

function init(self: AnimatedShape): boolean
    self.time = 0
    rebuildPath(self, self.baseSize.value)
    self.paint.color = self.color.value
    return true
end

function update(self: AnimatedShape)
    -- Only update color here; size is handled in advance
    self.paint.color = self.color.value
end

function advance(self: AnimatedShape, seconds: number): boolean
    self.time += seconds

    -- Pulse the size based on time
    local pulse = math.sin(self.time * self.pulseSpeed.value) * 0.2 + 1
    local currentSize = self.baseSize.value * pulse
    rebuildPath(self, currentSize)

    return true
end

function draw(self: AnimatedShape, renderer: Renderer)
    renderer:drawPath(self.path, self.paint)
end

return function(): Node<AnimatedShape>
    return {
        init = init,
        update = update,
        advance = advance,
        draw = draw,
        baseSize = 60,
        pulseSpeed = 2,
        color = Color.rgb(255, 120, 80),
        time = 0,
        path = Path.new(),
        paint = Paint.with({ style = "fill", color = Color.rgb(255, 120, 80) }),
    }
end

Notice: In this example, we rebuild the path in advance because the size changes every frame due to animation. Color only changes when the input changes, so we handle it in update.

Pointer Events​

Node scripts can also respond to pointer interactions:

function pointerDown(self: MyNode, position: Vector): boolean
    print(`Clicked at {position.x}, {position.y}`)
    return true  -- Return true to consume the event
end

function pointerMove(self: MyNode, position: Vector): boolean
    return false  -- Return false to let the event propagate
end

function pointerUp(self: MyNode, position: Vector): boolean
    return true
end

Include these in your factory return table to enable them:

return function(): Node<MyNode>
    return {
        init = init,
        draw = draw,
        pointerDown = pointerDown,
        pointerMove = pointerMove,
        pointerUp = pointerUp,
    }
end

Rive Takeaway​

Put expensive work in update, not in draw or advance. Understanding the lifecycle helps you write efficient scripts that only do work when necessary.
