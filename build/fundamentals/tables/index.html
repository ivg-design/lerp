Lesson 1.4: Tables

Rive Context​

Tables are the main data structure you use in Rive scripts: arrays for collections (enemies, particles), dictionaries for lookup (config, stats), and self for persistent state.

Table Basics​

Arrays (Sequential Tables)​

Arrays use numeric indices starting at 1 (not 0):

local enemies = {"Slime", "Goblin", "Mage"}
print(enemies[1])  -- "Slime"
print(#enemies)    -- 3 (length)

table.insert(enemies, "Boss")     -- Add to end
table.remove(enemies, 1)          -- Remove first element

Dictionaries (Key-Value Tables)​

local stats = {
    health = 100,
    mana = 50,
    speed = 12,
}

print(stats.health)       -- 100
print(stats["health"])    -- 100 (same thing)
stats.health = 80         -- Modify
stats.armor = 25          -- Add new key

Iteration​

Arrays (ipairs)​

local items = {"Sword", "Shield", "Potion"}
for i, item in ipairs(items) do
    print(`{i}: {item}`)
end

Dictionaries (generalized iteration)​

local loot = { gold = 100, gems = 3, keys = 1 }
for key, value in loot do
    print(`{key}: {value}`)
end

Exercises​

Exercise 1: Arrays for Runtime Collections ⭐​

--!strict

export type Exercise1 = {}

function init(self: Exercise1): boolean
    local enemies = {"Slime", "Goblin", "Mage"}
    print(`First enemy: {enemies[1]}`)
    print(`Enemy count: {#enemies}`)

    table.insert(enemies, "Boss")
    print(`Enemy count after insert: {#enemies}`)

    for i, name in ipairs(enemies) do
        print(`Enemy {i}: {name}`)
    end

    return true
end

function draw(self: Exercise1, renderer: Renderer)
end

return function(): Node<Exercise1>
    return {
        init = init,
        draw = draw,
    }
end

Exercise 3: Persistent Tables on self ⭐⭐​

When you need data across frames, store it on self.

--!strict

export type Exercise3 = {
    positions: {Vector},
}

function init(self: Exercise3): boolean
    self.positions = {
        Vector.xy(0, 0),
        Vector.xy(50, 50),
        Vector.xy(100, 100),
    }
    return true
end

function draw(self: Exercise3, renderer: Renderer)
end

return function(): Node<Exercise3>
    return {
        init = init,
        draw = draw,
        positions = late(),
    }
end
Using late() for Complex Types

When your self has a table or complex type that gets initialized in init, use late() in the factory return table. This tells the type system the value will be assigned later.

Common Table Operations​

OperationSyntaxDescription
Get length#tblNumber of array elements
Inserttable.insert(tbl, value)Add to end
Insert attable.insert(tbl, index, value)Insert at position
Removetable.remove(tbl, index)Remove and return
Findtable.find(tbl, value)Find index of value
Cleartable.clear(tbl)Remove all elements
Clonetable.clone(tbl)Shallow copy

Key Takeaways​

  1. Arrays start at index 1 in Luau
  2. #table only counts consecutive integer keys
  3. Tables are references - assignment doesn't copy
  4. table.clone is shallow - nested tables are still shared
  5. Use self to store tables that need to persist across frames
